# Glossary — the owned vocabulary

Terminology is grammar element #7 (product-philosophy §4): one word per concept, owned forever. A new product registers its nouns here **before** they appear in any UI (playbook step 1). Where two meanings share a word, the fence is stated — that's what this page is for.

## The nine primitives (GOV-002 §1 — definitions are normative)

**Organization** — the boundary of identity, billing, and policy. Deliberately thin; nothing operational lives here. · **Project** — an application; the atom of the platform; the unit of provisioning, cost, promotion, deletion. · **Environment** — a named, isolated instance of a project (production, staging, preview). A *filter*, never a container (ADR-013). · **Service** — a provisioned capability inside an environment; all services share lifecycle verbs and page anatomy. · **Deployment** — an immutable release of a compute service (artifact + config snapshot). · **Binding** — a managed connection between two services: scoped credentials minted at bind, network path, config injection, rotation. Wiring — always $0. · **Secret** — a versioned, scoped, encrypted value; one injection mechanism, shared with bindings. · **Policy** — a declarative rule attached at org/project/env; inheritance is tighten-only. · **Event** — anything that happened; the one pipeline behind logs, alerts, notifications, audit, markers, and AI context.

## Products & the catalog (ADR-039/040)

**Product** — a catalog entry expressing developer intent (App, Database, Jobs, Search, Vector, Cache, Storage, AI — Storage and AI are *Binding-backed* intents: the outcome resolves to an external-provider Binding, ADR-0004); outcome-named and flat — parentage is never displayed as structure. What developers discover and buy. · **Semantic contract** — the meaning a Product promises: what its state is, what it branches/joins/transacts with, what its meter is. **Execution models are replaceable; semantic contracts are not.** · **Execution model** — how a Product is delivered (in-database capability · dedicated service · shared platform service · external binding — instances of an extensible concept, never a closed list). · **Resolution** — one named, priced way the Composer can satisfy an intent, its semantics stated; never a "backend" dropdown. · **The Composer** — the platform intelligence (C1/AI1) that fans an intent out to resolutions and prices each; it proposes, never silently decides — the **accepted estimate is the contract** between catalog and architecture. *Fence:* the capital-C Composer is this intent-resolver only — distinct from the U3 storage *lifecycle-rule composer* widget, the rung-0 *live composer* (the C1 estimate surface run unauthenticated as a pricing calculator), and the assistant's message composer (AI2). · **Intent tag** — `intent:` stamped on services and meter groups at creation; the grouping key that lets estimates and invoices label by outcome while accounting by component.

## Services & topology

**Fleet service** — a service type with pointable instances (PostgreSQL, Valkey, Web, Worker); count badge and instance switcher render only at n>1. · **Capability service** — one endpoint, config-shaped; *no current service has this shape* (Storage and AI became Bindings — ADR-0004/A5; the X1 exemplar is stale, ruling S9); the shape remains available to future services. · **Instance** — one service of a product within a project (db-main, db-reports); instances are peers, never nested. · **Cell** — a regional unit of Steloit-operated infrastructure; internal, except in **BYOC** where a cell's data plane runs in the customer's cloud account. Ownership is a facet of location, not a new axis. · **Topology map** — services as nodes, bindings as edges; the visual proof no multi-vendor stack can draw. · **Branch** — a copy-on-write database lineage from a parent (pr-142 from main); a branch is not a copy and carries its freshness, cost, and credential scope. · **Shape** — *what services a project has* (per-project); **scale** is how big they run (per-environment).

## Environments & lifecycle

**Production** — the primary instance of a project: the one others branch from and the one policies protect. *Not* "publicly launched" — an internal tool's live instance is its production; an experiment's only instance is trivially its primary. A stable identity, never a deployment state; every project is born with it (ADR-037). · **Implicit environment** — environment chrome is presentation-layer: hidden while a project has one environment and no previews, revealed everywhere at once by the one rule (envs ≥ 2 ∨ previews). Implicit ≠ anonymous — the name `production` is real on every API response, audit row, and billing line from birth (ADR-037). · **Env-as-filter** — switching environment re-renders the page in place; the page stays, data changes; `?env=` in every project-scoped URL (omitted `?env=` always means production). · **Home region** — set by the environment; instances inherit it; overriding is an explicit, priced exception (C7). · **Preview environment** — created on PR open, subset-provisioned under `preview-minimal`, database branched (masked by policy), expired by policy. · **Promotion** — moving a deployment env → env with the diff shown first; production promotes progressively behind **gates** (health conditions with an auto-abort contract). · **Rollout** — replacement, not restart: instances move to the new deployment while others still serve the old. · **Canary** — the partial-traffic stage of a rollout, judged against baseline live. · **Rollback** — redeploy of the previous image in <60 s; migrations never auto-revert (expand-contract).

## Money

**Estimate** — the priced consequence of a shape, shown before anything exists; its line grammar equals the invoice's. · **Meter** — a usage counter behind a bill line; updates ~5 min; the invoice is the meter table frozen on the 1st. · **Quota** — a plan-included allowance on a *platform* meter. **Soft** quotas keep working and bill (the price printed up front); **hard** quotas fail loudly with a reason; both warn at 80% with the math. · **Overage** — usage beyond included quota, priced per unit, never a forced upgrade. · **Dunning** — the failed-payment timeline, printed before it's needed: retries → provisioning paused (running services untouched) → suspend state-kept → nothing deleted for billing reasons within 90 days. · **One arithmetic** — the same cost number on every surface; org total = Σ projects + plan fee, reconciled exactly (canon: $383 + $99 = $482).

## AI layer

**The four laws** — suggest never act · every claim cites evidence · read broadly, act within the viewer's permissions · the platform is whole without AI. · **Insight** — an AI-generated finding (category, severity, evidence); lives in the inbox; durable ledger of open/applied/dismissed/snoozed. · **Proposal** — the reviewable artifact an insight can yield: evidence → reasoning → proposed change → impact, with a human-only Apply. One platform-wide schema; nothing AI ships outside it. · **Evidence** — a citable ref (metric, trace id, query plan, log line) rendered in the logwell. · **"via assistant"** — the audit attribution for a human-applied proposal: *applied as \<user\>, via assistant*. · **⌘K vs Assistant** — ⌘K is *imperative* (go there, do that); the Assistant (⌘J) is *interrogative* (explain, why, recommend). Cousins, not duplicates.

## Console anatomy

**Rail** — the fixed left icon column: Home · Observe · Deploy · the services zone (the project's silhouette) · `+` · gear. Admission = weight × frequency. · **Context bar / crumb** — Org / Project / env-pill; the spine; mirrors `--project/--env` and the URL. · **Switcher** — the crumb/header menus; each preserves your place exactly as much as the destination has one (SW1–SW3). · **Settings mode** — the gear swaps the sidebar for governance navigation (project · org · billing groups); the only nav home for those destinations. · **Canvas** — a full-width, sidebar-less Tier-1 surface (project overview, create surface). · **Tier** — the overlay decision rule: **modal** (one decision / ≤4 fields; typed-confirm for data-destructive) · **drawer** (previews, live checks) · **page** (multi-step, provisioning). Inline create/edit forms are prohibited. · **Logwell** — the mono evidence well: log excerpts, dry-runs, DNS checks, math-in-the-open. · **Pill** — status chip; always carries a word, never color alone.

## Status & observability

**The six marks** — `ready ✓ · provisioning ◌ · degraded ! · failed ✕ · suspended ○ · deleting ·` — one vocabulary across console, CLI, topology, status page. (`ready`, not `running` — ADR-024; metering starts at ready.) · **Markers** — ◆ deploy · ◇ scale · ⬖ policy, drawn from the Event spine onto every chart on every surface. · **The query language** — one grammar (`level:warn+ source:postgres "duration"`) shared verbatim by log bar, ⌘K, CLI, and alert rules: anything findable is alertable. · **Silence ≠ mute ≠ unsubscribe** — silence: this alert, a duration, logged · mute: this *type*, per user · unsubscribe: a delivery channel. Quiet hours affect routing, never recording, and never gate escalation paging.

## Assets & governance

**Template (infrastructure)** — an org-scoped frozen copy of a shape; instantiation copies, never links; secrets never captured; carries its price from birth. **Dashboard template** — a *layout only* that binds to your services at instantiation; deliberately a different asset, fenced on the page (DB6). Never let a third "template" in without a fence. · **Scope ⊥ visibility** — what a dashboard ranges over (org | project) vs who sees it (personal | org | restricted); orthogonal by design. · **Warn-first** — the default policy posture: violations accrue telemetry; promote-to-enforce is a data-backed click with a public date. · **Reveal-once** — a secret is shown exactly once at creation; only the hash is stored; never retrievable. · **Audit log vs Events** — compliance question → audit (who decided); ops question → events (what happened).

## Meta

**LATTICE** — the design system (cells compose into a lattice). · **Instrument** — the superseded pre-LATTICE visual language; historical only (ADR-007). · **Canon** — the one demo world (19-canon/); no demo data exists outside it. · **The grammar** — the eight-element shared language (product-philosophy §4); "fits the grammar" means all eight. · **The four planes** — Products (catalog intents) → Execution models (Composer resolutions) → Infrastructure (the State Test) → Platform capabilities (the governed-resource contract); ADR-040, full text `docs/plan/developer-first-review.md` §4. · **Frame id** — the cross-reference currency (`W3`, `U6`, `AI3`…); a claim about a screen resolves by searching its frame id in `00-sources/`.
