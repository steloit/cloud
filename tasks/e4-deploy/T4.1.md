## Goal

GitHub App: push + PR webhooks, repo link storage

## Summary

**AC:** push and PR open/close events received and stored; repo link survives reinstalls.

## Outcome

- `internal/github`: the integration ingress at /integrations/github/webhook —
  deliberately OFF /v1 (GitHub can't speak the contract; no substrate grammar leaks).
  Unconfigured (no GITHUB_WEBHOOK_SECRET, pre-P2) → 503, honestly.
- Tables: github_installations (uninstall keeps the row), repo_links
  (UNIQUE(service_id); monorepos = many services → one repo), github_deliveries
  (idempotent by X-GitHub-Delivery).
- Spine events: git.push (per linked service, branch-matched) and git.pr_opened/closed
  — via=system, actor=github.
- Findings: (1) repo-link MANAGEMENT has no contract surface (ledger §10 row added) —
  store-level only until the owner shapes the endpoints; (2) mapping a NEW installation
  to an org needs the setup-flow callback (console G3 / E8) — installs are stored but
  unmapped until then; (3) the app registration itself is P2.
