## Goal

Four defects in what Q10 WROTE, found by its QA re-verification after the branch
had merged. The code Q10 shipped was confirmed correct; the durable artefacts
around it were not.

## The defects

1. **The mistake-bank entry named the wrong mechanism.** It said the race needed
   `-count=20` locally and that "a single run passes". Measured: a single `-race`
   run detects it reliably, and a single PLAIN run hits Go's `fatal error:
   concurrent map read and map write` about 1 in 100 — so **CI was flaking at ~1%,
   not passing**, and the blast radius was the whole test binary, not one test.
   Wrong cause and wrong severity, in the living file whose entire job is to carry
   the cause forward. This is the same naming-the-wrong-mechanism class the `cp -R`
   entry in `contexts/provisioning.md` had already been corrected for.

2. **The most transferable lesson had no living file.** *"A mutation result is
   only evidence about the invocation it was measured at"* lived only in Q10's
   Outcome and a commit message — and `tasks/` is the execution layer, not a
   living file (protocol §8). It clears this repo's evidentiary bar because it has
   a verifiable incident: 18/100 → 3/100 → 100/100, with the implementer's *and*
   the architecture review's evidence both looking fine at an invocation CI never
   runs. Now in the mistake bank.

3. **O21 cited ADR-0014 as standing authority.** It does not exist on main — it is
   Proposed, unratified, and lands with O16. `docs/adr/` tops out at 0013, and the
   repo's other references carry the qualifier. This is the citation-hygiene rule
   AGENTS.md makes explicit ("cite only what the committed history supports"),
   which the O11 entries had already had to be corrected for. Now qualified.

4. **O21 said "a 30-minute CI timeout".** CI on main passes no `-timeout`, so it
   is Go's default 10 minutes per package. O13 raises it to 30m, which makes the
   deadlock symptom slower to appear, not clearer. Corrected, and the distinction
   stated.

## Outcome

All four fixed. Also added to O21: a **third** invariant of the same family that
Q10 introduced — `fakeQ.afterRead` must be invoked outside `q.mu` or the first
caller deadlocks holding the lock. Unlike O21's other two it is already converted
into a fast legible failure (the `stuck` escape counts arrivals and fails in 30s),
so it is recorded as satisfied-by-construction and doubles as the worked example
for O21's AC 4.

`contexts/canon-testing.md` is **net-zero on length** (152 lines before and
after): the existing entry was compressed to fund the new one. It remains 2 lines
over the DOCUMENTED 150 cap — inherited from Q10, under the 160 actually
enforced, and O12 owns which of those two numbers is real.

Filed **Q11** for the one thing that is not a documentation defect: QA saw
`TestIdempotentCreateWebhookReplaysTheRevealOnceSecret` fail once under `-race`
without preserving the output. Reported as an observation rather than a
diagnosis, and it is a reveal-once security property, so it gets a task instead of
a shrug.

## Process note

Q10 merged **before** this re-verification came back. ADR-0008 puts the reviewers
before the merge; I merged on the strength of the fix plus a green CI while the
re-verification I had explicitly requested was still running. No harm here — the
verdict was "confirmed" — but the sequence inverted the pipeline, and the whole
point of that pipeline is that the answer is not known in advance.
