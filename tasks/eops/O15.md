## Goal

Pin the composition root's background workers, so removing one fails a test.

## Why

`cmd/api` has no test files. Deleting either of these lines leaves
`go test ./...` fully green:

```go
go idemSvc.RunSweeper(ctx, time.Hour, logger)          // main.go:268
go prov.RunOverrideExpiry(ctx, 5*time.Minute, logger)  // main.go:272
```

Both were verified by mutation (US-3.8 QA, 2026-07-27, for the second one).

The behaviour of each worker is well covered — `TestAPinCreatedAfterBootStillExpires`
pins that the ticker sweeps, and the idempotency tests drive `RunSweeper`
directly. What nothing covers is that **anything ever calls them in
production**. Every test starts the goroutine itself. So the failure mode is the
whole feature dark in production with a green suite, which is exactly the shape
US-3.8 spent three review rounds removing from the code it could reach — the
composition root was simply outside every test's reach.

Consequences if it happens: manual pins never expire (capacity provisioned
indefinitely, priced but "temporary"), and idempotency records outlive their 24h
window and grow without bound.

This is a repo-wide gap, not US-3.8's: the idempotency sweeper has identical
exposure and predates it. The middleware chain by contrast IS pinned —
`identity_integration_test.go`'s world asserts "a middleware dropped from
production fails here" — so the precedent for covering the composition root
exists; it just does not extend to background goroutines.

## Approach

Do NOT assert on source text. Extract the workers into a value the wiring
returns and the test can enumerate:

```go
// backgroundWorkers is every long-lived goroutine the API starts. Adding one
// here and starting it below is the whole registration; a worker that is not
// in this list is not running in production.
func backgroundWorkers(...) map[string]func(context.Context) { … }
```

`main` ranges over it and starts each; the test asserts the expected names are
present and that each is non-nil. That makes deletion a compile-or-assert
failure rather than a silent no-op, without pinning the literal text of `main`.

Consider whether `newWorld` in `identity_integration_test.go` should start the
same registry, so integration tests exercise production's worker set rather than
a hand-assembled one.
