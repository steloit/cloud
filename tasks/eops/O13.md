## Goal

Add two gates CI does not have: `gofmt -l` must be empty in every Go module, and
`sqlc diff` must be clean in `services/api`.

## Why

Both were found as *findings from other work*, which is the point — nothing in
the repo was going to surface them on its own.

**`sqlc diff`.** `db/queries/*.sql` is the source and
`internal/*/store/*.sql.go` is generated from it, but only the generated file
executes. CI (`ci.yml:96`) runs build/vet/test and never regenerates, so the two
can disagree indefinitely and every test still passes — the tests are running
the generated file. US-3.8 hit this from the other side: every SQL mutation in
two independent QA sweeps had to be applied to the *generated* file to have any
effect, which is the same fact stated as a threat model. A `.sql` edit that
never reached the generator is invisible to the entire pipeline, and the failure
mode is a query that silently is not the query anyone reviewed.

**`gofmt -l`.** `services/api/internal/billing/plans_test.go` and
`services/api/internal/metering/metering_test.go` are unformatted on
`feat/phase-1-shell-auth-workloads` today. Neither is large or interesting —
that is why they went unnoticed. CI runs `go vet`, which does not check
formatting, so nothing has ever reported them.

## Approach

1. `gofmt -w` the two files (a formatting-only commit, nothing else in it).
2. Add both gates to `ci.yml` in the Go job, before the build step, so a drift
   or format failure reports as itself rather than as a confusing test failure.
3. `sqlc diff` needs the sqlc version pinned — `sqlc.yaml` and the generated
   header both say v1.30.0; pin the action to that, since a version bump
   reformats generated output and would fail the gate for the wrong reason.
