## The defect

PR #345 was merged against a rollup that read `validate= go= infra=`. The polling
predicate tested for the literal string `"pending"`. GitHub reports an unfinished
check with an **empty** conclusion, so *"not pending"* was true on the first tick
and the loop exited before anything had run.

The merge turned out to be correct — the branch run and `main` were both green
afterwards. **That is the result, not the process.** A predicate that treats "no
answer yet" as "answered" is the same class of defect this repo keeps finding: a
guard that cannot fail.

## The rule

**Empty, missing, unknown, skipped, cancelled and stale are never success.** Only
an explicit terminal `SUCCESS` is. Every verification mechanism needs a positive
success state, and it must be the *only* path to a pass.

## The enums are GitHub's, not invented

Read from the live schema rather than a blog or memory:

    gh api graphql -f query='{__type(name:"CheckConclusionState"){enumValues{name}}}'

    CheckConclusionState: ACTION_REQUIRED TIMED_OUT CANCELLED FAILURE SUCCESS
                          NEUTRAL SKIPPED STARTUP_FAILURE STALE
    CheckStatusState:     REQUESTED QUEUED IN_PROGRESS COMPLETED WAITING PENDING
    StatusState:          EXPECTED ERROR FAILURE PENDING SUCCESS

`STALE` and `STARTUP_FAILURE` are the ones a hand-written list omits. *(An earlier
revision of this task said `STARTUP_FAILURE` is "precisely what the Actions billing
outage (O35) produced". O35 records the opposite — "not a workflow parse error…
the jobs exist and are individually refused" — so that was a claim about a task
which that task does not make. Corrected rather than deleted, because the
mis-citation is the point of the rule.)*

## What shipped

- `scripts/ci/check-state.mjs` — a pure classifier and `verdict()`. Status is
  consulted **before** conclusion, because reading conclusion first *is* the bug.
  Returns `{ready, wait, reason}`: `wait` separates "not yet" from "no", so a
  poller neither merges early nor spins forever on a failure.
- `scripts/ci/await-checks.mjs` — the I/O around it. Exit 0 only on merge
  eligibility, 1 on a terminal non-success, **2 on timeout — a timeout is not a
  pass**, which is exactly what the original defect turned into a merge.
- `scripts/ci/check-state.test.mjs` — 14 tests, run in CI.

## Two properties made structural rather than checked

- **The commit seam.** A first draft read `statusCheckRollup` and compared the
  run's commit to the PR head — but the rollup does not expose the run's SHA, so
  the comparison was `undefined !== undefined`: *a seam check that could never
  fire*, the same defect one layer up. It now queries
  `repos/{nwo}/commits/{headRefOid}/check-runs`, which **cannot** return an answer
  about a different commit. Enforced by the query, not by a branch.
- **SKIPPED is allow-listed by name**, never blanket-accepted — otherwise a job
  that silently stops running looks like a pass.

## Mutation-verified — and review and QA found nine more

Baseline green before and after each; every branch mutated.

| mutation | caught? |
|---|---|
| reintroduce the original bug (conclusion before status) | ✅ 5 tests fail |
| zero checks counts as green | ✅ |
| SKIPPED accepted without an allow-list | ✅ |
| the head-SHA seam removed | ✅ |
| `STALE` treated as success | ✅ |
| **unknown conclusion defaults to SUCCESS** | ❌ **survived** → test added |
| **drop `.toUpperCase()`** (REST sends lowercase) | ❌ **survived** → test added |

Those two matter most of my own set. The default branch **was** the fail-closed
property and nothing tested it; and every test used the GraphQL rollup's UPPERCASE
shape while `await-checks.mjs` queries REST, which returns **lowercase** — the
suite was testing one layer underneath the seam it protects.

### Review and QA then found the same defect reproduced inside the fix

My seven mutations sampled one per guard, not one per *way* each guard can break.
An independent sweep of 37 found 14 real survivors. The serious ones:

| defect | why it mattered |
|---|---|
| **any non-empty SUBSET of the expected jobs was `ready`** | constructible here: `build-sign` is a *separate* workflow that completes as `skipped` in ~1s when `vars.GCP_PROJECT` is unset, so a tick could see only that and merge a PR nothing ran on — **the original defect one level up** |
| an all-skipped rollup was `ready` with zero successes | `--allow-skipped validate,go,infra` is a plausible copy-paste |
| `--timeout-min` with a missing/garbage value → `NaN` | `elapsed > NaN` is false forever, so the timeout **could never fire** — a predicate that cannot fail, inside the fix for a predicate that could not fail |
| the PR number was `args.find(/^\d+$/)` | `--timeout-min 5 346` polled **PR #5** |
| `/check-runs` unpaginated (caps at 30) | a failing check on page 2 is absent, and absence reads as success — fail-**open** truncation inside a fail-closed guard |
| the `StatusContext` branch had no production caller | tested, unreachable, and carrying the same missing-`toUpperCase()` bug — coverage claimed, not held |
| failure-vs-running precedence untested | flipping `if (bad.length)` survived; without it a red build is polled to timeout instead of reported |
| allow-list excused the JOB, not the SKIP | an allow-listed job going `NEUTRAL`/`STALE` would merge |

Fixed: a `require` set (absent required check → *not yet*, never *fine*), at least
one real `SUCCESS` demanded, pagination with `total_count` asserted, argument
parsing extracted into `args.mjs` and unit-tested, the dead `StatusContext` branch
deleted, `head_sha` asserted per check run, and the head re-read after the verdict
so a mid-poll push cannot be merged on an older commit's green.

All eight re-run as **RED**. 23 tests.

## Acceptance criteria

- [x] Pending / running / success / failure / cancelled / skipped / unknown are
      distinguished, and an empty or missing conclusion is never success.
- [x] The completion predicate is fail-closed, with a single positive success path.
- [x] Regression test: incomplete check with empty conclusion → polling continues.
- [x] Regression test: only explicit terminal success → eligible for merge.
- [x] The negative cases are proved by mutation, so the guard cannot silently
      become ineffective again.
