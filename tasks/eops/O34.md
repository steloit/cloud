## The defect

Three testcontainers-backed tests have now failed once each and passed on re-run.
Nobody has explained any of them, and each was individually reasonable to write
off — which is the problem: **three write-offs is a pattern, and the pattern has
no owner.**

| test | package | symptom | recorded |
|---|---|---|---|
| `TestIdempotentCreateWebhookReplaysTheRevealOnceSecret` | identity | failed once under `-race` | Q11 |
| `TestARollupRefusesASpanWithANegativeRate` | identity | `dial tcp [::1]:52381: connect: connection refused`, then `invalid body length: expected at most 1073741822, but got 1414811691` | T3.4c PR |
| `TestOverrideEditReachesCell` | reconcile | failed under `go test ./...`; passed alone, passed on a full re-run of its own package, passed on a clean re-run of the whole module | T3.4c QA round |

The second one is the informative one. `invalid body length … got 1414811691`
is not a Postgres wire message at all — 1414811691 is ASCII `TSEU`, i.e. the
client read someone else's bytes off that port. Combined with `connection
refused` on the first address, that is a **port reused after a container went
away**, not a logic race. Every case so far appears only when many packages run
concurrently, each starting its own container.

## Why this matters more than three flakes

`verify:` blocks and CI both run `go test ./...`. A suite that fails ~1 run in N
for reasons nobody has explained trains everyone to re-run instead of read — and
the next real regression arrives wearing the same costume. This repo's own
mistake bank says a green suite proves nothing if it can be green for the wrong
reason; the mirror is that a red one must not be dismissible by habit.

## Acceptance criteria

1. The mechanism is **named**, not guessed: reproduce a failure with container
   lifecycle logging on, and say which component reused the port (testcontainers'
   reaper, the pool helper, the OS ephemeral range, or a container torn down
   while a connection was still open).
2. Whatever the fix is — a shared container per module, a leased port range,
   `testcontainers.WithReuse`, or serialising the container-backed packages — it
   is asserted, not assumed: a test or CI step that fails if the safeguard is
   removed.
3. Q11 is either explained by the same mechanism and closed, or kept open with
   the reason it is *different*.
4. A re-run does not count as evidence. The PR shows the failure reproduced under
   the diagnosis, then absent under the fix.
