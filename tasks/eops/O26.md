## What happened

O16 (#310) merged the money primitive and **none of its review fixes**. I made
both rounds in a `git worktree`, never committed them, `git push` therefore sent
only the pre-existing commit `2a3679c`, the PR merged that, and
`git worktree remove --force` destroyed the rest. I did not check `git status`
before removing the worktree.

The PR description claimed all of it. Corrected in a comment on #310 rather than
quietly patched, because a merged PR body is a permanent record.

**What was NOT damaged:** `tasks/eops/O16.md` on main does not claim the reviews
happened — those edits were uncommitted too. So the repository was not making
false claims; the PR description was. And the critical defect O16 exists to close
**did** land and IS closed: verified directly against merged `main`, not inferred
from a diff.

## What this task re-lands

Everything from both rounds, re-verified rather than reconstructed from memory
(both reviewers' full reports are in #310's thread).

**Architecture round** — the unreachable `problemError` switch arm (dead on
arrival, with a comment asserting a false model of who owns the responsibility);
unexporting `secondsInLongestMonth` (the justification for exporting it was
false — `money_test.go` is `package money`); `limit` through `money.FromInt` (the
one stored summand evaluated unchecked); no more `$0.00` arithmetic in the 402 or
on the audit spine for the not-representable case; `AccessDeniedReason()` instead
of `err.Error()`, which leaked `identity: access denied: …` onto the API surface;
a 409-with-remediation instead of a bare 500 for a poisoned stored row; dead
`dollars()`; the doubled comment block.

**QA round** — the BLOCKING finding: `MulInt`'s `hi != 0` arm was untested and
the test whose comment named it did not exercise it (`2 × (MaxInt64/2 + 2)` is
2^63+2, below 2^64, so it died on the `lo` arm). Deleting `hi != 0` survived the
whole suite and `postgres {storage_gb: 368934881474191033}` priced at 1934 cents.
Plus five unpinned guards: the fail-closed spend cap (five arms, all surviving
mutation), `problem.FromDenial`'s pass-through (misclassifying a DB failure as a
404 survived), `SurvivesBillingMonth`, the postgres `ha` arm, and valkey's
ceiling division.

**Not taken, and why:** QA's proposed valkey case above 2^53 MB is not
constructible through `Price` — at 2200 cents/GB the largest priceable size is
~1.6e12 MB, three orders of magnitude below 2^53, so the ceiling refuses every
input where float64 and integer rounding could differ. Recorded in the test.

**O19 and O20** restored — they were lost with everything else, and #310's
description referenced them.

## The living-file change

AGENTS.md gains a hard rule: *a worktree is not a commit, and `git push` only
pushes commits.* Commit after each review round before pushing; check
`git status` before removing any worktree. The tell is a push that reports an
unchanged range.

This is the entry that would have prevented it, and per protocol §8 a lesson that
did not change a living file did not happen.

## Outcome

Both rounds re-landed and re-verified. Evidence in the PR.
