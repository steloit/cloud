## The blocker, in GitHub's own words

Every workflow job on every branch has been refused since **2026-08-25 ~03:20 UTC**.
Not a test failure — the jobs are never started. GitHub's annotation on each
refused check-run:

> The job was not started because recent account payments have failed or your
> spending limit needs to be increased. Please check the 'Billing & plans'
> section in your settings

Read from `GET /repos/steloit/cloud/check-runs/{id}/annotations`, identically on
all three jobs of run `32807567207` and on every run since the cutover.

**This requires the account owner.** It cannot be inspected or changed with the
access available here: `GET /orgs/steloit/settings/billing/actions` now returns
**HTTP 410** ("This endpoint has been moved"), so even the remaining quota is not
readable from the CLI.

## The signature, for the next person who sees it

| observation | value |
|---|---|
| duration | ~2 s per job |
| steps executed | **0** |
| billable time | **0 ms** (`/actions/runs/{id}/timing`) |
| jobs affected | all — `validate`, `go`, `infra`, on 5 branches |
| manual re-run | reproduces, including `--failed` at attempt 2 |
| cutover | last green `03:18`, first red `03:25` |

A job that fails with **zero steps and zero billable milliseconds** was never
assigned a runner. That is always an account or policy condition, never a code
one — no test can fail before a step runs.

## Ruled out, from the repository side

Checked before concluding it was external:

- **No workflow file changed.** `git diff main...<branch> -- .github/` is empty on
  all five open branches, and the last commit touching `.github/` predates the
  last GREEN run.
- **Actions is enabled** and unrestricted: `/actions/permissions` →
  `{"enabled": true, "allowed_actions": "all"}`.
- **No self-hosted or custom labels.** Every job is `runs-on: ubuntu-latest`.
- **No reusable workflows, no job-level `uses:`, no environment protection rules**
  on `ci.yml` — nothing that could gate a job before it starts.
- **Not a workflow parse error.** That produces a run-level `startup_failure` with
  no jobs; here the jobs exist and are individually refused.

## What must NOT happen while this holds

- No merge on local evidence. Local `go test` / `validate.mjs` / `terraform fmt`
  are **not** CI, and this repo has no branch protection (O6g), so the only thing
  actually stopping a merge is discipline.
- No weakening of the CI gate, no path-filtering jobs out, no "temporarily
  disable" — the symptom would disappear while the gate it represents did too.

## Acceptance criteria

1. The Actions billing condition is resolved by the account owner (payment method
   and/or spending limit under **Billing & plans**).
2. A run on `main` completes with all three jobs executing steps — confirmed by a
   non-zero `total_ms` in `/actions/runs/{id}/timing`, not by a green tick alone.
3. Each PR blocked by this is re-run and merged on its OWN CI evidence.
