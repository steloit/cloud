## The problem

`canon.Service` carries only `name` and `monthly_estimate_cents`
(`internal/canon/canon.go`). The fixtures have `product` and `shape` too, and
the estimate engine needs both to price anything — so
`internal/estimates/engine_test.go` carries a **private second loader** that
reads `docs/product/19-canon/fixtures.json` raw and picks its section with a
loose `key[:8] == "services"` prefix match.

Two consequences:

1. **CLAUDE.md's token-discipline rule is violated** — "`19-canon/fixtures.json`
   raw — import via `packages/canon`". Two loaders over one file can drift, and
   the prefix match would silently pick up a future `services_v2` key.
2. **The engine↔canon sweep cannot be reused.** CK-M3 wanted to assert the full
   invariant (every canon service priced through the engine, Σ against the $208
   anchor) and could only assert one shape, because the shapes are not reachable
   through the canon package.

## The fix

Widen `canon.Service` with `Product string` and `Shape map[string]any` (the JSON
tags already exist in the fixtures), delete `engine_test.go`'s
`loadCanonServices`, and let both callers use `canon.Load()`.

Then the six-line sweep becomes reusable:

```go
var sum int64
for _, s := range cw.Services {
    l, err := estimates.Price(estimates.ShapeInput{Product: s.Product, Name: s.Name, Shape: s.Shape})
    // assert l.MonthlyCents == s.MonthlyEstimateCent
    sum += l.MonthlyCents
}
// assert sum == cw.EcommerceProjectCents()
```

## Also worth doing while in here

`canon.CheckArithmetic` compares fixtures to fixtures and never touches the
engine — which is correct for what it is, but means "canon arithmetic green
**against the estimate engine**" (CK-M3's second exit criterion) is carried
solely by `estimates.TestCanonArithmetic`. With the widening, any caller can
assert the engine half directly, and CK-M3's in-file assertion can become the
full sweep rather than a single shape.

## Acceptance criteria

- [ ] `canon.Service` exposes product and shape; `canon.Load()` populates them.
- [ ] `engine_test.go`'s private fixtures loader is deleted; no test outside
  `internal/canon` reads the fixtures file directly.
- [ ] `TestCanonArithmetic` still passes, unchanged in intent.
- [ ] CK-M3's in-file canon assertion prices EVERY canon service through the
  engine and checks the Σ anchor, not one shape.
- [ ] Mutation-verified: changing one canon service's price without changing the
  engine fails the sweep.

## Found by

CK-M3's QA review (2026-07-26), which noted that the checkpoint's canon
assertion had to retype `2400` because the shape was unreachable through the
canon package. The literal is now derived from `canon.Load()`, but only for the
one service CK-M3 creates.
