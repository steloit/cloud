## The defect

This session added five CI gates. **Only one of them is pinned by a test.**

| gate | added by | pinned? |
|---|---|---|
| `make gen-sql` in the drift step | O7 | **no** |
| `gofmt -l` over the derived module list | O13 | **no** |
| `-race` | O13 | **no** |
| `-timeout 30m` | O13 | **no** |
| `STELOIT_REQUIRE_CONTAINERS` | O23 | yes |

The container gate got pinned only because a reviewer caught it
(`TestCIWorkflowArmsTheContainerGate`). The other four were never asked the same
question, and they fail it.

**Reproduced.** In a throwaway copy I deleted `make gen-sql`, the entire
`gofmt (every Go module)` step, and `-race -timeout 30m` from `ci.yml`. The file
still parses, and `go test ./internal/platform/testenv/` reports **ok**. Nothing
in the repository notices that three gates are gone.

## Why this is `high`

These gates exist because their absence let real defects through — a stale
`services.sql.go` (US-1.3a), two unformatted files nothing reported, and a data
race that reached the base branch and sat there a month (O14/Q10). A gate that
can be removed by deleting four lines, with a green suite, is a gate that will
eventually be removed by someone tidying a YAML file.

This is also the third instance of one shape in this file: `ci.yml` records the
lesson about its own hardcoded module list, O23 recorded it about the container
constant, and here it is again across the whole gate set.

## Approach

Extend `TestCIWorkflowArmsTheContainerGate` into a check over **every** gate.

**A hand-maintained list is correct here, and that needs saying** — the previous
two instances were fixed by DERIVING (`git ls-files '*/go.mod'`, walking the tree
for testcontainers users) because a source of truth existed. There is no source
from which "which gates ought to exist" can be derived: the set is a decision, so
the list IS the assertion rather than a duplicate of one. Each entry names the
task that added it, so a failure says why the gate is there.

## Acceptance criteria

- [x] Deleting any one gate from `ci.yml` fails a test that names the gate and
  the task that added it.
- [x] The test `t.Fatal`s if it cannot read `ci.yml` — a missing file must not
  read as "clean" (the failure mode `ci.yml:41-43` already records about itself).
- [x] The gate list is documented as a deliberate hand-maintained assertion, with
  the reason no derivation is possible.
- [x] No false positive on the current `ci.yml`.

## Outcome

`TestCIWorkflowArmsEveryGate` pins all six gate needles. Each entry carries the
task that added it and why the gate exists, so a failure explains the gate rather
than reporting that a string went missing.

**Two versions of this test were wrong before this one, and both were found by
mutation rather than by reading.**

*Version 1* matched needles with `strings.Contains` over the whole file. Every
gate here is DOCUMENTED next to itself — `-race` in three comments,
`-timeout 30m` in two — so deleting `-race` from all three module lines while
leaving the comments reported **ok** with the detector running nowhere. The
better-documented a gate, the more reliably a text match lies about it.

*Version 2* stripped whole-line comments. Still wrong: an **inline** comment
(`STELOIT_REQUIRE_CONTAINERS: ""   # was: "1"`) kept the needle alive while the
value was emptied — and an empty value disarms the gate, because `Required()` is
`!= ""`. That defeated the pre-existing container pin too.

*This version parses the YAML* (`gopkg.in/yaml.v3`, already a dependency) and
asserts against `jobs.<job>.steps[].run` and `.env`. Text cannot tell code from a
corpse; a parse makes a commented-out step, an `if: false` job and a removed
trigger structurally invisible.

## Three versions were wrong before this one

*v1* matched with `strings.Contains` over the whole file. Every gate is DOCUMENTED
next to itself, so deleting `-race` from all three commands while leaving three
comments reported **ok** with the detector running nowhere.

*v2* stripped whole-line YAML comments. An **inline** comment still kept a needle
alive while the env value was emptied — and an empty value disarms the gate.

*v3* parsed the YAML. Review found **16 of 26** classes still surviving, and the
sharpest part was that **my own evidence had been false**: "the entire drift step
commented out → RED" was not the assertion firing. Commenting out the step's YAML
*keys* makes `ci.yml` unparseable, so it hit `t.Fatalf("does not parse")` and the
gate logic never ran. One representation died; the class stayed open.

The class it hid: **a shell `#` comment inside a `run:` block scalar is DATA, not a
YAML comment.** The parser preserves it, so `strings.Contains(st.Run, needle)`
matched a corpse exactly as v1 did. Confirmed by commenting out every executable
line of the Generate step — **zero commands left, both needles satisfied, suite
green.** The comment hole had moved, not closed.

*v4* (this one) strips shell comments from `run:`, and adds the three things a
presence check cannot see on its own:

- **`continue-on-error`** at job *and* step level — one line lets every gate run,
  fail, and the job report success.
- **step-level `if:`** — `if: false` on Build+vet+test kills `-race`, `-timeout`
  and the container gate at once. Not a blanket ban: authority-paths legitimately
  carries `if: github.event_name == 'pull_request'`, so only a constant-false is
  rejected.
- the `pull_request` **text fallback deleted**. My comment claimed YAML 1.1 folds
  bare `on` to boolean true; that is false for yaml.v3 (YAML 1.2 core schema), so
  the fallback could never help and could only hurt — it fires exactly when the
  trigger is gone, and any literal `pull_request:` re-arms it.

## Scope: 23 gates across all three jobs

The name said `ArmsEveryGate` while covering six needles in one job. Now pinned:
the go job's generators **and** its drift assertion, gofmt (including the
stderr/exit-status capture), `-race`, `-timeout`, the container env, cell-agent and
cli; **authority-paths**, `validate.mjs`, the hook regression tests, the gen-ts
drift assertion, console lint/typecheck/test/build, SDK, canon; terraform fmt,
both env validates, and the k8s manifest parse.

**authority-paths needed two needles.** A presence check cannot see a *semantic*
neutering: flipping its final `exit 1` to `exit 0` leaves every marker string
intact and fails the gate **open**. The failure itself is pinned by matching the
last message together with the exit that follows it.

One class first read GREEN and the **mutation** was wrong, not the gate — a
pattern with the wrong indentation that never applied. Re-run under an
assert-the-mutation-applied guard: RED. A mutation that does not mutate proves
nothing, which is the same defect as a test that does not discriminate.


## Scope corrected

The first version was named `ArmsEveryGate` while covering six needles in **one
job** — an overclaim of exactly the kind "examples are normative" targets. It now
covers the `validate` and `infra` jobs too, including the drift *assertion*
(`git diff --cached --exit-code`), which was unpinned while its generators were
pinned: generators without the diff are a no-op that looks busy.
