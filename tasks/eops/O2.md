### Fixed here, because it needs no policy

`currency_code` was **hardcoded `"USD"`** while the only budget observable on that
account is **INR**. The Budget API requires the amount's currency to equal the
billing account's currency, so a hardcoded value that disagrees fails at apply —
and P1 is exactly when that would first be discovered.

It is now `var.budget_currency`, wired through both envs. *Not* asserted as
"USD is wrong": the account's currency could not be read (the Cloud Billing API
is not enabled on `steloit-dev`, and enabling it is not this task's business).
What is asserted is that hardcoding a value which contradicts the only live
sample is a defect, and the value belongs where whoever supplies
`billing_account` sets it in the same breath.

Verified: `terraform validate` **Success** for `infra/envs/dev` and
`infra/envs/cell0`, `terraform fmt -check -recursive infra` clean. Both envs
declare AND pass the variable — checked separately, because declaring it without
passing it (or the reverse) is the same one-representation mistake this repo keeps
finding. `terraform validate` caught exactly that on cell0 mid-change.

### NEEDS FOUNDER INPUT — four decisions, none of them mine

1. **Which instrument?** A recurring monthly budget and a one-off trial-credit
   exhaustion alarm are different alarms. `INCLUDE_ALL_CREDITS` makes a monthly
   budget approximate the credit view, but they diverge the moment the credit is
   exhausted or the month rolls.
2. **Which amount?** $300/mo (terraform) vs ₹1000/mo (live) is roughly a 25×
   difference. ₹1000 is a tight runaway-tripwire; $300/mo is "the trial's whole
   value each month".
3. **Which middle threshold — 80% or 90%?** Terraform and the task say 80, live
   says 90.
4. **What happens to the existing budget when P1 lands?** Terraform will create
   `"<cell> budget"` **alongside** `steloit-dev tripwire` — different display
   names, so no adoption. Two budgets, two alert sets, two currencies. Either
   `terraform import` the existing one, delete it, or accept both deliberately.

Until (1)-(4) are answered this task stays `stub`: enriching it would mean
choosing them.
