## Goal

Make "the integration tests ran against real Postgres" a checked fact in CI
rather than an assumption.

## Why

Three packages skip themselves when no container runtime is available:

- `internal/reconcile/integration_test.go:42`
- `internal/identity/identity_integration_test.go:70`
- `internal/platform/db/db_integration_test.go:22`

Each calls `t.Skipf("container runtime unavailable (CI runs this): %v", err)`.
That is right for a laptop. In CI it means that if Docker is unavailable or
misconfigured on the runner, **those three packages print `ok` having executed
essentially nothing, and the go job is green.**

`internal/identity` is the largest suite in the repo (~350s with containers). A
run where it finishes in seconds and reports `ok` is indistinguishable, at the
job level, from a run where it passed.

## Why it is worth doing NOW

O13 just staked two decisions on those containers running:

- `-race` was added specifically because it had never run. Under a silent skip it
  degrades to a unit-test-only detector — and the race it exists to catch
  (O14/Q10) lived in exactly one of these three packages.
- `-timeout 30m` was derived from `identity` measuring 347s. For a suite that
  skips, the number is meaningless.

Both of O13's headline gates evaporate silently in that state, which is the same
class of defect O13 was written to remove.

## Approach

**The repo already contains the pattern.** `internal/identity/ckm3_checkpoint_test.go:137`
gates on `STELOIT_CHECKPOINT` and panics in `t.Cleanup` `if t.Skipped()`, with a
comment stating verbatim that "a milestone gate can be green on a machine that
never executed it".

Generalise it:

1. A single env var (`STELOIT_REQUIRE_CONTAINERS=1`, or reuse `STELOIT_CHECKPOINT`).
2. In each of the three helpers, when it is set, `t.Fatalf` instead of `t.Skipf`.
3. Set it as `env:` on the go job in `ci.yml`.

Local behaviour is unchanged — the var is unset, and the skip stays a skip.

## Acceptance criteria

- [x] With the var set and no runtime, each of the three packages FAILS with a
  message naming the missing runtime — not a skip, not a pass.
- [x] With the var set and a runtime present, the suite is green and no test skips.
- [x] `ci.yml` sets the var on the go job.
- [x] Locally, with the var unset, the skip behaviour is exactly as today.

## Found by

O13's Security/QA review, 2026-08-23, while attacking the new `-race` and
`-timeout` gates. Reported non-blocking for O13 because it predates that branch —
but it is the gap that decides whether O13's gates mean anything.

## Outcome

One decision, in one place: `internal/platform/testenv.SkipOrFail`. A missing
container runtime is a **skip locally and a fatal in CI**, and the three
integration helpers call it instead of each making that judgement themselves —
three independent copies of a decision is how one of them quietly stops making it.

`.github/workflows/ci.yml` sets `STELOIT_REQUIRE_CONTAINERS: "1"` on the go job.

**Verified in all three directions**, which is what a gate needs rather than one
happy-path run:

| runtime | `STELOIT_REQUIRE_CONTAINERS` | result |
|---|---|---|
| absent | unset (a laptop) | **skip**, `ok`, exit 0 — local workflow unchanged |
| absent | set (CI) | **FAIL**, naming the var and why a skip is not a pass |
| present | set (CI) | **pass** — no false positive |

The middle row is the whole task, and the first row is why it is safe.

**Two mutations that survived the first version, now killed.** Both were found by
review, and both are the same shape — a coupling held by nothing:

- **Renaming `RequireContainersVar`** left `go build`, `go vet` and `gofmt -l` all
  clean while every container suite went back to printing `ok`. The Go constant
  and `ci.yml` were coupled by string equality alone. `TestCIWorkflowArmsTheContainerGate`
  now reads `ci.yml` and fails if the gate is not armed — and `t.Fatal`s if it
  cannot read the file, because a missing file must not report "clean".
- **Reverting one helper to `t.Skipf`** and dropping the import left everything
  green with the gate armed. The package doc says the point is that "three helpers
  each making it independently is how one of them quietly stops making it" — and
  the first version unified the three that exist while leaving the fourth, added
  next month, invisible. `TestEveryTestcontainersUserRoutesThroughTestenv` now
  DERIVES the set by walking the tree.

`ci.yml` records this exact lesson about itself twenty lines above the env block:
the gofmt module list was hardcoded twice and had to become
`git ls-files '*/go.mod'` because "a fifth module would silently get no gofmt …
and nothing would say so". The first version of this task reintroduced that shape,
in that file.

The derived check also initially counted **itself** — `wiring_test.go` contains
the strings it greps for — which inflated the count and would have kept the
vacuity guard satisfied with every real caller deleted. Excluded, and the guard
now requires at least the three known packages rather than merely non-zero.

**Filed, not fixed here: O28.** This gate is NEGATIVE — it converts an error into
a failure. With the runtime present and the gate armed, `t.Skip("quarantined")` on
every container test in a package still yields `ok` with zero containers started.
Quarantining a flaky integration test is the likeliest way that happens for real.
O28 owns the positive assertion, and also the `ckm3_checkpoint_test.go` panic that
aborts the whole binary (discarding ~100 other identity results) where a clean
failure would report one.

**Why this was `high` rather than housekeeping** — and the version of this
argument I first wrote was **wrong**, so here is the corrected one.

`-timeout 30m` is derived from `internal/identity` measuring ~350s. That number
is meaningless for a suite that skips, so CI reports success while proving
nothing about the run the timeout was sized for. That half is sound.

The `-race` half I got wrong. I wrote that the race O14/Q10 fixed "lived in one
of these three packages", implying a silent skip would have hidden it. **It would
not have.** That race was in `reconcile_test.go`'s in-memory fakes — 18
`newFixture` uses, zero `realDB` — so the test runs with or without a container
and `-race` catches it either way. The review reproduced exactly that:
`TestConcurrentWritebackAppliesOnce` PASSES while its `AgainstRealPostgres`
sibling SKIPS. Naming the same PACKAGE on both sides while the distinction that
matters is *unit-test file vs container-test file* is the O11 failure CLAUDE.md
records verbatim, and "examples are normative" makes it a correction.

The accurate `-race` argument is **prospective**: under a silent skip the detector
never examines the container-backed suites at all — including
`TestConcurrentWritebackAppliesOnceAgainstRealPostgres` and
`TestIdempotencyConcurrentDoubleSubmitHasOneWinner`, which are where concurrency
against real Postgres is exercised. That is where the next such defect lives, not
where the last one did.

The pattern is not new: `identity/ckm3_checkpoint_test.go` already gated on
`STELOIT_CHECKPOINT` and failed in `t.Cleanup` if the test skipped, with a comment
saying verbatim that "a milestone gate can be green on a machine that never
executed it". This generalises that one test's insight to every container-backed
suite.
