## Goal

Three gaps in `internal/reconcile`, all found by Q10's QA review while attacking
a different diff, none caused by it.

## 1 · The 409 branch is dead weight as far as the suite knows

`http.go`'s `writeErr` maps a `problem.Carrier` error to a 409. **Deleting that
branch entirely — so every illegal-edge and every concurrency-loser becomes a
`problem.Internal` 500 — passes the full package suite**, unit and real-Postgres
integration included.

That is the exact shape ADR-0014 (**Accepted**, founder-ratified 2026-08-23) is
written to name: a guard whose removal nothing notices. It matters here because the losers of a concurrent writeback are the
NORMAL case, not an error case — the reconciler's whole design is N agents
racing to report the same edge, and telling them "500, internal error" instead
of "409, someone else got there" is both wrong and unactionable.

The unit fixture cannot currently reach the branch at all: `fakeTrans` returns a
bare `errors.New`, not a `problem.Carrier`.

Sketch: `TestHTTPConcurrencyLoserIs409NotInternal` — mount the handler, have the
double return a `problem.Carrier` conflict, POST the writeback, assert 409 **and
a non-empty `remediation`** (the repo's hard rule), not 500.

## 2 · No concurrency test at the HTTP representation

Production calls `POST /v1/reconcile/{cell}/status`, N times, concurrently. Both
existing concurrency tests (`TestConcurrentWritebackAppliesOnce` and its
real-Postgres sibling) exercise the SERVICE layer. The transport in between —
status mapping, body shape, the middleware chain — is unexercised under
concurrency.

Sketch: 8 goroutines against the mounted endpoint; assert exactly one 200 and
seven 409s.

## 3 · Two invariants stated in comments, enforced by nothing

Q10 left `internal/reconcile/reconcile_test.go` relying on two facts that only a
comment records:

- `fakeQ.cells` and `fakeQ.rows` are written only at construction (their reads
  are unlocked, which is safe only while that holds).
- `fakeTrans.Transition` calls no `fakeQ` *method* — it takes `q.mu` directly, so
  a future edit that calls one **self-deadlocks the test binary** and surfaces as
  a package timeout rather than a clear failure.

Both are true today. Neither is pinned. The second is the nastier: a deadlocked
test binary surfaces as a TIMEOUT, which people diagnose wrong. On main today
that is Go's default **10 minutes per package** (CI passes no `-timeout`); O13
raises it to 30m, which makes the symptom slower to appear, not clearer.

## A third invariant of the same family — already satisfied, listed so it is not "fixed" away

Q10's barrier added one more comment-only rule: `fakeQ.afterRead` must be invoked
**outside** `q.mu`, or the first caller deadlocks holding the lock. Unlike the two
above, this one IS converted into a fast legible failure — the `stuck` channel
escape turns it into a 30s `t.Errorf` that counts arrivals (`only 1 of 8`,
`only 2 of 8`, …) and points straight at the cause. Verified by moving the hook
back under the lock.

It is the worked example for AC 4 below: this is what "fails fast with a legible
message" looks like for the other two.

## Acceptance criteria

- [ ] Deleting the `problem.Carrier` arm in `writeErr` makes a test go red.
- [ ] Concurrent requests at the HTTP representation assert one 200 / seven 409s.
- [ ] Every reachable `writeErr` error is problem+json with a non-empty
  `remediation`, and only genuinely internal faults are 5xx.
- [ ] The deadlock invariant is either enforced or converted into something that
  fails fast with a legible message.

Q10's Security/QA review, 2026-08-23. Reported non-blocking for Q10: all three
