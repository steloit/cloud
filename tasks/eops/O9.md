## Goal

Create operational guidance for security-sensitive procedures. KEK rotation is
the first entry and the reason this task exists; the structure should admit the
others that will follow (credential revocation, incident key compromise, secret
re-sealing).

**Founder direction (2026-07-26):** this is *operational documentation, not
application architecture*. Do not scatter it across ADRs. The long-term
operational-documentation structure is a separate decision — propose one here
rather than inventing it silently, and do not create an ad-hoc tree.

## Why now

ADR-0013 (US-3.6a) created a live operational obligation with nowhere to put it.
Envelope-encrypting the idempotency replay cache means **a KEK rotation
invalidates every recorded response at once** — lazy re-wrap is impossible when
the record cannot be opened. For up to 24h afterwards, requests that would have
been deduped **execute again**, including `POST /v1/envs/{env}/services`, whose
one-shot estimate is the reason that layer exists.

The mitigation is one line — truncate `idempotency_keys` at rotation — but it
currently lives only in an ADR, which is where a reader looks for *why*, not for
*what to run at 3am*. `docs/` has `adr/`, `dev/`, `plan/`, `product/` and
nothing runbook-shaped, so there is no correct home for it yet.

## Scope

- **Decide the home.** Propose where operational procedures live (a `docs/ops/`
  tree, a runbooks section under `docs/dev/`, or something else) and why. This
  is the part to get agreement on before writing much.
- **Write the KEK rotation procedure.** At minimum:
  - what `kek_id` means per row and which tables carry sealed values
    (`secrets`, `webhooks`, TOTP, `idempotency_keys`);
  - the re-seal path for tables that hold authoritative secrets;
  - the **replay-cache invalidation step** for `idempotency_keys` — truncate,
    because it is a 24h cache and truncation is the explicit form of what the
    code does implicitly (ADR-0013);
  - what to expect afterwards: the discard path logs at Error for every
    unopenable record, and dedupe is degraded until the window passes.
- **Make it discoverable from the code that creates the obligation** — a
  pointer from `internal/platform/idempotency` and `internal/secrets` to the
  procedure, so the obligation is not findable only by reading an ADR.

## Acceptance criteria

- [ ] The operational-documentation home is decided and recorded (with the
  reasoning, so the next procedure does not re-litigate it).
- [ ] A KEK rotation procedure exists and covers every table holding sealed
  values, including the `idempotency_keys` invalidation step.
- [ ] The code that creates the obligation points at the procedure.
- [ ] The procedure states the expected post-rotation behaviour (Error-level
  discard logs, degraded dedupe for the TTL) so it is not mistaken for an
  incident.
