## Goal

`infra/envs/dev/main.tf` declares `module "cost_guardrails"` **twice**, with
byte-identical bodies, at lines 77 and 86. Terraform refuses:

```
Error: Duplicate module call
  on main.tf line 86:
  86: module "cost_guardrails" {
A module call named "cost_guardrails" was already defined at main.tf:77,1-25.
```

So `terraform validate` fails, and CI's whole `infra` job has been red on `main`.

## Why it matters more than a duplicated block

- **It is not one env's problem.** The job also validates `infra/envs/cell0` and
  parses every `infra/k8s/**` manifest. Those steps run *after* the failing one,
  so nothing in the infra tree has been checked by CI for as long as this has
  been broken.
- **A permanently-red job stops being read.** Once "infra is always red" is
  ambient, the next genuine infra regression arrives invisible. That is the real
  cost, and it compounds.

## Cause

A merge artifact, not an authoring mistake. `git log -S'module "cost_guardrails"'`
shows the block introduced twice — once on the O2 branch (`24e4252`) and once by
its PR merge (`6e257c1`, #209) — and a later consolidation merge kept both. The
bodies are identical, so no review diff showed anything semantically odd.

## Fix

Delete the second block. Verified: both bodies are byte-identical, so which one
survives cannot matter.

## Outcome

One duplicated block removed. `terraform fmt -check -recursive infra` clean;
`terraform validate` **Success** for both `infra/envs/dev` and `infra/envs/cell0`
(Terraform v1.15.8, the version CI pins). The infra job's later steps —
`cell0` validate and the `infra/k8s/**` manifest parse — now execute for the
first time in this window rather than being skipped behind the failure.

**Found by** running CI on an unrelated PR (Q10, #305) and noticing the `infra`
job fail in 8s on a branch touching no infra files, then confirming the same
failure on `main` at `28fa30f`.

**Filed as a finding, not silently fixed:** the O2 terraform module this
duplicates declares 50/80/100% budget alerts, which is O2's acceptance criterion.
The budget that actually exists in GCP (`steloit-dev tripwire`, billing account
`016006-61AFB9-0DD7E7`) is a ₹1000 *monthly* budget with 50/90/100% thresholds
and an empty `notificationsRule`. So the terraform and the live state disagree on
the instrument, the amount and the thresholds. That belongs to O2, which is still
a stub; this task only makes the file parse.
