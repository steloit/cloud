## The gap

Comments and task files point at tests by name — "pinned by `TestX`" — as the
pointer a reader follows to find where an invariant is held. Eight of those names
do not exist anywhere in the repo:

| cited name | |
|---|---|
| `TestAIAssistantDisabledNarrowsAI` | |
| `TestConvergeReturnsProvisioningUntilReady` | |
| `TestFlaggedEventsReprojectWithoutBackfill` | |
| `TestHTTPConcurrencyLoserIs409NotInternal` | |
| `TestTheD7PolicyObjectsAreDeliberatelyNotRenderedYet` | renamed by US-3.3e to `TestTheD7NetworkPoliciesAreStillWithheld`; the citation was not updated |
| `TestTheEnvFeedIsFencedToItsEnv` | |
| `TestTheEventFeedKindFilterExcludes` | |
| `TestThePricedInstanceCountRefusesWhatItCannotRepresent` | |

A dangling citation is worse than none: it asserts that an invariant is held
somewhere, and a reader who cannot find the test concludes they mis-searched
rather than that the pointer is wrong. AGENTS.md already binds this — "cite only
what the committed history supports" — with no mechanism behind it.

**The rename case is the instructive one.** Renaming a test is a normal,
correct refactor; nothing anywhere connects the new name to the comment that
pointed at the old one.

## Acceptance criteria

1. A check — in `scripts/spec-sync/validate.mjs`, so it runs on every PR — fails
   when a `Test[A-Za-z0-9_]+` token appearing in a comment or task file matches
   no `func Test…` in the repo.
2. It must be **wrap-aware**: these names are routinely broken across two comment
   lines, so a naive line-by-line scan reports false positives (measured: 8
   spurious hits before the check joined lines) and a naive exact-match reports
   false negatives. A token that is a strict PREFIX of a real test name, and is
   immediately continued on the next line, resolves.
3. The eight above are fixed — repointed at the real test, or deleted where the
   claim no longer holds.
4. Mutation-verified: renaming any cited test must turn the check red.
