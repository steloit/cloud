## Goal

`docs/adr/` contains **two** files numbered 0007:

```
0007-org-key-authorization.md
0007-substrate-spike-findings.md
```

so a citation of "ADR-0007" does not identify a document. CLAUDE.md and several
task files already cite ADR-0007 meaning the org-key one; `docs/adr/README.md`
and any index will list two entries under one number.

## Why — found writing ADR-0013 (US-3.6a)

ADR-0013 originally cited "ADR-0007 (envelope encryption / KEK model)". That was
wrong twice over: ADR-0007 is org-key authorization, *and* the number is
ambiguous. The reviewer caught it. The envelope/KEK model has **no ADR at all** —
it lives in `services/api/internal/secrets` (T3.5) and `docs/architecture.md` D5.

An ambiguous ADR number is a small defect with a long tail: every future
citation inherits it, and ADRs are the durable record precisely because people
cite them years later.

## Decide

1. **Renumber one file** — cheapest, but rewrites history and breaks existing
   citations unless every reference is updated in the same change. Check
   `grep -rn "ADR-0007" --include=*.md .` first; if the only citations mean the
   org-key ADR, renumber the substrate-spike one to the next free number and
   leave a one-line pointer at the old path.
2. **Leave both, disambiguate by slug** — record in `docs/adr/README.md` that
   0007 is split and citations must use the full filename. Honest but permanent.

Option 1 is probably right while the citation count is small.

## Also worth deciding

Whether the envelope/KEK model deserves its own ADR. It is load-bearing for
secrets, webhooks, TOTP and now the idempotency replay cache (ADR-0013), and it
is currently documented only in code and an architecture-doc line item.
