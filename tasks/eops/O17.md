## Goal

Move ~560 lines of tests to the packages they actually exercise, and remove the
structural reason they landed in the wrong one.

## Why

Founder question on US-3.8 (2026-07-27): `services_integration_test.go` grew
+1577 lines against ~440 of product code — *"should these tests remain as an
integration suite, or do they indicate responsibilities that should migrate into
focused package-level tests?"* Both reviewers answered independently, and agreed:
**migrate the sweep/SQL cluster, keep the cross-layer tests.**

The density is not the finding. The finding is that the file is 2102 lines when
the next largest in its package is 288, and that several of its tests **never
make an HTTP request** — in a file whose header says "services over live HTTP".

**The structural cause:** `newWorld` lives in `identity_integration_test.go`, so
any test wanting a live server must be written in `package identity_test`,
whatever domain it exercises. Provisioning's HTTP surface therefore accumulates
in `identity` by construction, and will keep doing so on US-3.10, US-11.9 and
O16 unless the fixture moves.

## Move to `internal/reconcile` — real Postgres, no HTTP

`reconcile` already has `realDB`/`newProvisioning` with no server, and already
hosts `TestTheClearFenceRejectsARowThatStartedDeletingMidSweep`, which is this
exact shape. Failure messages would then point at the query rather than at a
PATCH four layers up.

- `TestTheSweepLeavesADeletingServiceAlone` (~105) — calls
  `store.New(pool).ListExpiredOverrides` directly. It is the **sibling** of the
  clear-fence test above: same sweep, same `status <> 'deleting'` pair, one
  fence each. Splitting that pair across two packages is the clearest single
  misplacement in the diff.
- `TestTheSweepClearsEveryDeadPinShapeAndSurvivesAMalformedOne` (~186) — pure
  `ListExpiredOverrides` CASE-arm semantics.
- `TestAPinExpiringAtExactlyNowIsSweptNotStranded` (~108) — a `now()` boundary
  inside one transaction.
- `TestAPinCreatedAfterBootStillExpires` (~99) — `RunOverrideExpiry`'s ticker;
  needs a store, not a server.
- `TestARepriceBeforeReadyEmitsNoSpan` (~71) — its siblings
  `TestMeteringStartsAtReadyE2E`, `TestFailedProvisioningNeverBills` and
  `TestFailureAfterReadyClosesTheSpan` are **already** in `reconcile`. This one
  landed in `identity` only because it happened to start from a PATCH.

## Move to `internal/estimates` — no database at all

- `TestUnpriceablePinIsRefused` (~60) — ~50 lines of world setup for one catalog
  fact. Now largely covered by
  `TestAPinIsPriceableOnlyWhereTheShapeDeclaresInstances`; keep at most one
  handler-level assertion that the refusal surfaces as 422.

## Keep in `identity` — the claim is cross-layer and exists nowhere else

- `TestAPinsInstanceCountIsBoundedAtEveryLayer` — "422 from the engine, 402 from
  the cap, and the cap writes the spine" is only meaningful across handler +
  engine + budget + events.
- `TestManualOverrideRespectsTheCapAndExpires` — the task's acceptance test.
- `TestAPinAndItsReleaseAreBothVisibleInTheActivityFeed` — asserts the feed's
  serialized shape, which only exists over HTTP.
- `TestAConcurrentEditIsRefusedNotSilentlyOverwritten` — the 409 mapping needs
  the real row, the real generation and the real handler.

## The structural fix

Lift `newWorld` into `internal/testsupport` so `provisioning` can own its own
HTTP-level tests. Do this FIRST — without it, the next task faces the same
forced choice and the file regrows.

Separately and lower value: a shared `newPinnedWebService(t)` helper would
remove ~300 lines of repeated org→project→estimate→service setup mechanically,
without moving anything.

## Notes

Filed rather than done inside US-3.8, on the same reasoning that split O16 out:
moving 560 lines across packages and introducing a shared test-support package
is structural work, and structural work deserves its own review rather than
riding a feature branch. Both reviewers' lists agreed; where they differed only
in emphasis, the union is recorded above.
