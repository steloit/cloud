## The gap

`ready`/`degraded`/`failed`/`provisioning`/`suspended`/`deleting` (ADR-024) is
written down five times:

1. `provisioning.transitions` — the state machine
2. `reconcile/http.go`'s `statusVocab` — what the writeback endpoint accepts
   (plus the wire-only `gone` and `""`)
3. the `CHECK (status IN (...))` in `20260718203138_services.up.sql`
4. `docs/product/09-data-models/models.md` §Enums
5. the generated `ServiceStatus` enum from `openapi.yaml`

Measured (US-3.3a QA, 2026-08-23): adding an `archived` state to the machine —
consistently, in every Go representation — is **green across the whole suite**,
while the DB `CHECK` would reject the UPDATE with SQLSTATE 23514 and the
writeback would 400 the status as unknown. The vocabulary drifts silently in the
direction that matters: a status the code believes in and the database refuses.

## Why the obvious fix is wrong

Deriving all five from one Go constant does not work — the DB CHECK is applied by
Postgres and the OpenAPI enum is the wire contract, generated. The pin has to be
a TEST that reads each representation from its own artifact (parse the migration
SQL, parse `openapi.yaml`, read the Go maps) and asserts one set. That is the
same shape as `TestTheBackfillMigrationMatchesThePlanTable` (US-3.3e), which
parses shipped SQL rather than trusting a second copy of it.

## Acceptance criteria

1. One test reads all five representations from their own files and asserts a
   single vocabulary, naming which one disagrees.
2. Adding a status to any one of them fails it. Mutation-verified for each of
   the five, on a GREEN baseline.
3. `gone` and `""` are handled explicitly as WIRE-ONLY (`reconcile/http.go` maps
   `gone` to observation-only), not silently tolerated as a sixth state.
4. The test fails if a representation cannot be found, rather than passing by
   failing to look.
