## Goal

Move the verification lessons of E3 out of conversation history and task files and
into the files agents actually read, so every future task inherits them.

## Why

Founder directive (2026-07-27): *"I do not want those lessons to remain trapped in task
files or conversation history. Treat the Engineering OS as a first-class product."*

The review is `docs/plan/engineering-os-review-2026-07.md`. Its central finding: across
eight tasks, **one defect class produced the majority of blocking review findings and the
gate caught none of them** — a test asserting a *proxy* for the property rather than the
property, passing for a reason unrelated to what it claims. Seven instances, one shape.

## Scope

Adopt **C1–C5** (critical) and **H1–H6** (high value) from the review. Explicitly out of
scope per the founder: architecture changes, new agents. N1–N4 are not adopted here.

## Approach

1. `.claude/agents/qa.md` — mutation classes, not examples (C1).
2. `.claude/skills/verify/SKILL.md` — negative evidence + skip-proof gates (C1, C5).
3. `contexts/canon-testing.md` — the proxy-assertion classes (C2), semantics-derived
   registry tests (C3), API-constructible fixtures (H3), three techniques (H4).
4. `AGENTS.md` — fault injection in a copy, binding the implementer (C4).
5. `.claude/agents/reviewer.md` — dimension 7, displaced guards (H1).
6. `.claude/skills/task-pickup/SKILL.md` — blast radius (H2) and prior mutations (H6).
7. `contexts/api-conventions.md` — the silent-acceptance class (H5), in the review's
   7-line form. A first attempt wrote a longer entry, hit the pack cap, and was moved to
   AGENTS.md on a rationale that review showed to be false (the validator enforces >160
   while its message says "150 cap"; the pack was at 151, so the short form always fit).
   Corrected: the entry belongs in the pack, and the validator's own 150-vs-160
   discrepancy is filed as **O12**.

## Acceptance criteria

- [x] Every C and H recommendation appears in the file the review names, in a section an
  agent already reads.
- [x] Each entry carries its EVIDENCE (the task and the concrete failure), not just the
  rule — a mistake bank entry without its incident is a style guide.
- [x] `validate.mjs` passes (agent frontmatter, agents-readonly, table sync).
- [x] The authority hook's own test suite still passes (57 passed, 0 failed).
- [x] No product code changes on the branch: `git diff --name-only $(git merge-base HEAD <base>)...HEAD -- services apps packages` is empty, captured AFTER committing (the worktree-only form would miss staged or committed code — and the range form proves nothing while the branch has no commits).

## Out of scope

N1 (spec anti-vacuity line), N2 (retro harvest step), N3 (validator skip-proof check).
Recorded in the review; not adopted.

**N4 (agent-failure policy) WAS adopted**, on QA's argument: O11 raises the cost of a
review round (a seventh dimension, per-representation mutations, blast radius, mutation
lists), so it increases stall probability while leaving stall-handling unwritten — and a
stalled reviewer is otherwise indistinguishable from an approval. It landed in
`task-pickup` step 6.

## Review round: three blockers, all false evidence

The first submission cited three incidents that **did not happen as described**, in a task
whose own acceptance criterion is "each entry carries its EVIDENCE". Review verified each
against the committed history and rejected all three:

- Dimension 7 claimed US-3.7 *deleted* `Price`'s `default:` arm, leaving a declared product
  priced at 0 cents. `34774cd` shows the arm already present; US-3.7 *repurposed* it. The
  0-cent outcome existed only as a counterfactual in my own code comment, which I then
  narrated as history.
- `verify` claimed CK-M3 first shipped a non-skip-proof gate. Its claim commit had
  `verify: []` and its implementation commit already carried the grep form — CK-M3 is
  where the fix was INVENTED. The real silent-skip incident is US-1.3, which is in the
  review's evidence base and now carries the entry.
- `task-pickup` claimed every E3 survivor was found in an unexplored class, "never in a
  re-run of the builder's own" — falsified by the very finding C1 cites, which came from a
  reviewer re-running my plaintext scan against a different representation.

Also corrected: the "no product code" gate compared worktree-to-index only, so staged or
committed product code would have passed it — the exact defect class
`contexts/canon-testing.md` already records from Q3, in the file this task edits.

## Outcome

Eleven recommendations landed across six files. Every entry carries the incident that
produced it — a mistake bank entry without its evidence is a style guide, and the entries
that have actually changed behaviour in this repo are the ones naming the task and the
concrete failure.

**No deviation in the end.** H5 briefly moved to AGENTS.md when a long draft hit the pack
cap; review showed the rationale was false — the validator enforces >160 while its message
says "150 cap", so the pack had headroom and the review's own 7-line form always fit. It
sits in `contexts/api-conventions.md` as proposed, and the validator's message/behaviour
discrepancy is filed as **O12**. Worth noting: the wrong diagnosis came from trusting an
error message over the code that produced it.

**What is now written down that was not.** That a mutation is a hypothesis about a class,
not a check that a test can fail. That an assertion satisfiable by output from elsewhere in
the program is a defect regardless of whether it currently passes. That a refactor
relocating validation between layers is the highest-risk shape in this repo, because the
new check gets tested and the thing the old one quietly did does not. That fault injection
in the working tree corrupts other agents' evidence — with the incident where it did.
That a green suite proves code runs, and only a recorded mutation proves a test
discriminates.

The seven proxy-assertion instances are listed with the mutation that survived each, so a
future agent can pattern-match rather than rediscover.

Not adopted (recorded in the review, not implemented): N1 spec anti-vacuity line, N2 retro
harvest step, N3 validator skip-proof check, N4 agent-failure policy.

Evidence: `validate.mjs` OK (206 tasks, 8 packs under the ENFORCED cap of 160;
`api-conventions.md` is 158, which is over the 150 documented in `contexts/README.md` —
that discrepancy is O12, and O11's entry is the ~8 lines that must move if 150 wins);
`protect-authority.test.sh` 57 passed, 0 failed; the merge-base product-code gate empty
when run against the committed branch.
