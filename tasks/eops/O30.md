## Goal

O29 pinned every gate in `ci.yml`. `.github/workflows/image.yml` is a second
workflow with its own gates and **none of them are pinned** — cosign keyless
signing and `provenance: mode=max`, described in-file as T1.3 / invariant-11
supply-chain controls.

## Why it is its own task

O29's reviewer explicitly said deferring was right — different workflow, different
failure mode, and that PR was already wide. But it also said the deferral belongs
in `tasks/`, not in prose inside a finished task's Outcome, because *"prose in a
done task's Outcome is where follow-ups go to die."* This is that task.

## What to do

Extend `ciGates` (or add a sibling `imageGates`) in
`services/api/internal/platform/testenv/wiring_test.go`. The machinery is already
there and already handles the classes that matter:

- shell comments inside a `run:` scalar (a needle matching a corpse)
- `continue-on-error` at job **and** step level
- a constant-false `if:` on the gate-bearing step
- workflow triggers removed
- an env key present but **empty**

The one genuinely new question is whether a `uses:`-style step (cosign is likely
an action, not a `run:`) needs a different assertion shape than `runContains` —
`Run` is `""` for those, which currently fails closed but also cannot express
"this action is present with these inputs".

## Acceptance criteria

- [ ] Removing cosign signing from `image.yml` fails a test.
- [ ] Removing `provenance: mode=max` fails a test.
- [ ] The `uses:`/`with:` shape is asserted properly rather than by absence.
- [ ] Same mutation classes as O29 verified, each individually.
