## Goal

Every agent defined under `.claude/agents/` is automatically discoverable and
invokable **by name** in the execution harness. Repository-defined agents take
precedence over any globally installed plugins. An unresolved repository agent
**fails fast** — no silent fallback to an unrelated global plugin.

(Founder framing: "INF-00X — Agent Registration". Filed under EOPS as the
Engineering-OS tooling owner; this is a tooling improvement, not an
implementation blocker.)

## Why

During autonomous implementation the mandatory ADR-0008 review pipeline needs
the repo's `reviewer` and `qa` agents. In the current harness those files exist
but are **not registered as invokable subagent types**, so `subagent_type:
"reviewer"` errors — and the only "reviewer"-named type available was the
machine-level `kernel:reviewer` **plugin**, which is explicitly rejected for
this repo (`docs/plan/kernel-workflow-review.md`, ADR-0008). The silent
availability of the plugin (with no repo agent to shadow it) caused a real
workflow drift: an external reviewer was invoked before it was caught. The fix
is to make repo agents first-class and to make unknown-agent requests loud.

## Acceptance criteria

`[~]` = partially met; the shortfall is not achievable within this task's scope and
is recorded in the Outcome. It is a deviation to read, not a silent pass — and
`validate.mjs` does not parse checkboxes, so nothing but the Outcome carries it.

- [x] `.claude/agents/*.md` (reviewer, qa, research, docs — and any future
  agent) are resolvable by their frontmatter `name` as `subagent_type` values
  in this harness.
- [~] A repository-defined agent name **shadows** any identically- or
  similarly-purposed global plugin agent (repo precedence). *Verified against
  namespaced plugins: bare `reviewer`/`qa` resolved to this repo's files while
  `kernel:reviewer` was installed. Precedence against a user-level
  `~/.claude/agents/` file of the same bare name is untested — none existed.*
- [~] Requesting an unregistered agent produces a **hard error** that lists the
  repository-defined agents and the available runtime agents, and states "No
  automatic fallback is permitted" — never a silent substitution. *Hard error
  and listing verified; there is no fallback. The literal sentence is
  harness-owned wording this repo cannot set — see Outcome.*
- [x] The ADR-0008 pipeline can invoke `reviewer` and `qa` by name (removing the
  documented general-purpose-with-verbatim-prompts workaround).

## Interim (already in place, not part of this task's fix)

Until this lands, reviews run per ADR-0008's "reviewer identity is fixed and
repo-native" clause by executing the verbatim `.claude/agents/reviewer.md` and
`qa.md` instructions through a generic **read-only** runner (`general-purpose`),
never Kernel. This task removes the need for that workaround.

## Out of scope

- Rewriting the reviewer/qa agent instructions (they are the source of truth).
- Any change to the review POLICY (independent architecture + QA, read-only,
  mandatory, no Kernel) — that is invariant and already codified in ADR-0008.

## Outcome

Registration already worked; what was missing was the written contract and the
evidence. Shipped `.claude/agents/README.md` as the living file recording the
registration contract and its reproducible checks, and retiring the
`general-purpose`-runner workaround. `reviewer` and `qa` resolve by name and
serve their repo files' prompts; an unregistered name hard-errors and lists the
repo agents with no substitution.

Both reviewers materially changed the result, which is the point of the pipeline.
The first draft's verification procedure was **wrong**: it checked
self-identification, which the retired pasted-prompt workaround passes just as
well — it would have failed to detect the one regression it existed to catch.
Replaced with a harness-enforced tool-grant probe, verified live (`reviewer`
reports `Write: absent, Edit: absent`). That probe also falsified a claim the
draft asserted — the effective grant is `Read, Bash`, *narrower* than the
frontmatter's four tools — so `tools:` is now documented as a request, not a
guarantee. Also corrected: "every `.md` file is an agent" (this README is not),
an unenforced claim that `docs` can only write to two paths, and duplicated
kernel policy now reduced to an ADR-0008 pointer.

Verifying the *new* procedure then falsified part of it in turn: `Reviewer`
resolves rather than erroring — matching is case-insensitive. It folds to this
repo's `reviewer` (same identity, same `Read, Bash` grant), so it is a fold, not
a substitution, and the README now says so. `reviewers` and `code-reviewer` do
hard-error as claimed.

Deviations, recorded rather than quietly marked met: criterion 3's literal
sentence is harness-owned wording; criterion 2 is downgraded to `[~]` because
shadowing was only observed against *namespaced* plugins — a user-level
`~/.claude/agents/reviewer.md` is an untested bare-name collision. `kernel:*`
stays visible because it is installed at the machine level; the README's
"visibility is not permission" is documentation, not enforcement.

The re-review then found the most consequential thing in the task, and it is a
finding beyond O6's scope: **"read-only reviewer" is not enforced anywhere.**
Withholding `Write`/`Edit` proves an agent is repo-native, not that it cannot
write — `reviewer` holds `Bash`, and `echo x > file` was verified to execute with
no prompt, while `protect-authority.sh` inspects only a tool's `file_path` and so
never sees a shell redirect. ADR-0008 calls the two reviewers read-only; that is
a behavioral constraint they observe, not a technical control. The README and O6c
now say so explicitly rather than letting an absent `Write` tool read as a
sandbox. Whether to actually constrain `Bash` needs its own task and likely its
own ADR — flagged here, not decided.

Follow-ups filed: **O6a** — a settings-level deny rule for `kernel:*`, the only
thing that would make the prohibition enforced. **O6b** — the retirement is
undiscoverable: CLAUDE.md §5a never names the two `subagent_type`s, while eight
completed Outcomes model the old pattern, so a session grepping for precedent
finds the workaround eight times and its retirement zero. **O6c** — `validate.mjs`
covers nothing under `.claude/**`, so adding `Edit` to `reviewer.md` would
silently convert a reviewer into a writer against ADR-0008, and no check pins
the README table to the files. All three lie outside this task's
`.claude/agents/**` glob.
