## Goal

Valkey cache as an **optional** managed service — never provisioned by default; provision-on-add, idle-suspend, hard memory quotas (ADR-0004/A5.1).

## Summary

Valkey is the cache substrate (D5), but a cache can't scale to zero — so a dedicated pod per project is a permanent idle floor. A5.1: provision only on explicit add, idle-suspend when unused, hard quotas; shared-multi-tenant-with-isolation permitted if idle economics require. Driver instantiates the Postgres pioneer anatomy (create → estimate → ready); estimate shapes + bindings. Frames S2/D3/D6/D14 (depth data-plane pending E14).

## Acceptance criteria

- [ ] No cache pod exists for a project until the project explicitly adds one
- [ ] Idle caches suspend (release compute) and resume on demand; hard memory quota enforced
- [ ] create → estimate → ready loop identical to Postgres (one grammar); metering starts at ready
