## Goal

Extend the Binding primitive so a target can be an external provider (`target_type ∈ {service, storage, ai}`) — the shared mechanism behind Storage and AI Bindings (ADR-0004/A5.5).

## Summary

A Binding already manages credentials, injects config, and rotates. A5.5: the target may be an external provider (`provider` + `provider_config` + `secret_ref`) instead of an internal service id. Credentials live in Secrets (reveal-once, rotated, never returned); config injected as env vars; allow-policy governs which providers/regions/models are permitted (RBAC + policy). Grammar isolation (D8): the only substrate name that may reach a customer surface is the provider the customer chose. openapi.yaml Binding schema already carries the fields (this task implements them).

## Acceptance criteria

- [ ] A Binding can target an external provider; credentials resolve from Secrets, never stored on the binding, never returned in reads
- [ ] Injected env vars are deterministic; allow-policy denies disallowed providers with a named-policy problem+json (rbac grammar)
- [ ] Lifecycle (create/rotate/revoke) audited on the events spine
