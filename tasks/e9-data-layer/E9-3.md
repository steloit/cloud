## Goal

The two external Bindings on the shared mechanism (E9-2): **Storage Binding** (S3/GCS/R2) and **AI Binding** (LLM provider) — governance + certainty, never proxying.

## Summary

**Storage Binding (A5.3):** connect the customer's own bucket — provider + region + bucket in `provider_config`, access keys in Secrets, config injected; allow-policy; estimate-at-bind (provider's public price shown); lifecycle audit. Steloit never proxies bytes and never bears egress. No managed storage product.

**AI Binding (A5.4):** bind to an LLM provider — allow-policy (providers/models), API key in Secrets, config injected; **estimate-at-bind** (model $/1k tokens — certainty on the scariest new bill); cost visibility surfaced from the provider usage API into billing; **soft** spend control (suspend/rotate at a threshold); lifecycle audit. **No proxy, no routing, no hard in-line caps** (that is the gateway commodity — never build). Distinct from the four-laws assistant (E13).

## Acceptance criteria

- [ ] Storage Binding: connect S3/GCS/R2; app reads its bucket directly; Steloit stores no bytes and shows the provider's price at bind
- [ ] AI Binding: bind a provider; estimate-at-bind shows model pricing; provider usage surfaced in billing; soft cap suspends the binding at threshold
- [ ] Neither binding proxies traffic; both audited; credentials only in Secrets
- [ ] No code path routes across providers or enforces a hard in-line cap (guardrail — A5.4)
