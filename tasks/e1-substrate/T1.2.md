## Goal

The production CNPG operator + OpenEBS ZFS-LocalPV storage layer deployed by Terraform/manifests — the substrate a customer database is born on, shaped by T1.0's measured findings.

## Why

Every customer Postgres (and the control-plane DB) runs on this layer; the spike proved the mechanics, this makes them the deployable, versioned shape (ADR-0003; one operator to know everywhere).

## Read first

- `docs/adr/0007-substrate-spike-findings.md` — the working storageclass/snapshotclass yaml and every measured constraint (this task productionizes exactly what worked)
- `docs/plan/e1-substrate-design.md` §1 (module shells to fill) + §2 (what the reconciler will later render — T1.2 installs platform, not per-customer clusters)
- `docs/architecture.md` §3 — CNPG ≤ 1.30 pin (in-tree Barman) and the version-knob note
- Don't read: console/UI docs.

## Approach

1. Fill `infra/modules/cnpg`: operator install (pinned ≤ 1.30 per architecture §3 v1.3 — a HARD ceiling, ADR-0007 F6), operator config, and the control-plane CNPG cluster (single instance, PITR to its own GCS bucket — invariant 10) **plus the F3 ScheduledBackup (load-bearing: WAL alone is not restorable)**.
2. *(Amended per ADR-0007/A6, ratified 2026-07-19 — was ZFS-LocalPV.)* Fill the storage side of `infra/modules/gke-cell` + `infra/k8s/storage/`: **PD-CSI** `StorageClass`/`VolumeSnapshotClass` — the exact yaml T1.0 proved, verbatim; the storage pool gains a `storage_driver` variable (`pd` canonical; `zfs` retained as the Cell-1 density knob, kit in `infra/spike/`).
3. `infra/k8s/` manifests are plain yaml applied by Terraform (`kubernetes_manifest`/helm provider) — one apply path, no second tool.
4. WAL archiving defaults (`archive_timeout` per the measured RPO number) templated into cluster config; the value cites the findings ADR.
5. Wire into both envs; dev applies first; cell0 is identical shape.

## Edge cases

- CNPG version pin vs upgrades: the pin is a tracked knob (architecture §3) — a bump is a PR citing the barman-cloud issue status, never a drive-by.
- PD volumes survive node replacement (a key A6 rationale); under the `zfs` knob, local-SSD node replacement loses pool state by design — that procedure doc rides the Cell-1 re-evaluation.
- The `zfs` knob additionally requires Ubuntu nodes + the zpool bootstrap DaemonSet (infra/spike/manifests/zfs-node-setup.yaml) — never flip it casually.

## Security & performance

Operator in its own namespace, least-privilege RBAC as shipped upstream (no cluster-admin widening); storage pool nodes tainted `storage=<driver>:NoSchedule` so only CNPG pods land there; the control-plane DB archives via workload identity (F5 — zero static keys, D5).

## Common mistakes

- Diverging from the spike's proven yaml "while cleaning it up" — productionize verbatim first; refactor as a separate reviewed change.
- Installing a second apply tool (kustomize/argo) — Terraform is the one apply path at this stage.
- Unpinned operator version.

## Outcome

Productionized the substrate layer **per the ratified ADR-0007/A6** (PD-CSI
canonical; the task's original ZFS text amended above, never silently):

- `modules/cnpg` filled: CNPG operator via `helm_release`, **pinned 1.30.0 with
  the §3-v1.3 ceiling citation** (in-tree Barman removed in 1.31 — F6; the
  barman-cloud plugin migration is the tracked exit); the T1.0-proven
  **`pd-cell` StorageClass + `pd-cell-snapclass`** applied from
  `infra/k8s/storage/*.yaml` (one source of truth; NOTE the apply is STAGED —
  `kubernetes_manifest` plans against the live cluster API and CNPG CRs need
  the operator's CRDs first; the required sequence is documented in
  infra/README.md — a bare full apply on empty state fails by provider design);
  and the **control-plane CNPG cluster** (single instance, `archive_timeout:
  300s` citing the measured bound, PITR to the SEPARATE `wal-control` bucket —
  invariant 10, workload-identity GSA plumbing — F5) **plus the F3 nightly
  `ScheduledBackup` with `immediate: true`** — restorable from day one, because
  WAL alone is not.
- `modules/gke-cell` storage pool is now **driver-agnostic**: `storage_driver`
  variable (`pd` canonical — no local SSD, survives node replacement; `zfs`
  retained verbatim as the Cell-1 density knob with its local-SSD shape).
- Both envs wired (dev carries the control plane; cell0 identical shape,
  `pd`), k8s/helm providers configured from gke-cell outputs with the caller's
  token — zero static keys.

Verified: `terraform fmt -check` clean; `validate` passes for dev and cell0
both against the live backend and in a fresh CI-parity `-backend=false` init;
all `infra/k8s/**` yaml parses (now also in CI); the chart pin greps with its
citation. **Review pipeline (arch + security/QA) findings fixed:** the chart
