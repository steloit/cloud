## Goal

Real measured numbers for the CNPG+ZFS branching substrate — branch create time, CoW delta cost, wake latency, RPO, PITR — recorded in a findings ADR that the estimate engine and the $0.07/day canon line build on.

## Why

ADR-0003 chose the substrate on architectural evidence; this spike converts it to *measured* evidence before anything else is built on it (the founder's rule: measured data, not assumptions, validates architecture and pricing).

## Read first

- `docs/plan/e1-substrate-design.md` §3 — the 9-step runbook this task executes exactly
- `docs/adr/0003-database-substrate.md` — what was promised; every promise gets a number here
- `docs/product/00-sources/INF-001-infrastructure-constitution.md` A1.3 (RPO ≤ 5 min, value pending founder ratification — this spike produces the evidence) + A4
- Don't read: anything console/UI; 99-history.

## Approach

1. **GATE: requires P1** (GCP project id + billing). Until then, author `infra/spike/`: numbered scripts (`01-cluster.sh` … `09-teardown.sh`) mirroring the runbook steps, CNPG manifests (`spike-a.yaml`, `spike-b-recovery.yaml`, hibernation patches), and `check.sh`.
2. Scripts are dumb and rerunnable: each prints its measurement as a greppable `MEASURE key=value unit=` line; `08-collect.sh` assembles `measurements.txt`.
3. Execute on `envs/dev` (T1.1) once P1 lands; run latency-measured steps twice (cold + warm).
4. Write `docs/adr/0007-substrate-spike-findings.md`: the measurement table, commands verbatim, deltas vs promises (RPO ≤ 5 min A1.3; branch cost vs the $0.07/day canon preview line; wake latency vs gateway cold-connect expectations), and any fired trigger (a broken promise is implementation evidence under ADR-0001's rules — surfaced, never silently absorbed).
5. `check.sh` (the verify): asserts the findings ADR exists and contains all six MEASURE keys (`snapshot_create_s`, `branch_create_s`, `cow_delta_bytes`, `wake_latency_s`, `rpo_measured_s`, `pitr_to_new_s`) plus a `## Verdict` section; asserts all spike manifests parse (python3 yaml); exits 1 while any is missing.

## Edge cases

- WAL archive lag exceeds 300s under load → that IS the finding; record, don't tune past it silently (A1.3 ratification consumes this number).
- Hibernated wake fails or exceeds tolerable cold-start → record; feeds the gateway design, may fire a trigger.
- ZFS-LocalPV snapshot class quirks on GKE local SSD → document the exact storageclass/snapshotclass yaml that worked; this is the spike's de-risking job.

## Security & performance

Spike runs in `steloit-dev` only (destroyable); pgbench synthetic data only. Teardown (step 9) is part of done — no idle spike infra survives the week (O2 cost guardrails).

## Acceptance criteria

- [ ] WHEN `bash infra/spike/check.sh` runs THEN it passes: findings ADR present with all six MEASURE keys + Verdict; manifests parse
- [ ] WHEN the findings ADR is read THEN every ADR-0003 promise has a measured number beside it, with the exact command
- [ ] WHEN measurements contradict a promise THEN the contradiction is a named finding with the fired trigger, not an adjusted number
- [ ] Spike infra torn down; teardown output in the PR

## Validation

`verify:` runs check.sh. PR evidence: measurements.txt, the ADR, teardown output. RPO *ratification* (founder) consumes the ADR — not part of this task's done.

## Common mistakes

- Measuring once (cold-only) and reporting it as the number — cold and warm are different products.
- Letting the spike grow into T1.2 (operator productionization) — this is measurement, not build.
- Recording derived $/GB-mo without showing the raw bytes and the arithmetic.

## Out of scope

- Production operator/storageclass layout → T1.2. Terraform → T1.1. RPO ratification → founder (INF-001 A1.3).
