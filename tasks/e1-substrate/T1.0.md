## Goal

Week-1 spike: ZFS snapshot → CNPG branch end-to-end *(redefined by ADR-0003 / INF-001 A4 — the Pageserver↔GCS spike is moot)*

## Summary

On a GKE node with OpenEBS ZFS-LocalPV: create a CNPG cluster → write data → VolumeSnapshot → new CNPG cluster via `bootstrap: recovery` from the snapshot → verify data + write divergence (CoW) → hibernate both → measure wake latency and per-branch storage delta. Also verify WAL archiving to GCS with `archive_timeout` ≤ 5 min (A1.3 RPO) and PITR-to-new-cluster. All documented, boring paths — this spike de-risks mechanics and produces the branch-cost numbers for the estimate engine.

## Acceptance criteria

- [ ] Branch e2e (snapshot → recovered cluster) works with measured create time and CoW delta cost
- [ ] Hibernation wake latency measured; WAL-to-GCS RPO ≤ 5 min verified; PITR-to-new-cluster verified
- [ ] Findings ADR recorded by end of week 1 (numbers feed the estimate engine and the $0.07/day check)
