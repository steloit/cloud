## The defect

`cnpg.storageForShape` sizes the PVC from `shape["size"]` and a `shape["storage"]`
key — but `storage` is NOT in the API's closed shape schema
(`estimates.shapeSchema` allows `storage_gb`), so the API rejects it and the
driver never sees it. The **priced** `storage_gb` is never read.

A customer billed for 78 GB receives the size-derived default (10Gi for `dev`).

## Why it matters

US-3.7 made the API guarantee that what provisions is what was priced. This
breaks that guarantee one layer down: the contract is enforced at the gate and
then discarded by the renderer. Being right at the API and wrong at the cell is
worse than being wrong consistently — the invoice and the audit trail both say
the customer got what they paid for.

## Investigated 2026-08-23 — the defect is WIDER than filed, and one part needs a ruling

`storageForShape` is twelve lines and contains **three** independent defects, not
one. Measured against `pricing.json`, which is the catalog:

| size | `included_gb` (priced) | PVC rendered today |
|---|---|---|
| `dev` | 0 | 10Gi |
| `standard` | **50** | **32Gi** |
| `performance` | **50** | **10Gi** (no case — falls through `default`) |
| `pro` | *not in the catalog* | 128Gi (dead code) |

1. **The filed defect.** `shape["storage"]` is not in `estimates.shapeSchema`
   (which allows `storage_gb`), so the API rejects it and the driver never sees
   it. The priced `storage_gb` is never read.
2. **`standard` renders 32Gi while its size alone includes 50 GB.** Under-
   provisioned *before* any extra storage is purchased — this one does not need
   `storage_gb` to be involved at all.
3. **`performance` has no case**, so the most expensive size (11200¢, 50 GB
   included) gets the **smallest** volume. `case "pro"` is dead: no such size
   exists.

### RULED 2026-08-23 (founder): unset means the size's `included_gb`, not 0

> "The customer-facing pricing definition takes precedence. When `storage_gb` is
> unset for a `standard` Postgres, the effective included storage is **50 GB**.
> Do not interpret unset as 0."

So `included_gb` is storage the customer **GETS**. Of the two readings below the
first is the ruling; it is implemented at the **API**, not the driver, because
`included_gb` is a pricing concept and the cell-agent is a separate module that
must not carry a copy of the catalog. Resolving it at the gate also satisfies
US-3.7's law directly: the shape a customer is priced on — and the one persisted
and shipped to the cell — says 50 rather than implying it.

### The reading that was open before the ruling

`storage_gb` defaults to **0** in the shape schema, and `included_gb` is a
*pricing* concept the cell-agent cannot see (it must not import the API's pricing
table — separate module, and duplicating the table is how it drifts).

So: **what does a `standard` with `storage_gb` unset actually receive?** The
price says 50 GB is included. The AC below says "sized from the priced
`storage_gb`", which for an unset field is 0. Those cannot both be satisfied.

Two coherent answers, and the choice is the founder's because it decides what
"included" means commercially:

- **`included_gb` is storage the customer GETS** → PVC = `max(storage_gb, included_gb)`,
  and the control plane must resolve that (it is the side that knows the catalog),
  passing an explicit size in the `Spec` rather than leaving the driver to guess.
- **`included_gb` is only "not charged extra"** → PVC = `storage_gb`, and the API
  should default `storage_gb` to the size's included amount so the contract is
  explicit at the gate rather than implied at the cell.

The second is more consistent with US-3.7's law (what provisions is what was
priced, and the priced shape is the contract). Either way the fix belongs partly
in the **control plane**, which is why this task's `files:` already includes
`services/api/internal/provisioning/services.go`.

### Not blocked on that ruling

Defects 2 and 3 are wrong under *both* readings — `standard` and `performance`
are under-provisioned relative to what their own base price includes, with no
`storage_gb` involved. Those can land first.

## Outcome

Three defects, one ruling, both planes.

**API** (`estimates.resolve`): an unset postgres `storage_gb` now resolves to the
size's `included_gb` (founder 2026-08-23). The price does not move — `Price`
charges `storage_gb - included_gb` only when positive, so 50 - 50 = 0 — and a
test pins that against the catalog's own base_cents, because a defaulting rule
that re-prices existing customers is a billing incident, not a rendering one.
`Canonical` treats unset and explicit-50 as the SAME contract, so a customer who
spells out what they were given can still provision the estimate they were
quoted. An explicit 0 is left alone: absence and zero are different declarations.

**Driver** (`cnpg.storageForShape`): sizes from `storage_gb`, floored at the
size's included amount. `storage` — never in the API's closed schema, so the
priced value was never read — is removed, not dual-read. `pro` (no such size) is
gone, `performance` (11200¢, 50 GB included, previously rendering the *smallest*
volume) is handled, and an uncatalogued size is REFUSED rather than defaulted.
An ABSENT size is still `dev`, matching the API's schema default — following the
contract, not guessing.

**The catalog is the source.** `TestEveryCatalogSizeRendersAtLeastItsIncluded
Storage` reads `pricing.json` from the repo root (the `parity_test.go`
precedent), so the cell-agent binds to the catalog without importing it.
Mutating `included_gb` to 4000 turns the driver RED — the binding is real, not a
retyped list that can be wrong in the same direction as the code it checks.

**Both halves of the wire.** The resolved shape crosses to the cell as JSON, so
the `int` the API resolves arrives as a `float64`. Reading only the Go int would
have proved nothing about the bytes the agent sees; both sides are pinned.

**Ten mutations RED**, on harnesses whose no-mutation baseline was asserted GREEN
first: standard floored back to 32 · performance dropped from the table · the
dead `storage` key re-read · float64 ignored · unknown size falling through ·
`included_gb` moved in the catalog · the default removed · unset back to 0 · the
default overwriting an explicit value · included storage charged for.

**One existing test was corrected, not adjusted to pass.** `TestRenderErrorPaths`
asserted that a non-string `size` silently became `dev` — the smallest volume,
which is exactly the under-provisioning this task closes. It now requires a
refusal: `size: 42` reaching the driver means the API's string schema was
bypassed, and answering that with the cheapest PVC is a guess about a contract
we cannot read.
