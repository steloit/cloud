## Goal

Every image Steloit ever runs is built in CI, signed keylessly, and carries provenance — from the very first build, with the cluster refusing anything unsigned.

## Why

Invariant 11 (signed images + provenance from first build) is only cheap if it predates the first image; retrofitting signing onto a running fleet is the expensive path. `services/api` and `cell-agent` are born into this pipeline (O1 dep).

## Read first

- `docs/architecture.md` §14 — Kaniko/BuildKit on the workload pool, cosign, provenance from first build
- `infra/modules/project-base/main.tf` — WIF pool/provider this pipeline federates through (zero static keys)
- `docs/product/00-sources/INF-001-infrastructure-constitution.md` invariant 11 + D5
- Don't read: console/UI docs.

## Approach

1. **Artifact Registry** (Terraform, project-base): `google_artifact_registry_repository` (docker format, region), cleanup policy keeping last N + signed tags; CI SA gains `artifactregistry.writer` scoped to the repo.
2. **`.github/workflows/image.yml`**: path-triggered on `services/**` + `Dockerfile*` (dormant until services exist — deliberate); auth via `google-github-actions/auth` WIF (no keys); build with BuildKit (`docker/build-push-action`) → push to AR → **cosign keyless sign** (GitHub OIDC identity) → SLSA provenance attestation attached.
3. **Cluster admission** (`infra/k8s/policy/`): sigstore policy-controller manifests — `ClusterImagePolicy` requiring keyless signatures from this repo's identity for `*.pkg.dev/<project>/steloit/*`; enforcement namespace-labeled (customer namespaces + core, not kube-system).
4. Policy install rides T1.2's Terraform apply path (one apply path rule); manifests authored + parse-verified now, applied with the cluster.
5. Document the trust chain in `infra/README.md` (identity → Fulcio cert → policy match).

## Edge cases

- No services exist yet → workflow is path-gated and inert; first real build is `services/api`'s first commit (E2/E3) — pipeline must already be green then.
- Emergency image (policy blocks a hotfix) → break-glass is editing the ClusterImagePolicy via PR, never disabling the controller; documented.
- Base-image provenance is out of scope (we attest OUR build; base pinning by digest is the rule).

## Security & performance

Keyless only — a cosign key would be a static secret (D5 violation). CI identity = the WIF-federated GitHub OIDC subject; policy pins `subject`/`issuer` to this repo's workflow. Builds run on GitHub runners now; move to the gVisor workload pool when volume justifies (measured trigger, not now).

## Acceptance criteria

- [ ] WHEN image.yml + policy manifests are parsed THEN they are valid (verify)
- [ ] WHEN Terraform validates THEN the AR repo + scoped writer role are present, keyless (no `google_service_account_key`)
- [ ] WHEN the cluster exists (P1) and policy is applied THEN an unsigned image is rejected — evidence: the rejection message in the PR/issue (cluster-gated AC, executed with T1.2's apply)
- [ ] Trust chain documented in infra/README.md

## Validation

`verify:` runs parse + terraform checks locally/CI. The cluster-gated AC (unsigned rejection) lands as evidence when P1/T1.2 apply happens — same authored-vs-applied split as T1.1.

## Common mistakes

- Generating a cosign keypair "for now" — keyless or nothing (D5).
- Enforcing the policy in kube-system (breaks GKE system images) — namespace selectors matter.
- Triggering image builds on every push (path-gate to `services/**`).

## Out of scope

- Control-plane deploy via reconciler → O1 (deps this). Build-on-workload-pool → measured trigger later. Base-image scanning → Trivy rides the same workflow later (architecture §17 names it; wire when services exist).
