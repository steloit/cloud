## Goal

One append-only events pipeline (GOV-002 primitive 9) with live SSE fanout — the single
source for audit, `/events`, the bell, notifications, and deploy markers.

## Why

Every later epic writes to or reads from this spine (metering, notifications, deploy
markers for QA scenario 1). Views over one table, never parallel truths.

## Read first

- `contexts/events-spine.md` — the contract and mistake bank (binding).
- `docs/product/08-api/openapi.yaml` — `listEvents` (`/envs/{env}/events`, x-streamable,
  kind+cursor), `listAuditEvents` (`/orgs/{org}/audit`, actor+action+cursor), `Event`/`EventList`.

## Approach

1. Migration (migrate CLI, real timestamp): `events` table per the pack row contract —
   `id (evt_), org_id, kind, via CHECK (user|assistant|system), actor, action, subject,
   at, detail jsonb`; `idx(org_id, at desc)`; **append-only enforced at the DB level** by a
   trigger raising on UPDATE/DELETE (owner-proof, unlike REVOKE).
2. `internal/events` package: `Recorder.Append(ctx, Event)` (write row + publish to hub),
   `Hub` (per-org in-process SSE fanout, non-blocking sends, drop-slow-subscriber),
   keyset cursor codec over `(at, id)`.
3. Identity writes events: org created, member added, session login, token minted/revoked —
   "every state change writes an event"; denials land when the mutating endpoints do (T2.7).
4. `listAuditEvents` in the strict server (add to include-operation-ids): org-scoped,
   `audit.read` via the Authorizer, cursor pagination, actor/action filters.
5. `listEvents` SSE: strict server serves the JSON list; a pre-strict route intercept
   handles `Accept: text/event-stream` (oapi strict handlers can't stream) — replay from
   cursor, then live via hub; `id:` on each SSE frame = the cursor (reconnect resume).
   Env→org resolution is an `EnvResolver` seam — real envs arrive with T3.2; until then the
   only resolver returns not_found, and tests inject a fake. Record this as the skeleton
   boundary, not silent scope-cut.
6. Wire recorder + hub in `main.go`; extend the integration world.

## Edge cases

- Cursor from a foreign org → empty page, never cross-org leakage (query is org-fenced).
- UPDATE/DELETE on events → SQLSTATE raised by trigger (integration-tested).
- Slow SSE subscriber → dropped (buffered channel full), never blocks Append.
- Reconnect with `cursor` → no gap, no duplicate (keyset is strict `>`).

## Security & performance

- `audit.read` gates `/orgs/{org}/audit`; `observe.read` gates `/envs/{env}/events`.
- Detail is jsonb pass-through — never render user input into `actor`/`action` enums.
- Fanout is in-process only (single api replica in MVP); cross-replica fanout is a later
  task on the same interface.

## Acceptance criteria

- [x] Ledger is append-only at the DB level: UPDATE and DELETE raise.
- [x] `GET /orgs/{org}/audit` returns the org's events, newest first, cursor-paginated,
      403-with-explanation for `developer`/`billing` roles.
- [x] `GET /envs/{env}/events` with `Accept: text/event-stream` streams: replay-from-cursor
      then live events; frames carry `id:` usable as the reconnect cursor.
- [x] Org-attached identity state changes (org create, member add) each land one event with
      correct `via`. (Login/personal-token changes have no org — the spine row requires
      `org_id`; actor-scoped visibility is a recorded finding, see PR.)

## Validation

`verify:` block plus: integration test output in the PR showing the append-only raise and
an SSE stream capture (replay + live frame).

## Common mistakes

- Enforcing append-only with REVOKE (app role owns the table — trigger or nothing).
- Streaming from the strict handler (it buffers; SSE needs the raw ResponseWriter).
- Offset pagination (keyset `(at, id)` only — offset drifts under append).
- Fanning out before the row commits (publish after successful insert, in that order).

## Outcome

- ONE append-only pipeline: `events` table (migration `20260718191159`) with a BEFORE
  UPDATE/DELETE trigger that raises — owner-proof (REVOKE would not bind the app role);
  integration-tested from SQL. `idx(org_id, at desc, id desc)` matches the keyset.
- `internal/events`: Recorder (append → publish, in that order), Hub (per-org fanout,
  non-blocking, drop-slow-subscriber), opaque `(at, id)` cursors, Reader (newest-first pages).
- `/orgs/{org}/audit` live in the strict server (`audit.read`; developer 403 names the role);
  `/envs/{env}/events` JSON live behind the `EnvResolver` seam (T3.2 fills it; `NoEnvs` until
  then — the recorded skeleton boundary).
- SSE served pre-strict (`Streamer.Intercept`) — strict handlers buffer; the stream replays
  from cursor in batches (no silent cap), subscribes before replay (no gap), dedups by keyset
  (no duplicate), heartbeats, and stamps every frame's `id:` with its cursor for resume.
  Integration test drives replay → live → cursor-resume end-to-end.
- Identity now writes the spine: `org.created` + `member.added` with `via`/actor provenance;
  `AddMember` takes an explicit actor (never inferred).
- **Finding:** login/personal-token changes have no org; the spine row requires `org_id`.
  Actor-scoped event visibility needs an owner-level decision — follow-up filed with T2.7.
