## Goal

Policy evaluation stub (closest-wins, tighten-only)

## Summary

Evaluation only — authoring UI/API is E12. Environment-sensitive restrictions are always policies, never role rows.

## Acceptance criteria

- [x] property test: no policy can widen a matrix N.

## Outcome

- `policy.Engine` implements the `rbac.PolicyLayer` seam from T2.3: consulted only on matrix Y,
  so a matrix N is structurally unwidenable — proven by `TestPropertyNoPolicyWidensN`
  (220 randomized policy environments swept over every N cell; all stayed denied, all named
  a role or policy).
- Typed kinds, no DSL: kinds register by key (`Engine.Register`); first kind `ai_assistant`
  (enforcement `disabled` denies `ai.*` — AI Law 4; `opt_in` is a UI concern, not a denial).
- Closest-wins per key: project-level row overrides the org-level row; org sets the floor.
  Verified against real DB rows in `policy_integration_test.go`.
- Fail-closed everywhere: unreadable policy source denies; an unrecognized policy key denies
  by name — an attached policy is never silently ignored.
- Schema: `policies` table (migration `20260718190145`) with `UNIQUE NULLS NOT DISTINCT
  (org_id, project_id, key)` — plain UNIQUE would let duplicate org-wide (NULL-project) rows
  through; `project_id` FK deferred to T3.2 with the projects table.
- Wired into the composition root (`main.go`) and the integration world; denials carry the
  E3 grammar (`policy:<key> <reason>`).
