## Goal

The full org governance surface live: orgs CRUD, members, the QA-8 invite
lifecycle, and org API keys — every state change on the events spine.

## Summary

Incl. invite 7-day expiry, dedupe (UNIQUE(org_id,email) WHERE pending), wrong-account
acceptance blocked, seat overage 402 with confirm=true.

## Acceptance criteria

- [x] QA scenario 8 (invite lifecycle) green: expire at 7d (computed, no cron); renew
      notifies inviter (spine event); accept from wrong email blocked (403); already-used
      → "sign in" path (409 with that remediation).
- [x] Seats per plan (Free 3 / Pro 5 / Business 20); invite past the allowance → 402 with
      `overage_price_cents: 700`; `?confirm=true` proceeds (catalog contract).
- [x] ≥1-owner enforced by DB trigger; demote/remove last owner → 409 naming the rule.
- [x] G6 removal semantics: sessions + personal tokens revoked immediately; owned
      resources flagged (empty until ownable resources exist), never silently reassigned.
- [x] Org API keys (G8): reveal-once, hash-stored, `api_keys.manage`-gated, authenticate
      as bearers.

## Outcome

- Migration `20260718192530`: orgs grow slug (unique, immutable — no code path writes it
  after create) + home_region + plan + deletion_scheduled_at; `subscriptions` row (inert,
  E11 attaches); `invites` with partial-unique pending dedupe; ≥1-owner trigger that steps
  aside during org CASCADE.
- Org creation is ONE transaction (org + subscription + owner membership), closing T2.3's
  recorded promise; slug derived by `Slugify` (`[a-z0-9-]{3,32}`), collision → 409.
- Invite ids are capability URLs (`inv_` + 16 bytes entropy); expiry computed from
  expires_at; A6 public view masks the email and explains the role by consequences
  (Developer's line is the frame's copy; other roles are matrix-faithful derivations —
  S9 candidate).
- Non-members get 404 (not 403) on org reads — org ids are not probeable.
- Spec deltas (S-process, recorded): `confirm` query param added to createInvite — the
  x-error-catalog already ratified "proceeds only on explicit confirm=true" but the op
  omitted the parameter.
- Findings: (1) org-key principals have no membership row, so RBAC denies them beyond
  authentication — the G8 scope model for org keys needs an owner decision; (2) a distinct
  display prefix for org keys (vs stp_) is an S-process candidate; (3) T2.5's carried
  finding — user-scoped events (login/tokens) still need an org-less spine decision.
