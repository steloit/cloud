## Goal

Users, sessions, password auth (argon2id)

## Summary

Defines the `users` table (spec gap: absent from models.md — define it first).

## Acceptance criteria

- [ ] signup/signin/logout work; sessions stored server-side.

## Outcome

Delivered 2026-07-18. **Spec gap filled:** users + sessions defined in models.md (prefixed
ids per x-conventions — usr_/ses_ text pks, not raw UUIDs; lower(email) unique; token_hash
sha256, raw never stored; no soft-delete/verification fields — not in the contract).
**Stack:** golang-migrate (real-clock timestamped versions via the migrate CLI + a
`migrate-new` Makefile target — founder-directed convention), sqlc+pgx store, argon2id
(PHC format, OWASP defaults, stored-parameter verify, constant-time compare, timing-equalized
unknown-email path), server-side sessions (HttpOnly/SameSite=Lax/Secure-configurable,
30d TTL, rotation-per-login, logout revocation + cookie clear), fixed-window login rate
limiting (injected, in-process — single-instance alpha). **Strict server:** the generated
interface is scoped by include-operation-ids (grows per task; nothing generated goes
unimplemented) — signup/login/logout/getSession implemented; cookies flow through a
context carrier applied by the strict middleware; every failure maps to a problem-catalog
constructor. **Tests:** unit (password/session/ratelimit/problem) + full-stack
testcontainers suite (signup w/ DB-state asserts incl. hash-only token storage · dup-email
409 · weak-password 422 · login + rotation · no-disclosure failed-login byte-equality ·
session current/unauthorized · expiry · logout revocation) — skips without a local
container runtime, enforced in CI. **Contract findings filed for the next founder bundle:**
the error catalog has no 401 class (invalid credentials/no-session map to 403
permission_denied interim) and signup's 409 duplicate-email response is absent from the
contract — both need S-process entries.
