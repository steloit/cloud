## Goal

The contract's auth section flows into generated code on every client: the §17 Go generation pipeline exists (server + Go client), and `services/api` is born as the composition-root skeleton the E2 tasks fill.

## Why

Contract-first only means something once drift *fails a build*. S1 amended the yaml; this task makes the yaml the single source every language generates from — the birth of the Go side of `make gen`.

## Read first

- `docs/architecture.md` §15 (repo layout the skeleton instantiates) + §17 (the one `make gen` pipeline, drift fails CI)
- `docs/product/08-api/openapi.yaml` — the contract (S1 auth section already present)
- Don't read: console feature code; frames.

## Approach

1. `services/api`: Go module (`go 1.26`), `cmd/api/main.go` minimal boot (slog JSON, `/healthz`; handlers wire per-module as E2/E3 tasks land — the §15 composition root, not a stub of everything).
2. oapi-codegen v2.8.0 configs: strict std-http server + types → `services/api/internal/httpapi/gen/`; types + client → `packages/contracts/go/` (its own module; imported by CLI + cell-agent later).
3. Root `Makefile`: `gen` = `gen-go` (both Go outputs) + `gen-ts` (copy yaml → console, `pnpm gen:api`). Generated code committed; CI regenerates and fails on diff (§16).
4. CI: `go` job — `make gen-go`, `git diff --exit-code`, build + vet both modules.
5. Typename collisions (schema `Org` vs param `org`) resolved via `x-go-name` on the five shared parameters — codegen metadata, zero wire impact (noted here because openapi.yaml edits otherwise route via S-process).

## Edge cases

- OpenAPI 3.1 vs oapi-codegen: probed before building — v2.8.0 parses this contract cleanly (the only failure was the typename collision). If a future contract construct breaks generation, that's a finding, not a silent workaround.
- `@v2.8.0` pinned in the Makefile — generator upgrades are reviewed diffs of generated code.

## Security & performance

None beyond pack rules; no handlers exist yet. The strict-server interface guarantees handler↔contract conformance by construction when modules implement it (§16 contract-test layer 3).

## Acceptance criteria

- [ ] WHEN `make gen-go` runs twice THEN the tree is identical (drift check green)
- [ ] WHEN both Go modules build + vet THEN they pass with zero hand-written API types
- [ ] WHEN the console client regenerates (`gen-ts`) THEN it is unchanged apart from the x-go-name-annotated yaml copy (extensions don't affect TS output)
- [ ] CI enforces gen-drift + build + vet on every PR

## Validation

`verify:` block; PR evidence: generation output, drift check, both builds, console still green.

## Common mistakes

- Editing generated files (they carry DO NOT EDIT; drift check catches it).
- Hand-writing a type the generator owns (14-development rule).
- Wiring the full strict server into main before any module implements it — main stays minimal until T2.1+.
