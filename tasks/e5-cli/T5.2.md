## Goal

CLI auth (device flow or token paste)

## Summary

**AC:** login/logout; token stored in OS keychain; acts-as-user semantics.

## Acceptance criteria

- [x] Token paste flow: `steloit auth login` (--token flag, piped stdin, or interactive
      paste) — the token is VERIFIED against `/v1/auth/session` before storage; rejected
      tokens exit 3 and are never stored; config lands 0600.
- [x] Reveal-once holds in the terminal: no command ever prints a stored token back
      (asserted in tests); logout forgets locally and names the server-side revoke path.
- [x] `steloit connect verify` renders A9's moment with the account identity; exit 3
      when unconnected or stale.

## Outcome

- The CLI speaks through the GENERATED core (`packages/contracts/go`,
  sdk.md's pattern) with a bearer request editor — no hand-written HTTP paths.
- Device flow deferred (the stub offered "device flow or token paste"); paste covers the
  alpha and the seam (whoami/apiClient) is where device flow slots in.
- `--api` / `STELOIT_API_URL` point the CLI at any deployment (dev, partner cells).
