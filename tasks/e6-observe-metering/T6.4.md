## Goal

Events SSE endpoint hardened (the spine)

## Summary

Drives CLI -f now; console toasts/bell/status pills later (state.md: SSE-primary, poll-fallback).

## Acceptance criteria

- [x] reconnect/cursor-resume tested three ways: explicit ?cursor= (T2.5), the browser's
      native Last-Event-ID header (added here — EventSource's own reconnect channel), and
      the precedence between them; a dropped stream comes back via the `retry:` hint.

## Outcome

- The endpoint honored only ?cursor= (the CLI channel); a comment CLAIMED Last-Event-ID
  support the code didn't have. Closed: the header is read when no query cursor is
  present, decoded by the same opaque codec, so **native EventSource resumes losslessly**
  — this is what the console's toasts/bell/status pills (state.md SSE-primary) will use.
- Every stream opens with `retry: 2000` (state.md's 2s SSE-primary posture) so a dropped
  connection reconnects fast; the poll-fallback (2s→10s) is the console's client policy
  over the same rows.
- Resume precedence (query cursor > header) and the header path are unit-tested; the full
  reconnect (replay → live → Last-Event-ID resume + retry hint) is integration-tested.
