## Goal

Metering store + rollup job (quota_usage)

## Summary

`quota_usage(org, meter, period)` with `idx(org_id, period)`.

## Acceptance criteria

- [x] rollups idempotent: a pure recomputation upserted over the previous value —
      rerun yields the identical row (integration-asserted, no accumulation); a later
      rollup with new raw edges recomputes correctly upward.
- [x] raw events retained: the rollup only READS usage_events (append-only since T3.7);
      the row count is asserted untouched after rollups.

## Outcome

- `quota_usage(org_id, meter, period)` per models.md with `rate_cents` (Σ seconds ×
  monthly rate) so billing derives charges without re-reading raw events.
- `Emitter.Rollup(org, period, now)`: span pairing (close↔latest open per service),
  still-open spans accrue to min(now, period end), period-clamped both sides.
- Scheduling: River (architecture §5) invokes Rollup periodically when internal jobs
  land; until then billing reads and tests invoke it directly — recorded, not silent.
