## Goal

Add the intent surface to `docs/product/08-api/openapi.yaml` via the S-process: an `intent` field on `ServiceShapeInput`/`Service`/`Estimate` lines (the grouping key stamped by the Composer at creation — ADR-039 §4c mechanism), and a catalog read surface listing intents with their named resolutions and semantic contracts (ADR-040 plane 1/2 bridge).

## Summary

The 2026-07-18 consistency audit found no owner for the ratified intent mechanism. Additive, `/v1`-compatible. Unblocks the intent-catalog create canvas (E8-S3), the Composer (T13.7), and the CLI intent door (`steloit add <intent>`, T5.3). Clients regenerated after the yaml change (the P3 migration establishes the drift-free baseline).

## Outcome

Ratified 2026-07-18 (founder, S-process). openapi.yaml (both copies) gains the `Intent` enum
(app·database·jobs·search·vector·cache·storage·ai), optional `intent` on ServiceShapeInput /
Service / Estimate lines / Binding (server-defaulted by product), and `GET /catalog` —
CatalogIntent with title + one-line semantic contract + named resolutions (service- or
Binding-backed, from_cents; never backend dropdowns). models.md: services.intent column +
enum registry entry. Clients regenerated drift-free; console typecheck/lint/tests green.
Unblocks E8-S3 (intent canvas), T13.7 (Composer), T5.3 (`steloit add <intent>`).
