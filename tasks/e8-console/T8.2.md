## Goal

The state.md realtime contract in the console: SSE-primary on the env event
spine, poll fallback 2s→10s, cursor resume — driving toasts, the bell badge,
and status-pill flips; provisioning entities poll independently and SURVIVE
drawer close (U5).

## Read first

- docs/product/10-state-management/state.md — the contract verbatim (SSE on
  /events; poll 2s→backoff 10s; stream drives toasts/bell/pills/markers; async
  drawers poll independently and survive close).
- openapi.yaml `listEvents` (`/envs/{env}/events`, x-streamable, cursor param) —
  EventSource sends `Accept: text/event-stream` natively; the same endpoint's
  JSON list is the poll fallback (one endpoint, two modes — T6.4's server).
- apps/console/AGENTS.md — canon mode must stay green: MSW can't stream, so the
  fallback path IS canon mode's path (by construction, not a special case).

## Approach

1. `lib/realtime.ts`: `createRealtimeChannel` — SSE-primary with injectable
   EventSource + timers (testable); on error → poll via the generated listEvents
   at 2s backing off to 10s; cursor resume on both paths; periodic SSE retry.
2. `lib/watch.ts`: the U5 registry — a zustand set of watched provisioning
   entities + a HEADLESS `ProvisioningWatcher` mounted in the shell: per watched
   id a query polls 2s→10s until status leaves `provisioning`, then toast +
   invalidate + unwatch. The drawer only registers; closing it changes nothing.
3. Shell wiring: active env (?env=) → one channel; events fan out to sonner
   toasts (deploy/lifecycle), query invalidation (services/deployments/events —
   the status pills flip), and the bell badge bump.
4. Canon mode: MSW serves the JSON list; EventSource fails → fallback engages —
   both modes green with zero canon-specific code.

## Acceptance criteria

- [x] U5-style async drawers keep verifying after close — the survival property
  is STRUCTURAL (module-scoped registry; the shell owns the polling; drawers
  only register) and the registry semantics are pinned by tests/watch.test.ts.
  HONESTY: the ProvisioningWatcher COMPONENT (toast-on-ready, invalidation,
  cadence) has no render-test — node-env vitest, no DOM lib; recorded as a
  ledger gap to close when the console gains a DOM test environment.
- [x] SSE failure degrades to polling at 2s→10s and recovers to SSE (engine
  test with injected fakes).
- [x] Canon mode stays green (fallback is the canon path by construction).

## Common mistakes

- Poll state living in the drawer component (dies on close — the AC).
- A canon-only code path (the fallback must BE the degraded path).
- Optimistic status flips — pills flip on server truth (event/poll), never on
  the mutation response.

## Outcome

`lib/realtime.ts` is the state.md contract as a testable engine:
`createRealtimeChannel` — SSE-primary on `/envs/{env}/events` (EventSource sends
`Accept: text/event-stream` natively; T6.4's Streamer claims it pre-strict),
hard-failure degradation to polling the SAME endpoint at 2s→4s→8s→10s (capped),
cursor resume on both paths, and a 30s SSE recovery loop — every seam
(EventSource, timers, fetch) injectable, proven by a virtual-deadline clock in
`tests/realtime.test.ts` (degrade, backoff sequence, cursor pass-through,
recovery-to-SSE, teardown, malformed-frame tolerance).

`lib/watch.ts` is the U5 guarantee: a module-scoped registry a drawer only
REGISTERS into; the shell's headless `ProvisioningWatcher` owns the polling
(per-entity 2s→10s) until status leaves `provisioning`, then toasts on server
truth, predicate-invalidates the hey-api structured keys (pills flip), and
unwatches. Structurally independent of any drawer lifecycle — pinned by
`tests/watch.test.ts`.

`RealtimeMount` (org shell): one channel for the active env — deploy/lifecycle
toasts, list invalidation (services/deployments/events), and the bell badge
bump (`liveUnread` on the notifications store; `markAllRead` clears it).
Canon mode green by construction: MSW can't stream → the fallback IS the canon
path; all 26 console tests + typecheck + build pass.

Honest scope notes: no live create-service mutation exists yet in the console
(that E8 slice wires `watchProvisioning` at its creation site); pre-existing
`biome` lint failures on main (command-palette/overlay/type-blocks) are not
from this change and are recorded as a finding.

**Review round (arch + QA — both NOT-APPROVED first pass; all fixed):** both
found the same blocker — `degrade()` early-returned when already polling, so a
FAILED 30s SSE recovery attempt (canon mode's steady state, since MSW cannot
stream) left the channel permanently dead; fixed with an idempotent degrade +
polling-continues-through-recovery-attempts, and the exact regression test both
demanded. Also fixed: the SSE URL now threads VITE_API_URL (SSE-primary was
structurally unreachable cross-origin — H2); the poll path PRIMES its first
page (history is never replayed as live toasts) with a bounded id-dedup against
cursor-ignoring servers (M1); late delivery after close() is dropped (M4);
invalidation coalesces per delivered batch (P1); the bell panel now clears
liveUnread on open (the stranded-badge defect — clearLive had no caller); the
watcher terminates on hard error and shares the channel's attempt-doubling
backoff; the accidental second RealtimeMount in the skeleton branch is gone.
Ledger: notification-worthy bell filtering rides the N1 slice; component-level
watcher/mount tests need a DOM test env; pre-existing console lint failures.

**Second review round:** both reviewers caught that the P2 bell-clear hunk was
LOST on the first fix commit (the `useEffect` import landed but not the effect —
a stale-claim + dangling-import defect that would fail the task's own lint
gate). Now genuinely wired: `BellPanel` calls `clearLive()` in a mount effect.
Two real MEDIUM races also fixed: (1) `pollTimer===null` was a false "not
polling" proxy mid-fetch, so a `degrade()` in that window spawned an orphan
poll loop that survived recovery — replaced with an explicit `polling` flag
gating every schedule/continuation (regression test: a mid-flight degrade
leaves exactly one loop); (2) prime now guards on `cursor === undefined` too,
so a poll page that follows SSE delivery (genuinely new rows) is delivered, not
swallowed (regression test). The stale "EventSource retries itself" comment is
replaced with the accurate design note. 29/29 tests; typecheck, build, and
scoped `biome check` on every touched file all clean.
