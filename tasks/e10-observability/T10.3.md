## Goal

An event on the spine fans out to the routes a principal chose — in-app bell,
email, org webhook — with a webhook test that returns its result inline.

## Why

The console's bell (U8), per-user notification prefs, and org webhooks all sit on
one routing matrix: the events spine is the single source, and each route is a
projection of it. Notifications endpoints block 8 console surfaces (ledger §9).

## Read first

- docs/product/08-api/openapi.yaml — `/me/notifications`, `/me/notifications:read`,
  `/me/notification-prefs`, `/orgs/{org}/webhooks`, `/webhooks/{wbh}:test`;
  schemas NotificationList, NotificationPrefs, WebhookInput, Webhook,
  WebhookCreated, WebhookList (the exact wire shapes — never hand-write types).
- services/api/internal/mailer/dispatcher.go — the outbox pattern to imitate:
  a durable delivery ledger, claim-before-send, pending→sent/failed state.
- services/api/internal/events/{events.go,hub.go,read.go} — the spine an event
  is written to (T2.5) and the SSE hub the bell reads live; routing hangs off the
  same Dispatch seam email already uses.
- services/api/internal/identity/personal_tokens.go — reveal-once secret pattern
  (hash-at-rest, plaintext returned once) to reuse for the webhook signing secret.
- docs/product/09-data-models/models.md — notification / webhook rows.
- **Don't read:** the frame gallery HTML end-to-end (search `U8`/`P6`); mailer
  internals beyond the Dispatch/outbox seam.

## Approach

1. **Migration** `notifications` (id `ntf_…`, user_id, kind, title, body, link,
   read bool, created_at), `notification_prefs` (user_id PK, channels jsonb,
   quiet_hours jsonb), `webhooks` (id `wbh_…`, org_id, url, events text[],
   status active|disabled, secret_hash, created_at). FKs to users/orgs.
2. **`internal/notify` package** — `Router.Route(ctx, event)` reads the recipient
   set for the event, consults per-user prefs + org webhooks, and fans out:
   bell → insert a notification row; email → the existing `mailer.Dispatch`;
   webhook → enqueue a webhook delivery. Prefs gate email/inapp only; routing
   never suppresses a recording (glossary law — prefs are routing, not audit).
3. **Webhook delivery** — a delivery worker POSTs the event JSON with an
   `X-Steloit-Signature` HMAC-SHA256 over the body keyed by the webhook secret,
   through the same durable-ledger + claim-before-send shape as email
   (pending→sent/failed, bounded retry). Reuse, don't fork, the outbox pattern.
4. **`createWebhook`** mints the signing secret, stores only its hash, returns the
   plaintext **once** (WebhookCreated) — the personal-token contract.
5. **`testWebhook`** delivers a synthetic event **synchronously** and returns
   `{delivered, status_code, duration_ms}` inline — never a dead end (U8).
6. **HTTP handlers** — `notifications_http.go` (list/mark-read/prefs, `/me`, self
   only) under the session principal; `webhooks_http.go` (list/create/test) under
   `governance` on the org (`webhooks.*` permissions, requireOrg).
7. Add the seven operationIds to `oapi-server.cfg.yaml` `include-operation-ids`
   (staged conformance — nothing generated goes unimplemented) and `make gen`.

## Edge cases

- Mark-read with foreign notification ids → no-op on rows the user doesn't own
  (WHERE user_id scopes it); never 404-leaks another user's id space.
- Empty prefs row → defaults (bell on, email on, no quiet hours); a missing row
  is never a route-suppression.
- Webhook to a disabled webhook or an unreachable URL → delivery marked failed,
  bounded retry, never blocks the routing of the other routes.
- `testWebhook` on a `disabled` webhook still delivers (it's a test) but reports
  the real result; on a missing wbh → 404.
- Quiet hours defer **email** routing only — bell + webhook + the recording are
  unaffected (routing-only law).

## Security & performance

- Webhook secret: 256-bit, hashed at rest, plaintext returned once; the signature
  lets the receiver verify authenticity — never send the secret in the payload.
- SSRF: a webhook URL is attacker-controllable. Reject non-https and
  private/loopback/link-local hosts at create time and re-check at delivery.
- Test delivery is synchronous but time-bounded (short timeout) so it can't hang
  the request; the async path carries the bounded-retry.
- List endpoints paginate by cursor (api-conventions) — bell history grows.

## Acceptance criteria

- [x] WHEN an event routes THEN it fans to exactly the chosen routes
  (bell|email|webhook), each a projection of the same spine event.
- [x] WHEN a user has email-off prefs THEN email is suppressed but the bell row
  and the recording still happen (routing ≠ recording).
- [x] WHEN a webhook is created THEN the signing secret is returned once and is
  stored only as a recoverable envelope (sealed, not plaintext).
- [x] WHEN a webhook delivers THEN the body carries a verifiable
  `X-Steloit-Signature` HMAC and delivery state is durable (pending→sent/failed).
- [x] WHEN `testWebhook` is called THEN it returns `{delivered, status_code,
  duration_ms}` inline.
- [x] WHEN mark-read includes ids the caller doesn't own THEN those rows are
  untouched and no id-space leaks.

## Common mistakes

- Suppressing a **recording** because a pref is off — prefs route, they never gag
  the audit/spine (glossary law; NotificationPrefs description says so verbatim).
- Forking a second outbox for webhooks instead of reusing the email delivery
  ledger's claim-before-send shape.
- Storing the webhook secret in cleartext or returning it on every GET (it is
  reveal-once, like a personal token).
- Skipping SSRF validation on the webhook URL.

## Outcome

`internal/notify` is the routing matrix: one spine event projected onto the
routes a principal chose. Migration adds `notifications` (the bell — a per-user
projection), `notification_prefs` (channels + quiet hours), `webhooks` (org
outbound, envelope-sealed signing secret), and `webhook_deliveries` (a durable
outbox, the same claim-before-send shape as the email ledger).

**Bell + prefs** (`/me/notifications`, `:read`, `/me/notification-prefs`):
per-user, self-scoped — a mark-read with ids the caller doesn't own leaves those
rows untouched and never 404-leaks. `Router.Notify` fans a projection to org
members' bells + email, each **gated by that member's prefs**; a pref-off
suppresses the *route*, never the spine recording (glossary law — verified: email
off ⇒ bell present, email sender not called). Keyset pagination on
`(created_at, id)` because `ids.New` is random hex, not time-sortable.

**Webhooks** (`/orgs/{org}/webhooks` create/list, `/webhooks/{wbh}:test`):
create mints a signing secret returned **once** and stored as a **recoverable
envelope** (`secrets.Seal`, AAD-bound) — a webhook must re-sign every delivery,
so unlike a token it is sealed, not hashed. Delivery signs the body with
`X-Steloit-Signature` HMAC-SHA256, runs off a durable outbox (bounded retry,
idempotent per `(webhook, event)`), and is SSRF-guarded (https + routable host,
re-checked at delivery). The outbox **never backfills events predating the
webhook** (`e.at >= w.created_at`). `testWebhook` delivers synchronously and
returns `{delivered, status_code, duration_ms}` inline.

Verified against real Postgres: prefs-gated bell routing with email suppressed,
owner-scoped mark-read, a signed webhook delivery whose HMAC verifies with the
reveal-once secret, idempotent re-scan (no double-deliver), and the inline test
result; plus unit tests for the SSRF cases and quiet-hours windows.

**Findings (follow-ups filed — [spec-change-proposals.md](../../docs/product/claudedocs/spec-change-proposals.md)):**
(1) `testWebhook`'s `/webhooks/{wbh}:test` path is unroutable by Go's stdlib mux
(a `:verb` on a wildcard) — handled with a pre-strict manual route (the SSE

has no production caller yet — the webhook route is wired in `main`, but firing
the bell needs the P6/U8 frame-verbatim titles the router must not invent. (3)
Webhooks reuse `api_keys.manage`; a dedicated `webhooks.manage` is proposed if
the product wants it distinct.
