## Goal

Email service integration (provider; event→template map): provider integrated;
nothing but Event kinds sends mail.

## Summary

Buy, don't build (comms infra is a never-build). Resend behind a provider
interface, async via the events/outbox pipeline, versioned provider-agnostic
templates (ADR-0009).

## Outcome

Email is a governed, Event-driven capability (ADR-0009). The `mailer` package
fronts email behind a `Provider` interface — **Resend** is the implementation
(`resend.go`, a thin HTTP adapter), with a **Noop** provider selected when no
`RESEND_API_KEY` is configured so every environment runs without credentials.
Templates are **versioned and provider-agnostic** (`Template.Version`, rendered
to `{subject, html, text}` before the provider boundary).

The **only** thing that sends mail is the `Dispatcher`, whose single input is a
spine `store.Event`: a `registry()` maps event actions → templates + recipient
resolvers (the event→template map; `invite.created` → org-invite is the V1
wiring), and an event with no rule sends nothing. Delivery is **durable and
idempotent**: `ProcessPending` scans the spine for mail-triggering events with
no `email_deliveries` row (the spine + ledger ARE the outbox — nothing lost on
restart), claims each (event, recipient) before sending (the idempotency gate,
UNIQUE-backed), and records the outcome; `RunOutbox` polls it. A `MailDirectory`
adapter resolves recipients from the identity store, keeping `mailer` free of
domain knowledge. Verified end-to-end against real Postgres (invite → outbox →
spy provider → recorded delivery → idempotent re-drain).

Deferred (finalizers, not blockers): the live Resend send path needs the real
`RESEND_API_KEY` (the adapter is structurally complete, Noop-substituted until
then); a River-backed retry/backoff worker replaces the polling loop later (the
idempotent ledger makes that swap free). More templates (password reset T7.2,
invite-to-existing-user) land with their features — each is one `registry` rule.
