## Goal

The bell rings for what actually needs a person: notification-worthy spine events
project into per-user bell rows with frame-verbatim titles, so the unread count
the console derives equals the list it shows.

## Why

S4 named the notifications family the highest-frequency gap (8 blocked surfaces).
T10.3 built the store, the routing matrix and webhook delivery — but nothing
rings the bell in a running system, and the console bumps the badge on **every**
spine event, so the badge and the list disagree today
(`spec-change-proposals.md:204` and `:225`, which names the N1 slice as owner).
This task is that slice.

## Approach

1. **Amend the contract first.** `NotificationList.data[].kind` is a bare string
   (`openapi.yaml:1984`). Pin it to the frame vocabulary from P6/N2:
   `[alert, proposal, approval, deploy, lifecycle]`. This *adopts* 00-sources, it
   does not invent — but it narrows a shipped field, so request founder sign-off
   in the PR (§1a). Then Trap T2's order: `make gen-go` → `make gen-ts` →
   commit every generated file.
2. **`notify.Classify(action string) (kind string, title string, ok bool)`** — a
   pure, table-driven map from spine `action` → frame type + title template.
   `ok=false` means **not notification-worthy** and is the common case: the
   default is silence. Titles come from N1/N2 verbatim; a spine action with no
   frame row returns `false` rather than a guessed title.
3. **Bell = spine projection, not ad-hoc pushes.** Add `ListPendingBellEvents`
   to `db/queries/notify.sql`, mirroring `ListPendingWebhookEvents`: scan
   `events` forward, LEFT JOIN `notifications` on `event_id` to skip projected
   rows, bounded `LIMIT`, `ORDER BY e.at ASC`. Do **not** add a second
   notifications truth or a 39-call-site fan-out (pack law: one pipeline, views
   over it).
4. **`Router.ProcessBell(ctx) (int, error)`** — drain one batch: for each event
   `Classify` it, skip when `!ok`, else call the existing `Notify` with
   **`EventID` set**, so `InsertNotification`'s `ON CONFLICT DO NOTHING` makes a
   re-scan idempotent. Reuse `Notify`'s per-member prefs/quiet-hours fan; do not
   fork it. Run it from `cmd/api/main.go` beside `RunOutbox` (`main.go:230`).
5. **Fix the `unread` filter asymmetry.** `notify.sql:24`'s `IS NOT TRUE` makes
   `unread=false` identical to unset, so read-only rows cannot be requested.
   Make the predicate honor an explicit `false`. This is the query the console
   derives its count from — the contract already exposes the param
   (`openapi.yaml:956`), so this is a fix, not a surface change.
6. **Cover the `testWebhook` shim at the HTTP layer.** `webhooks_http.go:88-133`
   bypasses `contextMiddleware` and hand-rolls path parsing, principal lookup,
   token-scope and `authz.Require` — none of it is tested. Drive it through the
   real mux.
7. **File the deferrals** (§ Out of scope) as ledger rows in the same PR, and add
   the lesson to `contexts/events-spine.md`'s mistake bank.

## Edge cases

- **A spine event with no frame row** → `Classify` returns `false`; nothing is
  inserted. Silence is the default, and it is the case that keeps the badge
  honest.
- **Re-scan / restart** → same events re-classified, `ON CONFLICT DO NOTHING` on
  `(user_id, event_id)` absorbs them; no double-ring. Only true because step 4
  sets `EventID` — an omitted `EventID` silently disables the dedupe.
- **Quiet hours** → gate the **email route only**; the bell row is inserted
  regardless (routing ≠ recording; already held by
  `TestQuietHoursRouteOnlyNeverRecordOrFire`).
- **Zero unread** → N3: the pill is **absent, not `0`**, and the chrome dot is
  gone. A rendered `0 unread` is a defect against N3.
- **Backfill** → a member who joins an org later must not receive the org's
  entire history. Bound the scan the way the webhook path bounds it (`e.at >=`
  a watermark), and pin it with a test.
- **`markNotificationsRead` with foreign ids** → already owner-scoped and
  silent; the projection must not regress it.
- **Three `kind` vocabularies exist** — frames (`alert|proposal|approval|deploy|
  lifecycle`), the spine's own (`events.go:23`), and Go's current ad-hoc
  `billing|lifecycle|security`. The **frames win** (00-sources). `Classify` is
  the single translation point from spine action → frame kind.
- **`billing` has no P6 row.** `EmitQuotaWarning` (`quota_warning.go:29`) sends
  `kind: "billing"`, which is not in the frame vocabulary and has no routing-matrix
  row, yet `flows.md:19` requires the 80% bell. Do **not** invent a sixth type —
  map it to the nearest frame row and record the gap (§ Out of scope).

## Security & performance

- The scan is bounded (`LIMIT`, ascending by `at`) and idempotent; it must never
  hold a transaction open across delivery.
- Per-member fan-out is O(members) per notification-worthy event — keep the
  classification pure and allocation-free so a large org does not stall the loop.
- `testWebhook`'s shim authorizes against the **webhook's own org**
  (`webhooks_http.go:121`), not a path org — the test must pin that a member of
  *another* org gets denied, and that a read-only token is refused.
- No new error class (Trap T3) — reuse the existing catalog.

## Acceptance criteria

- [ ] WHEN a spine event has no frame-sourced classification THEN no notification
      row is created — silence is the default.
- [ ] WHEN a notification-worthy event is projected THEN every org member's bell
      row carries a **frame-verbatim** title and a `kind` from
      `[alert, proposal, approval, deploy, lifecycle]`.
- [ ] WHEN the projection re-scans the same events THEN no duplicate row is
      created (`EventID` set + partial unique index).
- [ ] WHEN the console derives its badge from `?unread=true` THEN that count
      equals the unread rows `listNotifications` returns — the count is a
      projection of the spine through `Classify`, never of raw spine events.
- [ ] WHEN `unread=false` is passed explicitly THEN only read rows are returned
      (today it is indistinguishable from unset).
- [ ] WHEN `POST /v1/webhooks/{wbh}:test` is called by a principal lacking
      `api_keys.manage` on the **webhook's** org, or by a non-full-scope token,
      THEN it is denied — driven through the real mux, not `router.Test()`.
- [ ] WHEN quiet hours are active THEN the bell row is still written and only the
      email route is suppressed.

## Validation

Every `verify:` command passes, output pasted in the PR. Each Go entry greps for
an explicit `--- PASS` line **because `go test -run` exits 0 when no test
matches** — a bare `-run` would pass before the work exists and satisfy nothing.
PR evidence: the projection test showing a non-worthy event ringing nothing while
a worthy one rings every member; a re-scan producing no duplicate; and the
denied-`testWebhook` HTTP responses.

## Common mistakes

- **Inventing a title.** If a frame has no row for an action, `Classify` returns
  `false`. A plausible-sounding title is the exact failure `:204` warned about.
- **Adding an `unread_count` field or a count endpoint.** The design spec makes
  the count derived (`:410`); serving it creates a second truth that can drift.
- **Omitting `EventID`** when calling `Notify` from the projection — the unique
  index is partial, so the dedupe silently does nothing and restarts double-ring.
- **Forking a second scanner** instead of mirroring `ListPendingWebhookEvents`.
- **Rendering `0 unread`** instead of omitting the pill (N3).

## Out of scope

Each is a ledger row filed in this PR, not silent:

- `deleteWebhook` / `PATCH /webhooks/{wbh}` — **absent from the contract
  entirely**; adding an operation is a §8 proposal first, never inline (Trap T2).
- `needs-action` grouping (N1/N2) — depends on **approval threads**, proposed in
  §2c but never specced.
- SSE live delivery for `/me/notifications` — `x-streamable: true`
  (`openapi.yaml:955`) but no streamer, and `events.Hub` is org-keyed
  (`hub.go:15`), so a per-user stream needs a new subscription key. Own task.
- P6's **per-type** routing matrix and its `Mobile push` column —
  `NotificationPrefs.channels` is `{email, inapp}` only; "Alerts · production is
  always in-app, not a preference" is unexpressible in the current shape.
- `billing` type's missing P6 row (see Edge cases).
- `Urgent` source + the email-off-override ruling — E7/auth owns (`:239`).
- Webhook-per-org cap, delivery lease for >1 replica — T10.3 review items.
- `models.md` documents neither `notifications` nor `webhooks` — S-process item.
