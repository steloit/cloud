## Goal

The bell rings for what actually needs a person: notification-worthy spine events
project exactly once into per-user **in-app** bell rows with frame-sourced titles,
so the rows a console badge counts are a projection of the spine, not of raw
events.

## Why

S4 named the notifications family the highest-frequency gap. T10.3 built the
store and the routing matrix, but nothing rings the bell in a running system
(`spec-change-proposals.md:204`), and the console bumps the badge on **every**
spine event (`:225`, which names the N1 slice as owner). This is the server-side
in-app half of that slice. Five concerns were split out across three review
rounds (§ Out of scope), so this is deliberately narrower than the roadmap's
"notifications family" line — the title reflects the real deliverable.

## Approach

**In-app only. No contract change (`apis: []`), no email, no `Notify` change.**

1. **`notify.Classify(action string) (kind, title string, ok bool)`** — pure,
   table-driven: spine `action` → frame kind + title. `ok=false` means **not
   notification-worthy**, the common case; no frame row ⇒ `false`, never a
   guessed title. `ok=false` ⇒ both returns empty (no half-populated result).
   `TestClassify`'s table must carry **negative rows** — unknown action, empty
   string, a near-miss action — asserting `!ok && kind=="" && title==""`; a table
   of positives alone never exercises the branch that keeps the badge honest.
2. **Pin titles at both ends.** A golden table asserts `action → (kind, title)`
   by **exact equality** (pins the mapping), *and* each title's fragment is found
   in the gallery (pins provenance). Derive the search region **at test time** by
   scanning for the `<b>N1</b>` and `<b>N3</b>` markers — the N1/N2 region is
   `[N1, N3)`. Do **not** pin gallery line numbers: `00-sources/**` changes by
   human decision, and a one-line insert anywhere above 10444 would break every
   pin with no semantic cause. Region scoping is load-bearing: ` is ready` matches
   four places in the gallery, two of them outside N1/N2.
   **Guard the guard:** assert both markers were found and `n1 < n3` before using
   the region, plus a negative control — a fragment that exists only *outside*
   N1/N2 must NOT be found in it. A clamped -1 index would silently widen the
   region back to the whole 1.4 MB file and restore the false-pass step 2 forbids.
3. **A terminal ledger, not a timestamp watermark.** Migration `bell_scanned`
   (`event_id text PRIMARY KEY REFERENCES events(id), scanned_at timestamptz NOT
   NULL DEFAULT now()`) records **every scanned event, worthy or not** — the
   marker the webhook path gets from `webhook_deliveries` and the bell otherwise
   lacks. Seed it with every existing event id so first boot does not fan the
   whole spine, and no-backfill holds by construction. Add
   `CREATE INDEX events_at_id_idx ON events (at, id)`. **State the cost in the
   PR:** golang-migrate runs each file in one tx, so `CONCURRENTLY` is
   unavailable and the build takes a `SHARE` lock on the spine — report the
   `events` row count and the measured pause.
4. **`ListPendingBellEvents`** — pure anti-join, no time bound:
   `FROM events e LEFT JOIN bell_scanned bs ON bs.event_id = e.id
   WHERE bs.event_id IS NULL ORDER BY e.at, e.id LIMIT 100`. **Deliberately no
   `at >= floor` predicate:** `events.at` is tx-*start* time, so any floor
   permanently skips a long tx that commits late, and correctness must not rest
   on an unbounded "longest write tx" assumption. The anti-join is immune —
   an event simply has no ledger row until it is seen. The cost is that the scan
   walks from the oldest unscanned row; revisit only with measured evidence.
5. **`Router.ProcessBell(ctx) (int, error)`** — per event, in **one tx** on a
   `WithTx`-bound store: claim via `INSERT INTO bell_scanned … ON CONFLICT DO
   NOTHING RETURNING event_id` (no row ⇒ another replica owns it, skip);
   `Classify`; if worthy, list org members, and for each whose `prefsFor` has
   `inapp` on, `InsertNotification` with **`EventID` set**; commit. Treat
   `errors.Is(err, pgx.ErrNoRows)` from `InsertNotification` as a **benign
   dedupe**, not a failure — any *other* error must abort the tx, because a
   partial fan-out that commits is never retried.
   **`Notify` is not called and not modified**: it sends email inline, which this
   tx forbids, and its only other caller (`EmitQuotaWarning`) must not change.
   **The Router cannot currently begin a transaction** — it holds only `q Store`
   (`notify.go:44-52`), the `Store` interface has no `Begin` (`:26-35`), and
   `Queries.WithTx` needs a `pgx.Tx` from a pool the Router does not hold. Give it
   a tx source and **state the `NewRouter` signature change in the PR**
   (`main.go:229` constructs it). This fails at compile time, not silently.
   **The tx source must yield a `notify.Store`, not a concrete `*store.Queries`**
   (e.g. `txStore(ctx) (Store, commit, rollback, error)`) — otherwise AC8 has no
   injection point: `store.WithTx` returns a concrete type, and wrapping `r.q`
   only wraps the *pool*-bound store, never the tx-bound one the inserts run on.
   Getting this wrong is discovered after the test world is built, not before.
   Note `prefsFor` reads `r.q` (`notify.go:241`), not a passed store — either pass
   the tx-bound store to it or accept the prefs read on the pool (harmless: a
   stale pref costs one routing decision, never a lost recording). Say which.
   **One event's failure aborts only its own tx; the batch loop continues** to the
   next event. `bell_scanned` has no attempts column, so a permanently-failing
   event retries forever at one slot per tick — the dead-letter gap is filed.
6. **Wire it** in `cmd/api/main.go` beside `RunOutbox` (`:230`).
7. **File the deferrals** (§ Out of scope) as ledger rows, and bank the lessons
   in `contexts/events-spine.md`.

## Edge cases

- **A long run of non-worthy events** → each still gets a `bell_scanned` row, so
  the window cannot fill with un-clearable rows. This is why step 3 exists.
- **A tx that opens before a scan and commits after it** → invisible to any
  `at`-based watermark (`events.at` is tx-start). The ledger is immune: no row
  until seen. This is why step 4 has no floor.
- **Two replicas** → both may scan; `ON CONFLICT DO NOTHING` means exactly one
  fans out. The loser **blocks** on the speculative index entry until the winner's
  tx ends, so replicas serialize per batch. Accepted; a lease is the general fix.
- **Crash mid-fan-out** → the tx rolls back, the claim disappears with it, and a
  later run re-fans **every** member.
- **Member with `inapp` off** → no bell row (`notify.go:118`); AC4 respects it.
- **Late joiner** → no backfill. **Note:** this holds because the ledger row
  already exists, *not* because anything enforces it — see the reopen banner.
- **Quiet hours** → never gate the bell; they route email only.

## Security & performance

- No network call inside the tx — that is why email is out (§ Out of scope) and
  why the claim can be held in-tx at all.
- The anti-join without `events_at_id_idx` is a seq scan + sort of the whole
  spine every tick; with it, a bounded index range.
- Per-member fan-out is O(members) per worthy event — keep `Classify` pure.
- No new error class — `internal/platform/problem` mirrors `openapi.yaml`'s
  `x-error-catalog` exactly and is closed; no new endpoint, so no authz surface.

## Acceptance criteria

- [ ] WHEN a spine event has no frame-sourced classification THEN no bell row is
      created.
- [ ] WHEN such an event is scanned THEN it is still marked in `bell_scanned`,
      and a second run neither returns nor re-processes it.
- [ ] WHEN more than one full batch (>100) of consecutive non-worthy events
      precedes a worthy one THEN the worthy one still produces bell rows.
- [ ] WHEN a notification-worthy event is projected THEN every org member **whose
      in-app pref is on** gets exactly one bell row, and no opted-out member gets
      one.
- [ ] WHEN a title is produced THEN it equals its golden `action → title` entry
      AND its fragment is found inside the gallery's `[N1, N3)` region.
- [ ] WHEN `ProcessBell` runs twice over the same events THEN the second reports
      0 new rows and the row count is unchanged.
- [ ] WHEN two `ProcessBell` calls run concurrently over the same window THEN
      each worthy event fans out exactly once.
- [ ] WHEN a per-member insert fails mid-fan-out THEN **that event's** tx rolls
      back (claim included) and a later run notifies **all** members — no member is
      silently skipped, and the other events in the batch are unaffected.
- [ ] WHEN a member joins after events were projected THEN they receive no
      backfill AND existing members are not re-notified.
- [ ] WHEN the migration's seed runs against a spine that already has events THEN
      a subsequent `ProcessBell` projects **none** of them. This is the only
      irreversible failure in the task and it is invisible to CI — integration
      tests migrate an empty DB, so the seed is a no-op there and a wrong
      predicate would ship silently and mass-fan the whole history, once.

## Validation

Every `verify:` command passes, output pasted in the PR, plus the step-3 index
build measurement.

**Three things about the `verify:` block are load-bearing**, each learned from a
review round here. (1) Each Go entry asserts an explicit `--- PASS: <name> (` line
**and** the exit code: `go test -run` exits 0 when nothing matches,
while a bare `… | grep -q` returns *grep's* status and masks a post-PASS panic —
both guards are independently necessary. (2) The pattern ends at `(`, **not** `$`:
`-v` prints `--- PASS: TestX (0.00s)`, so a `$` anchor is red on a **passing**
test. A red-state probe cannot catch that — **prove the green state too**.
(3) The `internal/identity` entries need a **container runtime**;
`newWorld` calls `t.Skipf` without Docker and a skip prints no `--- PASS`, so the
entry correctly goes red. Never paste a skip as evidence.

AC8 needs a failure-injection seam (a `Store` wrapper failing the Nth insert);
name it in the PR.

## Common mistakes

- **Copying `ListPendingWebhookEvents`' predicate without its ledger.** That
  query is self-limiting because its filter is **in SQL** (`e.kind =
  ANY(w.events)`) and `webhook_deliveries` records a terminal row for the rest.
  `Classify` runs **in Go**, so without `bell_scanned` a non-worthy event leaves
  no row, permanently satisfies `WHERE … IS NULL`, and fills every later window —
  after one batch of silence the bell stops ringing forever.
- **Replacing that with an `at`-based cursor or floor.** `events.at` is tx
  **start** time, so a concurrent long tx commits *below* the mark and is skipped
  permanently. Timestamps order; they do not prove handling.
- **Assuming `email_deliveries` has a consumer.** It does not: the dispatcher
  scans *spine events by action* against a static three-template registry
  (`mailer/templates.go:104-124`), and nothing scans the table for `pending`.
  This is the third time in this task's review history that prior art was assumed
  to transplant without reading its scan predicate — read the consumer first.
- **Treating `pgx.ErrNoRows` from `InsertNotification` as a failure** — it is the
  dedupe succeeding, and aborting on it turns the guard into a retry loop.
- **Inventing a title**, or asserting one by substring over the whole gallery.

## Out of scope

carved out across three review rounds — this started as four concerns in one.

  in the tx), and there is **no pending-row consumer** for `email_deliveries`;
  building one is real work (an ad-hoc/no-template send path, since the table
  requires `template`/`provider` NOT NULL and `Notify` carries free-text title
  and body). Also blocked on wiring `.WithEmail(...)` in `main.go:229`, which is
  dead today. Own task.
- **The `kind` enum** `[alert, proposal, approval, deploy, lifecycle]` — a ledger
  proposal, not inline: shipped rows already carry `billing`
  (`quota_warning.go:29`) and `security`, so pinning it would make
  `listNotifications` emit contract-invalid values.

- **`testWebhook` HTTP coverage** — own task; carries a live 403/404 leak (filed).
- **The console badge half** — `bumpLive()` counts every spine event
  (`apps/console/src/app/shell/realtime-mount.tsx:57`; `ctx.tsx:57` is the
  consumer). Needs console lint/test gates — biome's `noExportsInTest` fails CI on any
  `export` in a `*.test.ts`. Own task, with `:225`'s
  offline affordance.
- **Bell ordering by event time** — `notifications` orders by `created_at`
  (projection time), so a post-downtime backlog lands out of order. Fixing it is
  a second migration **plus** `ListNotifications`' ORDER BY *and* its keyset
  cursor (`notify.sql:26-29`) — an observable pagination change. Own task, and it
  should land a pagination test *first*: that query has none today.
- `deleteWebhook` / `PATCH /webhooks/{wbh}` — absent from the contract; adding
  an operation is a ledger proposal first, never an inline decision.
- `needs-action` grouping — depends on **approval threads**, never specced.
- SSE for `/me/notifications` — `x-streamable` but no streamer; `events.Hub` is
  org-keyed (`hub.go:15`).
- P6's per-type matrix and `Mobile push` — unexpressible in `channels{email,inapp}`.

The bell projects the spine. `notify.Classify` maps a spine action to a
frame-sourced kind + title; `ProcessBell` drains one batch per tick, claiming
each event in the `bell_scanned` **terminal ledger** and fanning bell rows to
every org member whose in-app pref is on. Wired in `main.go` beside `RunOutbox`.

**The classification table has one row, and that is the honest state.** N1 shows
seven rows but six describe planes that do not exist (approval threads, E13
proposals, E12 alert rules, queue runtime, E1 service-ready, cert management).
Only `deploy.created` both exists and has frame copy. Each gated row names the
roadmap item that enables it, so the table grows by evidence — padding it would
mean inventing titles.

**Titles render once, at projection** (founder ruling 2026-07-20, Option A —
recorded in `spec-change-proposals.md`; ratification into `decisions.md` is a
pending founder action, and the proposed ADR-043 text is in
`claudedocs/ratification-proposal-adr-043.md`). A notification is a historical
fact, so a later rename must not rewrite it. The renderer does local reads only
and **never invents copy**: if `users.name` or the env name is missing the row is
withheld rather than substituted.

That case is live — ADR-0007 **org keys carry `user_id NULL`**, so automation
deploys record an empty actor and N1 supplies no frame for a non-human actor.
`bell_scanned.unrenderable` flags them so a ruling applies retroactively (the
flag is coarse; see the ledger). Design note:
`claudedocs/design-note-non-human-actor-copy.md`.

**Two rejected designs are banked in `contexts/events-spine.md`** — the webhook
predicate (starves) and an `at`-based cursor (loses late-committing transactions).

Verified against real Postgres under `-race`: head-of-line blocking, idempotent
re-runs, exactly-once under concurrent drains, partial-fan-out rollback, and the
migration seed against a **non-empty** spine. Note the no-backfill test passes
because the ledger row already exists — it is an artifact of the ledger, not an
enforced property (blocker note above).
