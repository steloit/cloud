## Goal

The bell rings for what actually needs a person: notification-worthy spine events
project exactly once into per-user bell rows with frame-sourced titles, so the
rows a console badge counts are a projection of the spine, not of raw events.

## Why

S4 named the notifications family the highest-frequency gap. T10.3 built the
store, the routing matrix and webhook delivery — but nothing rings the bell in a
running system (`spec-change-proposals.md:204`), and the console bumps the badge
on **every** spine event (`:225`, which names the N1 slice as owner). This task
is the server-side half of that slice; the console half and three other concerns
were split out on review (§ Out of scope), so this is narrower than the roadmap's
"notifications family" line and the title reflects the real deliverable.

## Approach

**No contract change.** `apis: []`. The kind enum is deferred (§ Out of scope).

1. **`notify.Classify(action string) (kind, title string, ok bool)`** — pure,
   table-driven: spine `action` → frame kind + title template. `ok=false` means
   **not notification-worthy**, the common case. No frame row ⇒ `false`, never a
   guessed title. Each entry carries `// N1 gallery:<line>` provenance.
2. **Titles are pinned, not substring-searched.** Assert each title against a
   table of `(frame id, gallery line, exact fragment)` and search **only the
   N1/N2 region** (~10444-10700). A bare substring search over the 1.4 MB gallery
   false-passes: markup splits the skeleton, so fragments shrink until any short
   English phrase matches somewhere in the console copy.
3. **A terminal ledger, not a timestamp watermark.** Migration `bell_scanned`
   (`event_id text PRIMARY KEY REFERENCES events(id) ON DELETE CASCADE,
   scanned_at timestamptz NOT NULL DEFAULT now()`) records **every scanned
   event, worthy or not** — that marker is what the webhook path gets from
   `webhook_deliveries` and the bell otherwise lacks. Seed it in the migration
   with every existing event id, so first boot does not fan the whole spine and
   no-backfill holds by construction. Add
   `CREATE INDEX events_at_id_idx ON events (at, id)` — the existing index is
   org-leading and unusable for this cross-org scan.
4. **`ListPendingBellEvents`** — anti-join: `FROM events e LEFT JOIN bell_scanned
   bs ON bs.event_id = e.id WHERE bs.event_id IS NULL AND e.at >= @floor
   ORDER BY e.at, e.id LIMIT @lim`. `@floor` is a **performance bound only**
   (lag it behind `max(scanned_at)`; correctness never depends on it — see
   Edge cases for the residual).
5. **`Router.ProcessBell(ctx) (int, error)`** — per event, in **one tx**:
   claim via `INSERT INTO bell_scanned … ON CONFLICT DO NOTHING RETURNING
   event_id` (no row ⇒ another replica owns it, skip — the same claim-before-work
   shape as `ClaimWebhookDelivery`), `Classify`, insert bell rows for the worthy,
   **enqueue** email to `email_deliveries` (its `UNIQUE (event_id, recipient)`
   makes it idempotent; the existing dispatcher sends after commit), commit.
6. **The `Notify` seam must change.** `Router.Store` has no `WithTx`, and
   `Notify` calls `r.email.Send` inline — a network call this design forbids
   inside the tx. Give `Notify` a tx-bound `Store` argument and make it
   **enqueue** rather than send. State the `NewRouter` signature change in the
   PR. Also: `Notify` currently logs a per-member insert error and continues
   (`notify.go:119-124`); inside the tx that must become a hard error, or a
   partial fan-out commits and is never retried.
7. **Wire it** in `cmd/api/main.go` beside `RunOutbox` (`:230`), **and wire the
   mailer**: `main.go:229` builds the router with no `.WithEmail(...)`, so the
   email route is dead in production today. One line, inside `files:`; add a
   wiring assertion so a nil sender cannot ship silently again.
8. **`EmitQuotaWarning` stays imperative** — it is derived from a threshold
   crossing and carries no spine event (`quota_warning.go:17-21`), so it cannot
   route through the projection. Record that ruling in the task Outcome; it is
   the one bell writer that legitimately bypasses `Classify`.
9. **File the deferrals** (§ Out of scope) as ledger rows, and bank the lessons
   in `contexts/events-spine.md`.

## Edge cases

- **A long run of non-worthy events** → each still gets a `bell_scanned` row, so
  the anti-join excludes it and the window cannot fill with un-clearable rows.
  This is the head-of-line case and the whole reason for step 3.
- **A transaction that opens before a scan and commits after it** → invisible to
  any `at`-based watermark, because `events.at` is **transaction start** time.
  The ledger is immune: the event simply has no `bell_scanned` row and is picked
  up whenever it becomes visible. **Residual:** `@floor` must lag further than
  the longest write tx, or a late-committing event below the floor is missed;
  state the chosen lag and why.
- **Two replicas** → both may scan an event; the `ON CONFLICT DO NOTHING` claim
  means exactly one fans out. Bell rows also dedupe on the partial unique index,
  and email on `UNIQUE (event_id, recipient)` — three independent guards.
- **Crash mid-fan-out** → the tx rolls back, the claim disappears with it, and
  the retry re-fans **every** member. A design that committed the claim
  separately would drop members 4–10 of a 10-member org, silently, forever.
- **Member with `inapp` off** → no bell row (`notify.go:118`); that is the
  shipped pref semantic and AC3 is worded to respect it.
- **Late joiner** → no backfill by construction: history is pre-seeded into
  `bell_scanned`, and membership is read at projection time. Pin both halves —
  the new member has 0 rows *and* existing members are not re-notified.
- **Quiet hours** → gate the **email route only**; the bell row is written
  regardless (routing ≠ recording).

## Security & performance

- Never hold the tx across a network call. Email is **enqueued** in-tx and sent
  by the existing dispatcher after commit — "send after commit" would be
  at-*most*-once (the claim is already committed, so a crash loses the mail
  permanently) and would reintroduce the silent-partial-delivery class.
- The anti-join without `events_at_id_idx` is a seq scan + sort of the whole
  spine every tick; with `@floor` it stays a bounded index range.
- Per-member fan-out is O(members) per worthy event — keep `Classify` pure.
- No new error class (Trap T3).

## Acceptance criteria

- [ ] WHEN a spine event has no frame-sourced classification THEN no bell row is
      created **and** the event is marked scanned (both halves).
- [ ] WHEN more than one full batch of consecutive non-worthy events precedes a
      worthy one THEN the worthy one still produces bell rows.
- [ ] WHEN a notification-worthy event is projected THEN every org member **whose
      in-app pref is on** gets exactly one bell row, and no opted-out member gets
      one.
- [ ] WHEN a bell title is produced THEN it matches a pinned `(frame id, gallery
      line, fragment)` entry located in the N1/N2 region — mechanically asserted.
- [ ] WHEN `ProcessBell` runs twice over the same events THEN the second call
      reports 0 new rows and the row count is unchanged.
- [ ] WHEN a per-member insert fails mid-fan-out THEN the batch rolls back and a
      later run notifies **all** members — no member is silently skipped.
- [ ] WHEN a member joins after events were projected THEN they receive no
      backfill AND existing members are not re-notified.
- [ ] WHEN quiet hours are active THEN the bell row is still written and only the
      email route is suppressed (existing test, kept in `verify:`).

**Three things about the `verify:` block are load-bearing.** (1) Each Go entry
asserts an explicit `--- PASS: <name> (` line **and** `go test`'s exit code.
`go test -run` exits 0 when nothing matches (Trap T9), and a bare `… | grep -q`
pipeline returns *grep's* status, masking a post-PASS panic. (2) The pattern ends
at `(`, **not** `$` — `go test -v` prints `--- PASS: TestX (0.00s)`, so a
`$`-anchored pattern never matches and the guard is red on a *passing* test. A
red-state probe cannot catch that; prove the **green** state too. (3) The
`internal/identity` entries need a **container runtime** (START-HERE §12):
`newWorld` calls `t.Skipf` without Docker and a skip prints no `--- PASS`, so the
entry correctly goes red. Do not paste a skip as evidence.

## Common mistakes

- **Copying `ListPendingWebhookEvents`' predicate without its ledger.** That
  query is self-limiting because its filter is **in SQL** (`e.kind =
  ANY(w.events)`) and `webhook_deliveries` records a terminal row for the rest.
  `Classify` runs **in Go**, so without `bell_scanned` a non-worthy event leaves
  no row, permanently satisfies `WHERE … IS NULL`, and fills every later `LIMIT`
  window — after one batch of silence the bell stops ringing forever.
- **Replacing that with an `at`-based cursor.** `events.at` is transaction
  **start** time, so a concurrent long tx commits *below* the watermark and is
  skipped permanently. Timestamps order; they do not prove handling.
- **Pairing a per-event skip with per-(user,event) `ON CONFLICT` and calling it
  idempotent** — mutually exclusive: if the scan excludes handled events the
  conflict never fires.
- **Sending email after commit** instead of enqueuing in-tx (at-most-once).
- **Inventing a title**, or asserting one by substring over the whole gallery.

## Out of scope

Server-side bell projection only. Each item is a ledger row, not silence. The
first four were carved out on review — this was four concerns, not one (rule 12).

- **The `kind` enum** `[alert, proposal, approval, deploy, lifecycle]` — §8
  proposal, **not inline**: shipped rows already carry `billing`
  (`quota_warning.go:29`) and `security`, so pinning it would make
  `listNotifications` emit contract-invalid values. The proposal must rule the
  legacy mapping **and** backfill-vs-tolerant-read.
- **`unread=false` ⇒ read-only rows** — invented semantic; no frame asks for it.
- **`testWebhook` HTTP coverage** — own task; carries a live 403/404 leak (filed).
- **The console badge half** — `bumpLive()` counts every spine event
  (`app/shell/realtime-mount.tsx:57`; `ctx.tsx:57` is the consumer). Needs
  console lint/test gates (Trap T6). Own task, with `:225`'s offline affordance.
- **Bell ordering by event time** — `notifications` orders by `created_at`
  (projection time), so a post-downtime backlog lands out of order. Fixing it is
  a second migration **plus** a change to `ListNotifications`' ORDER BY *and* its
  keyset cursor (`notify.sql:26-29`) — an observable pagination change. Own task.
- `deleteWebhook` / `PATCH /webhooks/{wbh}` — absent from the contract (Trap T2).
- `needs-action` grouping — depends on **approval threads**, never specced.
- SSE for `/me/notifications` — `x-streamable` but no streamer; `events.Hub` is
  org-keyed (`hub.go:15`).
- P6's per-type matrix and `Mobile push` — unexpressible in `channels{email,inapp}`.
- `Urgent` source + email-off-override — E7/auth owns (`:239`).
- Webhook-per-org cap and delivery lease — T10.3 review items.
- `models.md` documents neither `notifications` nor `webhooks` — S-process item.
