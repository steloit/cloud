## Goal

Plans gate CAPABILITIES, never SAFETY: TLS, backups, MFA, policies, alerts,
dunning protections, and self-deletion are free at every tier (B6/F9).

## Read first

- internal/billing/plans.json `never_gated.capabilities` — the list is law.
- internal/billing/plans.go IsNeverGated — the predicate the quota evaluator +
  gate call sites consult before any plan gate (T11.1/T11.5).
- internal/platform/problem/problem.go PlanGated — the ONE 402 plan-gate.

## Approach

T11.1 shipped the `never_gated` list + IsNeverGated + a basic assertion. US-11.1
makes it a DRIFT-PROOF, table-driven invariant in both directions and adds a
structural enforcement check:
- TestSafetyNeverGated: the plans.json list must EQUAL the canonical safety set
  exactly (set-equality — a dropped entry silently plan-gates safety; an extra
  entry silently frees a capability), + capability features (ai/sso/audit_export/
  byoc/priority_support) must NOT be on it.
- TestSafetyOperationsNeverPlanGated: the clearest always-available safety ops —
  MFA and self-deletion — must never reference problem.PlanGated in their
  handler source (a plan gate creeping in fails the build).

## Acceptance criteria

- [x] The never-gated list is a table-driven test — set-equality against the
  canonical safety set (drift-proof both directions) + the capability-negative.
- [x] Structural: the MFA + self-deletion handlers reference NO plan-gate signal
  (problem.PlanGated / RequiredPlan / RequirePlan) — must-exist files fail loudly
  if renamed; the tripwire refuses to pass inert (scanned==0 fatals).

## Related

B6/F9 · T11.1 (plans table) · T11.5 (quota evaluator consults IsNeverGated) ·
US-11.2 (soft/hard quotas) · US-11.7 (hard spend cap).

## Outcome

The "plans gate capabilities, never safety" law is now a drift-proof invariant.
T11.1 already shipped the `never_gated` list + IsNeverGated; US-11.1 hardens the
test from "these are present" to SET-EQUALITY against the canonical safety set
(tls, backups, mfa, policies, alerts, dunning_protections, self_deletion) — so
the list cannot silently gain or lose an entry — plus the capability-negative
(ai/sso/audit_export/byoc/priority_support are gated, not free). And a
structural test asserts the two clearest always-available safety operations
(MFA, self-deletion) never reference the single plan gate (problem.PlanGated) in
their handlers, so the property is enforced by code shape, not just by the list.
