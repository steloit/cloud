## Goal

B12 Cancel ≠ Delete: cancelling changes the PLAN (ends at anchor), never the
RESOURCES — services keep running and keep metering; the way back is one click.

## Read first

- docs/product/00-sources/Steloit-Console-Screens.html B12 (verbatim): "what
  stops, what keeps running (and billing)... Reactivation is one click, any
  time. Until [anchor]: 'Resume' uncancels — nothing was interrupted. After:
  'Restart' re-bills... because nothing was deleted in between."
- internal/subscription/subscription.go (Q9): Cancel → cancelled_at_anchor +
  plan_ends_at; Reactivate (cancelled_at_anchor → current); wind_down echoed.
- internal/metering/metering.go: BillingEdge is driven by RESOURCE status
  (ready/degraded bill; suspended/deleting/failed stop) — NOT subscription
  status, so cancel structurally cannot stop metering.

## Approach

The state machine + wind-down contract shipped with Q9. US-11.5:
1. Exposes the one-click way back — POST /orgs/{org}/subscription/reactivate
   (B12 "Resume"): before the anchor, Reactivate uncancels; after, it 409s and
   the caller restarts via changePlan (the plan already ended to free).
2. Proves the B12 invariant: cancel with a running (ready) service leaves the
   service ready and its metering span OPEN (no billing-close edge) — metering
   keeps running; the span closes only on real teardown.

## Acceptance criteria

- [x] Cancel leaves services running + metering: a ready service with an open
  span stays ready and its span stays open across cancel; only a real teardown
  (deleting) closes it. The API echoes status=cancelled_at_anchor +
  resources_unaffected:true.
- [x] One-click way back: Resume (reactivate) before the anchor → current, plan
  restored, wind-down cleared; after the anchor Resume 409s and Restart
  (changePlan free→paid) re-subscribes.

## Related

B12 · T11.2 (state machine) · Q9 (cancel + wind_down + Reactivate service method)

## Outcome

The "Cancel ≠ Delete" guarantee is now enforced-and-tested end to end. The key
structural fact: metering keys off RESOURCE status, not subscription status, so
cancel (which only writes the subscriptions row) cannot stop a running
service's billing span — the test proves a ready service with an open span
stays ready with the span open across cancel, and closes only on real teardown.
The one-click way back is exposed as POST .../subscription/reactivate: before
the anchor it uncancels to current/plan-restored with the wind-down cleared;
after the anchor it 409s (the plan already ended to free) and Restart is the
existing changePlan(free→paid). Reactivate reuses subscription.change authz (no
new permission). Spec change (the reactivate endpoint) made first in
openapi.yaml, regenerated across Go/SDK/console.
