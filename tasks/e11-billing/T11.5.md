## Goal

Quota evaluator: soft overage proceeds only on confirm=true with the price
shown; hard fails loudly with remediation.

## Summary

hard fails with remediation.

## Outcome

`internal/quota` is the **one decision function for every metered limit**, so
soft/hard behaviour can't diverge across call sites. `Evaluate(kind, allowance,
used, delta, overageRate, confirm)` returns a `Decision`:
- within the allowance → `Allowed`;
- soft over + `confirm=false` → `SoftBlocked` with `OveragePriceCents` = the
  **incremental** overage this op incurs × the rate (existing overage was
  already consented to) — the caller maps it to `problem.QuotaSoft` (402, price
  shown, never discovered on the invoice);
- soft over + `confirm=true` → `Allowed` + `OverageConfirmed` (billed);
- hard over → `HardBlocked` (confirm never bypasses it) → `problem.QuotaHard`
  (402/429 + remediation).
`WarnLevel`/`ShouldWarn` back the 80% banner+bell+email (QA scenario 2), and an
`allowance < 0` = unlimited path never blocks or warns. Money is integer cents.
Safety features are never seen here — the never-gate check is the caller's via
`billing.IsNeverGated`.

Wired consumer: the **seat** soft-quota (the one meter with a sourced per-plan
allowance, T11.1) now runs through `quota.Evaluate` instead of an ad-hoc
`used >= included` check — so invite-over-seats is the same evaluator every other
metered limit uses (existing invite integration tests cover it end-to-end).
Comprehensive unit tests pin the AC (soft under/at/over/partial/already-over,
confirm, hard, unlimited, warn-at-80%).

Metered soft quotas (egress, events, AI, builds) and hard quotas (the spend cap,
previews queue) plug into the SAME evaluator against `quota_usage.used` + the
billing table's overage rates once their per-plan allowances are sourced
(T11.1's deferred egress/event allowances — only the Business org's are
canon-pinned). The evaluator + the `QuotaSoft`/`QuotaHard` catalog mapping are
the ready seam.
