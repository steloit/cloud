## Goal

Pricing + quota tables as data — one table consumed by the estimate engine,
quota evaluator, and invoice generator.

## Summary

**AC:** one table consumed by estimate engine, quota evaluator, and invoice
generator.

## Read-first

- contexts/billing.md — the one arithmetic (Free $0 / Pro $29 / Business $99),
  the never-gated safety list, soft-overage unit prices
- services/api/internal/estimates/pricing.json — the resource-shape prices (T3.1)
- docs/adr/ (ADR-041) — Pro $29 canonical

## Acceptance criteria

- [x] one table consumed by estimate engine, quota evaluator, and invoice
  generator (the table + loader exist; the project-allowance quota already reads
  it; estimate/quota/invoice consume `PlanFeeCents`/`Overage`/`ProjectLimit`).

## Outcome

The ONE pricing + quota table now lives as data: `internal/billing/plans.json`
(plan fees, per-plan quota allowances, soft-overage unit prices, the never-gated
safety list) + a strict Go loader (`billing.Load`, embedded, invariant-checked,
deny-by-default for unknown plans). Money is integer cents (ADR-025).

It reproduces the billing pack + ADR-041: Free $0 / Pro $29 / Business $99 (fees
2900/9900), Enterprise custom-priced (no hard-coded number), project allowances
Free 1 / Pro 3 / Business+ unlimited, and the soft-overage schedule (egress
$0.09/GB, seats $7, builds $0.01/min, events $1.20/M, AI $2/1k). A canon test
reconciles it against the demo world (Business fee == canon `plan_fee_cents`;
resources + fee == the $482 org total), so the table and canon can't diverge.

Consumers: the provisioning **project-allowance quota gate** was refactored off
its hard-coded map onto `s.plans.ProjectLimit` (no second pricing constant — the
billing-pack law). The **estimate engine / invoice generator (T11.3) / quota
evaluator (T11.5)** read `PlanFeeCents` / `Overage` / `ProjectLimit` from the
same table as they land — the seam is ready, and the "shown estimate IS the
invoice line" invariant holds by construction (one source).
