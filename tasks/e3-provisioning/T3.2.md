## Goal

Projects and environments live behind the contract — the containment tree below orgs,
with the ADR-037 implicit production environment born at project creation.

## Why

Everything in E3+ hangs off these rows (services, estimates, deploys); the events spine's
`EnvResolver` seam closes here.

## Read first

- `contexts/provisioning.md` — D6/D7/D9 invariants; every resource row carries `cell_id`.
- `docs/product/08-api/openapi.yaml` — the 7 ops + Project/Environment schemas.
- `docs/product/09-data-models/models.md` — projects(id, org_id, name UNIQUE(org_id,name));
  environments(id, project_id, name, region_override).
- ADR-037 (decisions.md) — implicit-by-default: production is born, not created; a stable
  identity, not a deployment state.
- B5 frame (plan matrix): Projects — Free 1 / Pro 3 / Business+ unlimited.
- Don't read: 99-history, frame gallery end-to-end.

## Approach

1. Migration: `projects` (prj_, org_id FK, name, `cell_id NOT NULL DEFAULT 'cell-0'`
   — invariant 1, even while it's always cell-0; deletion_scheduled_at; UNIQUE(org_id,name))
   and `environments` (env_, project_id FK, name, region_override NULL, kind
   standard|preview, policy_flags jsonb, expires_at NULL; UNIQUE(project_id,name)).
   Add the `policies.project_id` FK deferred from T2.4.
2. New module `internal/provisioning`: service + strict handlers (7 ops added to
   include-operation-ids). Reads gated by org membership (404 for non-members — no id
   probing); mutations via the identity Authorizer (`project.create`, `org.manage` for
   rename/transfer, `project.delete`, `env.manage`).
3. `createProject` (one tx): project + implicit `production` env (region = input or org
   home_region), then spine events. Plan gate BEFORE create: Free 1 / Pro 3 /
   Business+ unlimited → 402 plan_gated naming the next plan (F2 "gate with reason").
4. `deleteProject` 202 = deletion_scheduled_at (like orgs); blocked 409 with reasons[]
   while non-implicit envs exist (services join the check when T3.3 lands). The implicit
   production env never blocks — it is born, not created (ADR-037).
5. `createEnvironment`: name unique per project; region_override; `clone_shape_from` /
   `data: branch` are T3.4-gated — 422 with remediation until the CNPG driver exists
   (recorded limitation, not silent).
6. Close the events seam: real `EnvResolver` (env → project → org) replaces `NoEnvs` in
   main.go and the fake in the integration world.
7. Project/Environment API mapping: monthly_cost_cents 0 until estimates/services exist;
   health `ok`; env_count real; last_deployment absent.

## Edge cases

- Duplicate project name in org → 409 reasons[]; same name in another org → fine.
- Duplicate env name in project → 409.
- `template_id` supplied → 404 template (templates are E9; honest not-found).
- Project of a deletion-scheduled org → still readable; creation blocked.
- Non-member on any /projects/{id} path → 404, never 403.

## Security & performance

- Project-scoped paths resolve project → org THEN authorize in that org's scope.
- `cell_id` never surfaces in any response (D8 grammar-only).

## Acceptance criteria

- [x] All 7 operations match openapi.yaml shapes on real Postgres.
- [x] createProject births the implicit `production` environment in the same tx; project
      creation at the plan limit → 402 naming the required plan.
- [x] `GET /envs/{env}/events` works end-to-end through the real resolver (seam closed).
- [x] Non-members get 404 on project/env ids.

## Validation

`verify:` block; integration evidence in the PR.

## Common mistakes

- Provisioning imperatively from the handler (nothing provisions here — rows only; D9).
- A resource table without `cell_id` (invariant 1).
- Counting the implicit production env as a deletion blocker (ADR-037: born, not created).
- Surfacing `cell_id` or substrate names in responses (D8).

## Outcome

- New `internal/provisioning` module (M4): rows only — nothing provisions (D9); every
  project row carries `cell_id` (invariant 1) and it never surfaces (D8, asserted).
- One strict server, composed handler sets: identity's mount now takes the composed
  `gen.StrictServerInterface`; module errors flow through one seam via `problem.Carrier`.
- ADR-037 landed in code: `production` is born inside the createProject tx, implicit
  production never blocks deletion, explicit envs do (409 with all reasons).
- Plan gate as data: Free 1 / Pro 3 / Business+ unlimited (B5 matrix); 402 names the
  lifting plan.
- The T2.5 `EnvResolver` seam is CLOSED: env → project → org resolves from real rows in
  main.go, the SSE streamer, and every test (fakeEnvs deleted).
- `clone_shape_from` / `data: branch` refuse loudly with remediation until T3.4 (the CNPG
  driver) — recorded limitation, not silent acceptance; `template_id` 404s until E9.
- policies.project_id FK added (the T2.4 deferral honored); the policy closest-wins test
  now runs against real project rows and doubles as plan-gate coverage.
