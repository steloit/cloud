## Goal

Bindings implementation (mint / rotate / restrict)

## Summary

`UNIQUE(source,target)`; FK `ON DELETE RESTRICT`; credentials rotate on unbind; edge `pending` immediately.

## Acceptance criteria

- [x] bind/unbind/rotate cycle audited: `binding.created` + `binding.revoked` on the
      spine; unbind rotates the credential (fresh version) then removes it; the revoked
      row keeps `rotated_at` as the trail.

## Outcome

- Bindings are wiring, $0 (F3): `pending` immediately, effective next deploy; the
  models.md row shape (internal target OR external provider, CHECK-enforced) with the
  partial-unique pair index scoped to non-revoked rows — revocation frees the pair.
- Credentials MINTED at bind straight into the vault (env-scoped, `binding/<id>`),
  never in a binding row; reads mask env-var values and never return `secret_ref`;
  deterministic `<TARGET>_URL` naming.
- Unbind ROTATES first (a racing reader sees a dead credential), then removes the vault
  entry; the row survives as `revoked` for audit.
- U6 lands in deleteService: deleting a bound target 409s naming EVERY dependent
  (source service + binding id) — proven over live HTTP.
- FK ON DELETE RESTRICT backs the API check at the storage layer.
- Findings: (1) cross-env bindings refuse loudly — the "elevated permission / policy
  default" mechanism needs a policy kind (E12); (2) external-provider bindings
  (storage/ai) have schema support but no create surface in createBinding's body —
  they arrive with their catalog flow.
