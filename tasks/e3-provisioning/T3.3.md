## Goal

Service CRUD + shape jsonb + status machine

## Summary

`provisioning|ready|degraded|failed|suspended|deleting` (ADR-024 — not running/deleted); `UNIQUE(env_id,name)`; `idx(env_id,status)`.

## Acceptance criteria

- [x] state machine transitions tested: every legal and illegal edge unit-swept (incl. `running` rejected by name — ADR-024); the SQL FROM-guard catches stale/concurrent transitions on real rows.

## Outcome

- `services` table: desired-state rows (D9 — nothing here touches infrastructure),
  ADR-024 vocabulary CHECK-enforced, `UNIQUE(env_id,name)`, `idx(env_id,status)`,
  `cell_id` per invariant 1, C4 provisioning-step timeline born with the row.
- **The estimate gate is now enforced at the API layer** (US-3.2's law): createService
  requires an estimate that (a) covers the exact shape being created — pre-checked
  without burning the one-shot (immutable rows make it race-free; a mistyped create
  keeps the estimate usable), then (b) Accepts (one-shot, env-fenced, live). Missing
  estimate 422 naming the field; bogus/reused/mismatched 409 with remediation.
- Closed status machine as data + `Transition` (SQL FROM-guard, lifecycle event per
  edge, C4 steps flip on provisioning→ready). `deleting` is terminal;
  provisioning→deleting = cancel-the-create.
- updateService: PATCH-merge shape with automatic REPRICE through the engine; D22
  override requires a reason and records 24h auto-expiry; scaling stored separately
  from shape (range changes never restart).
- deleteService 202 → `deleting`; final backup + teardown are the driver's job
  (T3.4/US-3.5, recorded); dependents join the 409 when bindings land (T3.6).
- Findings: (1) pre-wired `bindings` on create refuse loudly until T3.6; (2) `scaling`
  and `override` columns extend the models.md services row to carry the contract's
  Scaling/override fields — models.md amendment proposed.
