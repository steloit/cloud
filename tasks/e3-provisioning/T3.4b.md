## Goal

Migrate WAL archiving off the deprecated `spec.backup.barmanObjectStore` to the
Barman Cloud Plugin before CNPG 1.31.0 removes it.

## Why — observed on a live operator (US-3.3, 2026-07-26)

Applying T3.4's rendered manifest to a real CNPG operator (chart 0.29.0) emitted:

```
Warning: Native support for Barman Cloud backups and recovery is deprecated and
will be completely removed in CloudNativePG 1.31.0. Found usage in:
spec.backup.barmanObjectStore. Please migrate existing clusters to the new
Barman Cloud Plugin to ensure a smooth transition.
```

The cluster still provisioned and reached ready, so this is a **deadline, not a
breakage** — but it touches the load-bearing D5/F5 contract (WAL → GCS via
workload identity, zero static keys) and three places carry the field:

- `services/cell-agent/internal/driver/cnpg/templates/cluster.yaml.tmpl` (and the
  PITR template's `externalClusters[].barmanObjectStore`)
- `infra/k8s/control-plane/cnpg-cluster.yaml`
- ADR-0007's measured shape (§2 F5) — an ADR amendment if the mechanism changes

## Acceptance criteria

- [ ] The driver renders the plugin form; a live apply produces no deprecation
  warning.
- [ ] WAL still lands in GCS via workload identity (no static keys — D5/F5).
- [ ] PITR's `externalClusters` source is migrated in step (it reads the same
  archive; a half-migration would break recovery).
- [ ] The golden + ground-truth parity tests updated together, and ADR-0007
  amended if the measured mechanism changed.
