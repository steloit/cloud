## Goal

Metering emitters on every resource lifecycle edge

## Summary

D10 — cannot defer; backfill is impossible. compute-seconds, CU-hours, GB-months, egress bytes, tagged org/project/env.

## Acceptance criteria

- [x] events flow from the first provisioned resource: the span opens on the FIRST
      transition to ready (fully tagged org/project/env/service, rate snapshotted) and
      closes when billing stops — integration-proven end-to-end.

## Outcome

- `usage_events`: the raw metering store, append-only at the DB level (trigger), tags
  WITHOUT FKs by design — billing truth outlives the resource tree. T6.3 rolls up.
- Control-plane emitters ride the status machine: `BillingEdge(from,to)` — open at
  ready, degraded still bills, suspended/deleting/failed-from-degraded close; failed
  PROVISIONING never bills (C4; the pre-driver half of US-3.6, integration-proven).
- Rate snapshots at the edge (integer cents): later price changes never rewrite history.
- A metering emit failure after a committed transition logs LOUDLY as a billing
  incident (D10) and never rolls back the state change.
- Fine-grained meters (compute-seconds, egress bytes, CU-hours) are the cell-agent's to
  emit into the SAME table when it lands (T3.4+/E6) — the store and tags are ready.
