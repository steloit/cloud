## Goal

The CNPG driver behind one provisioner interface (ADR-0003 / INF-001 A4): render
a service's desired state into the CNPG/K8s manifests for cluster create,
snapshot-branch, hibernate/wake, and PITR-to-new-branch. The interface is
product-agnostic so E9 products (Valkey) reuse it unchanged.

## Authority — encode measured truth, do not re-prove it

Founder decision (2026-07-23): implement against **ADR-0007's measured behavior
as the contract**; NO live cluster (that evidence exists from T1.0). The golden
manifests are the validated shapes in `infra/k8s/control-plane/cnpg-cluster.yaml`
and `infra/spike/manifests/spike-*.yaml`. `contexts/provisioning.md` §Drivers and
`docs/plan/e1-substrate-design.md` §2/§3 govern.

Measured contracts the driver must encode (ADR-0007):
- `archive_timeout: 300s` — the RPO bound, by construction (A1.3 / F4).
- Branch = `VolumeSnapshot` → CNPG `bootstrap.recovery.volumeSnapshots` (measured
  branch e2e 52.4s; data-identical).
- PITR = new cluster, `bootstrap.recovery.recoveryTarget.targetTime` derived from
  the last archived WAL, **never wall-clock** (F4).
- WAL → GCS via `barmanObjectStore` + `gkeEnvironment: true` (workload identity,
  zero static keys, D5/F5).
- Storage on `pd-cell` storageClass, `db-storage` pool affinity + storage taint
  toleration (T1.2), retention 30d.

## Scope — rendering + orchestration only, apply is the seam

This builds the RENDER half of the reconciler's converge (US-1.3 §2:
"render manifests from desired, server-side-apply"). The actual k8s apply/exec is
behind the seam (the cell-agent's Renderer, a later live-integration task) — no
cluster, ~$0.

**1 · The provisioner interface** (`services/cell-agent/internal/driver/`)
- `Driver` (every product): `Render(DesiredService) (Manifests, error)` — grammar
  (product + shape + intent) → the manifests to apply. This is the interface E9
  reuses **unchanged** (the AC).
- `BranchingDriver` (Postgres-specific extension, the D2 primitive):
  `SnapshotBranch(BranchSource) (Manifests, error)`,
  `PITRBranch(BranchSource, targetTime) (Manifests, error)`,
  `Hibernate(cluster) / Wake(cluster) (Patch, error)`.
- `Manifests` is an ordered list of rendered objects (kind + YAML/bytes);
  substrate names live here — this is the INTERNAL plane, the driver's job is to
  translate grammar → substrate (D8 forbids substrate in CUSTOMER surfaces, not
  in the driver's output).

**2 · The CNPG driver** (`.../driver/cnpg/`)
- `Render`: a CNPG `Cluster` from product=postgres + shape (size → storage), with
  the measured parameters (archive_timeout, pd-cell, pool affinity, barman WAL,
  retention). instances from shape/scaling.
- `SnapshotBranch`: a `VolumeSnapshot` of the source + a `Cluster` with
  `bootstrap.recovery.volumeSnapshots`.
- `PITRBranch`: a `Cluster` with `bootstrap.recovery.recoveryTarget.targetTime` +
  `externalClusters` source; reject a wall-clock target with no archived-WAL basis.
- `Hibernate`/`Wake`: the CNPG declarative-hibernation annotation patch.
- Names/namespaces from the service+cell (never duplicated — one derivation).

**3 · Second-product proof** (`.../driver/valkey/` or a stub)
- A minimal Valkey driver implementing `Driver.Render` (NOT `BranchingDriver`) to
  prove the interface is reused unchanged (the AC). It need not be
  feature-complete — it proves the abstraction holds with a non-branching product.

## Summary

Cluster create, snapshot-branch, hibernate/wake, PITR-to-new-branch — per-product driver pattern (14-development). Branch orchestration (metadata, routing, cleanup) is control-plane code; Xata OSS is the reference implementation.

## Outcome

The CNPG driver behind one provisioner interface, encoding T1.0's measured truth
(ADR-0007) as the implementation contract — no live cluster, ~$0 (founder
decision 2026-07-23).

- **`driver.Driver`** (product-agnostic: `Render(Spec) → Manifests`) is the
  interface E9 reuses; **`driver.BranchingDriver`** is the Postgres D2 extension
  (snapshot-branch, PITR, hibernate/wake). Valkey implements `Driver` but NOT
  `BranchingDriver`, which is the actual proof the abstraction fits products with
  different capabilities — the headline AC.
- **CNPG** renders via `text/template` (deterministic, dep-free) into the
  validated manifest shapes: cluster-create matches the validated `cnpg-cluster.yaml` **shape** — a
  ground-truth parity test (`TestClusterMatchesGroundTruthManifest`) parses the
  real infra manifest and asserts the load-bearing subtree is field-equal, so the
  goldens are not circular, branch = VolumeSnapshot → `bootstrap.recovery.volumeSnapshots`,
  PITR = `recoveryTarget.targetTime` + `externalClusters`. The measured contracts
  are encoded and test-asserted: archive_timeout=300s (RPO/F4), WAL→GCS via
  workload identity (D5/F5), and PITR **refuses a wall-clock target with no
  archived-WAL basis** (F4).
- Scoped to RENDER (the reconciler's converge half, US-1.3 §2). The real
  server-side-apply is the cell-agent Renderer seam — a later live-integration
  task, per the founder's "validate new behavior only" policy.

Golden files under `testdata/`; regenerate with `go test ./... -update`.

## Review fixes (round 1 — both reviewers, all substantive)

The first pass shipped **circular golden tests** (compared the driver's output to
a golden it generated) that blessed manifests diverging from ground truth in
load-bearing ways. Fixed:
- **Anti-circularity:** `TestClusterMatchesGroundTruthManifest` ties the render to
  the validated `infra/k8s/control-plane/cnpg-cluster.yaml` (parses both, asserts
  the measured subtree — storageClass, affinity, archive_timeout, gkeEnvironment,
  retention, storage toleration).
- **F3 base backup:** `Render` now emits the `ScheduledBackup` (immediate:true) —
  WAL archiving alone is not restorable (ADR-0007 F3); PITR needs a base backup.
- **PITR was non-functional:** added `serviceAccountTemplate` (GSA — the recovering
  pod reads GCS WAL via workload identity) and the db-storage affinity/toleration;
  threaded the SOURCE's WAL bucket (was hardcoded, breaking non-dev cells).
- **Branch/PITR placement:** `Cell`, `WALBucket`, `GSAEmail` added to `BranchSource`
  and populated (branches carried an empty cell label); branch keeps archive_timeout.
- **RFC1123 names:** service ids (`svc_<hex>`) are sanitized to valid k8s names
  (underscores/case → dashes) — an underscored `metadata.name` would be rejected.
- Determinism test now renders a multi-key shape (was structurally vacuous); wake
  comment cites the 8.0s hibernation-wake (row 9), not the 17.7s pod-kill floor;
  edge/error paths (empty name, instances clamp/flow, nil/non-string shape, PITR
  guards) pinned.

Added `gopkg.in/yaml.v3` (test-only, for the parity parse).

## Review fixes (round 2 — QA: hold the anti-circularity line for all three primitives)

QA correctly noted that the cluster was pinned to ground truth but branch and
PITR were still pinned only by self-generated goldens — the same circularity that
blocked the cluster. Closed:
- `TestBranchMatchesSpikeGroundTruth` ties the branch recovery subtree
  (`volumeSnapshots.storage.{name,kind,apiGroup}`, archive_timeout) to
  `infra/spike/manifests/spike-b-recovery.yaml`.
- `TestPITRMatchesSpikeGroundTruth` ties the PITR read-source-WAL contract
  (`recovery.source`, `recoveryTarget.targetTime`, `externalClusters[0]` WAL path
  + gkeEnvironment) to `spike-pitr.yaml` — the field the recovering pod actually
  reads, previously unpinned.
- `repoRoot` now `t.Fatal`s (not `t.Skip`) so the ground-truth tests can't
  silently disarm under a different CI layout.
- `dnsName` gets a property sweep (`TestDNSNameIsAlwaysValid`) over
  unicode/punct/empty inputs, not one example.

Follow-up filed: **T3.4a** — branch/PITR hardcode 10Gi storage; a PITR off a
standard/pro source would be undersized. Threading the source size is a small,
separable fix.
