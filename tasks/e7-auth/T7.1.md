## Goal

MFA: TOTP + WebAuthn — a second factor for password login, never plan-gated.

## Summary

**AC:** enrol/verify/disable flows; MFA never plan-gated (F9 never-gated list).

Scope delivered: TOTP (RFC 6238) + reveal-once recovery codes + the login
`mfa_required` challenge. The TOTP secret is envelope-encrypted at rest
(`secrets.Seal`, user-scoped AAD); recovery codes are hash-stored, single-use.

WebAuthn/passkeys deferred — the register/login begin/finish operations need a
bound relying-party origin (the deployed content domain, P2/domains) and a
browser authenticator to exercise; they are not in the strict server's
include-operation-ids yet (nothing generated goes unimplemented). The
`LoginResult` already lists `webauthn` first (passkeys-first, ADR-0006).
Finding recorded in `docs/product/claudedocs/spec-change-proposals.md`.

## Outcome

TOTP MFA is live over HTTP: `totp:enroll` reveals a reveal-once secret +
otpauth URI; `totp:verify` confirms the first live code, enables MFA, and (via
`recovery:regenerate`) mints 10 single-use recovery codes. Password login then
returns `status: mfa_required` until a valid TOTP or recovery code accompanies
it; `DELETE /auth/mfa` tears it down. Never plan-gated — every handler needs
only a live session on the acting user's own account.

Security invariants proven by `mfa_integration_test.go`: the TOTP secret is
never plaintext at rest (envelope-encrypted, scanned in-test), recovery codes
are hash-stored and reject reuse, a wrong code never enables MFA, and no
session is issued while `mfa_required`. TOTP math is RFC-vector-tested
(287082 @ T=59).

WebAuthn deferred to P2 (needs a bound RP origin + browser E2E in E8).
