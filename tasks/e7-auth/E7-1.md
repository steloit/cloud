## Goal

Steloit is an OIDC relying party: a customer's CI (GitHub Actions first) federates into a **scoped, short-lived platform token** with **zero long-lived platform key stored in CI** (ADR-0006 — the blessed machine-auth path).

## Summary

The 2025-26 default for machine identity (GitHub/GCP/AWS all recommend federation over stored keys; "infrastructure trust" made literal, and consistent with invariant 11's "zero static keys"). A CI job presents its OIDC JWT (`sub=repo:org/repo:environment:prod`); Steloit validates issuer + audience + claims, gates on a configured trust policy, and mints a token scoped to one env, minutes of lifetime. The OIDC `sub`/`environment` claim maps to an **env-scoped role** in the two-layer evaluator (rbac pack). Long-lived personal/org tokens remain for humans and legacy. Differentiator, not a checkbox. GitLab CI + cloud workload identity are later extensions.

## Acceptance criteria

- [ ] A GitHub Actions job federates into a scoped, short-lived token with no stored platform secret
- [ ] Issuer/audience/claim validation + a per-org trust policy gate which `sub` maps to which env-scoped role
- [ ] Federated tokens are minted through the standard token path, audited on the events spine, and expire on job timescale
- [ ] Confused-deputy protection: claim conditions (repo/ref/environment) required; no wildcard trust

## Out of scope

- GitLab CI / cloud-workload-identity providers → later extensions
- Enterprise SSO/SCIM (human federation) → v3 WorkOS
