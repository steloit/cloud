## Goal

Contract tests + client regeneration in CI — type drift fails the build, not
the user.

## Summary

Handlers validated against openapi.yaml (schema round-trip); console/CLI/SDK
clients rebuilt on any yaml change.

## Read-first

- docs/product/08-api/openapi.yaml — the contract
- services/api/internal/httpapi/gen/types.gen.go — types generated FROM it
- Makefile gen-ts / .github/workflows/ci.yml — the generation + drift gates

## Acceptance criteria

- [x] type drift fails the build, not the user.

## Outcome

Two mechanisms close the type-drift gap:

**Schema round-trip (canon ↔ generated types).** `internal/contract`
strict-decodes **every** canon response section — all 18 (orgs, members,
projects, environments, services, bindings, deployments, events, trace,
alert_rules, insights_and_proposals, templates, dashboards, billing, quotas,
cells, estimate_example, borealis_lifecycle) — into the oapi-codegen types
generated FROM openapi.yaml, with `DisallowUnknownFields` (extra field fails)
and a required-field **presence** check (a dropped/renamed required field fails,
by key presence not zero-ness, so a legitimately-zero required value like a
quota's `used: 0` is not a false positive). A registry drives it and a
completeness tripwire fails if any fixtures section lacks a check — so coverage
can't rot as canon grows (derive, don't hand-maintain). Scope: this proves
canon ↔ generated-types; handler ↔ schema conformance is separate and comes from
oapi-codegen's strict server (handlers return `gen.*Response` types, enforced at
compile time). Canon's `$`-prefixed annotation keys (`$note`,
`$representative`) are stripped recursively (human docs, not wire fields).

**Client regeneration in CI.** The Q2 review exposed that CI ran `gen-go` but
never `gen-ts`, so a openapi.yaml change unreflected in the console/SDK clients
wouldn't fail the build. The validate job now runs `make gen-ts` then
`git add -A && git diff --cached --exit-code -- apps packages docs` (staged so a
newly-*generated* untracked file is caught too, not only tracked-file edits).
`make gen-ts` is deterministic (verified: zero drift on an up-to-date tree).
With the existing go-job `gen-go`/`gen-canon` gate (same `--cached` fix
applied), every generated artifact — console + `@steloit/sdk` clients (gen-ts)
and the Go server + `packages/contracts/go` the **CLI** imports (gen-go) — is
regenerated and diffed in CI, covering all of console/CLI/SDK.

Review hardening: coverage went from 5/18 sections to all 18 with a
completeness tripwire; missing-required detection now works for every section
(was projects-only); the git-diff gate catches untracked generated files.
