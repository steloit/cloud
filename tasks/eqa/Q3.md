## Goal

Contract tests + client regeneration in CI — type drift fails the build, not
the user.

## Summary

Handlers validated against openapi.yaml (schema round-trip); console/CLI/SDK
clients rebuilt on any yaml change.

## Read-first

- docs/product/08-api/openapi.yaml — the contract
- services/api/internal/httpapi/gen/types.gen.go — types generated FROM it
- Makefile gen-ts / .github/workflows/ci.yml — the generation + drift gates

## Acceptance criteria

- [x] type drift fails the build, not the user.

## Outcome

Two mechanisms close the type-drift gap:

**Schema round-trip (handlers ↔ openapi).** `internal/contract` strict-decodes
every canon response section (orgs, projects, environments, services, billing)
into the oapi-codegen types generated FROM openapi.yaml, with
`DisallowUnknownFields` — so a fixture field the schema doesn't declare fails,
and a schema that drops a field canon relies on fails too. A lossless
re-marshal proves the contract type doesn't silently narrow the wire shape. The
handlers return these very types, so canon conforming to them proves the wire
shapes agree. (Finding surfaced + handled: canon carries `$`-prefixed
annotation keys — `$note`, `$representative` — which are human documentation,
not wire fields; the test strips them recursively before conformance, matching
the mocks' behavior.)

**Client regeneration in CI.** The review of Q2 exposed that CI ran `gen-go`
but never `gen-ts`, so a openapi.yaml change that wasn't reflected in the
console/SDK generated clients would not fail the build. The validate job now
runs `make gen-ts` and `git diff --exit-code -- apps packages docs`: any drift
between openapi.yaml and the committed clients (console + `@steloit/sdk`) fails
CI. `make gen-ts` is deterministic (verified: zero drift on an up-to-date tree).
Combined with the existing go-job `gen-go`/`gen-canon` gate, every generated
artifact is now regenerated and diffed in CI.
