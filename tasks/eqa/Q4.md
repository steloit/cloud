## Goal

Full `matrix.csv` × role × endpoint sweep plus tighten-only property tests, so
the two-layer evaluator (ADR-0006/036) and the org-key path (ADR-0007) can never
silently widen authority or drift from the API surface.

## Summary

Full matrix cell sweep already exists (`rbac_test.go::TestEveryCell`). Q4 adds
the properties that a per-cell sweep can't express:

- **Tighten-only (monotonicity):** across a family of policy layers, a policy
  can only *narrow* — `Check(m,policy).Allowed ⟹ Check(m,nil).Allowed` and
  `⟹ Ceiling(role,perm)`. N is always final; a policy never widens it.
- **Org-key authorization (ADR-0007):** a key granted subset S authorizes `p`
  iff `p ∈ S ∧ Known(p) ∧ !Delegated(p) ∧ scope matches`, then policies narrow.
  Delegation ceiling and least-privilege denials named (E3 grammar).
- **Endpoint↔matrix drift guard:** every permission any endpoint enforces is a
  known, non-delegated matrix permission (else it is deny-by-default forever);
  a coverage report logs which matrix permissions are not yet enforced.

## Outcome

Three test files harden the authorization core with properties the existing
per-cell sweep can't state. `rbac_property_test.go` proves tighten-only
monotonicity over a deterministic policy family (allow-all, deny-all, and
index-derived deny subsets) across every role×permission×scope, plus the
delegated-never-answerable and denial-names-cause grammar. `authorize_orgkey_test.go`
sweeps the ADR-0007 org-key path with no DB (the org-key branch never reads
membership): allow iff granted∩known∩non-delegated∩scope-match, then policy
narrowing; foreign-scope, delegated, unknown, and ungranted denials each carry
their E3 explanation; `Holds`/`ValidGrantable` match `Require`. `endpoint_permission_coverage_test.go`
asserts every endpoint-enforced permission is Known∧!Delegated (no permanent
deny-by-default) and logs the 14 matrix permissions awaiting their epics. No
production code changed — pure hardening.
