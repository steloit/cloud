## Goal

The canon.md §invariants imported — never retyped — and asserted at each cost
layer, so a canon change that breaks the math fails every layer at once.

## Summary

canon.md §invariants imported, never retyped: estimate engine, invoice
generator, console.

The four equations (money = integer cents, ADR-025):
- `Σ ecommerce services == ecommerce project` (61+22+58+24+22+21 = 208)
- `Σ ecommerce environments == ecommerce project` (199.10+6.70+2.20 = 208)
- `Σ project totals == org resources` (208+96+41+38+0 = 383)
- `resources + plan fee == org total` (383+99 = 482)

## Read-first

- docs/product/19-canon/canon.md §invariants — the source numbers
- docs/product/19-canon/fixtures.json — the machine-readable world (ADR-026)
- Makefile gen-ts / rbac.go — the "copy + git-diff drift fails CI" precedent

## Acceptance criteria

- [x] the same numbers tested in all three; drift fails CI.

## Outcome

The four canon arithmetic invariants are now asserted from a single source
(fixtures.json) at each layer, with the check logic imported rather than the
numbers retyped:

- **Go** (`services/api/internal/canon`): `Load()` reads the canonical fixtures
  (relative to source); `CheckArithmetic()` verifies all four equations. The
  estimate engine test imports `EcommerceProjectCents()` instead of the literal
  20800; the invoice generator (E11) imports the same package when it lands —
  the third layer's seam is ready, not speculative code.
- **TS** (`packages/canon`, new `@steloit/canon`): the import point the
  canon-testing pack mandates ("import via packages/canon, never read
  fixtures.json raw"). Exports `assertArithmetic()` + typed accessors; its
  vitest suite proves the equations and a negative case (a corrupted fixture is
  rejected — the guard isn't vacuous).
- **Console** (`apps/console`): imports `@steloit/canon` and runs
  `assertArithmetic` over its own fixtures copy, plus a drift-identity check
  that the console copy equals the canonical source.

**Drift fails CI** two ways: `make gen-ts` copies fixtures.json into both
consumers and CI's `git diff --exit-code` fails on a stale copy (the matrix.csv
pattern); and the console identity test fails on a hand-edit that skipped gen.

Finding: the "invoice generator" third layer named in canon-testing.md does not
exist yet (E11 billing). Its arithmetic seam is the shared Go `canon` package;
wire its test when T11.x lands. Recorded, not improvised.
