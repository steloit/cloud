## Goal

POST /templates/{tpl}/refresh mints a new version; used_by_count preserved (T2
refresh-from-source).

## Read first

- internal/provisioning/templates.go RefreshTemplate (T12.4): re-captures the
  live source → UpdateTemplate (version = version + 1); used_by_count untouched.
- internal/provisioning/templates.go InstantiateTemplate: BumpTemplateUsage
  increments used_by_count on each instantiation (copies never link — no FK).
- Design-Spec §258 (T2): "refresh-from-source", templates carry a version ("v4")
  + usage count; a template survives its source's deletion (provenance strings).

## Approach

The refresh MECHANICS shipped with T12.4 (RefreshTemplate bumps version, the
UpdateTemplate SQL does version+1, used_by_count is a separate column it never
touches; instantiation bumps used_by_count via BumpTemplateUsage). T12.5 turns
the AC into an ENFORCEABLE invariant: an end-to-end test that captures (v1),
instantiates (used_by_count→1), changes the source, refreshes (v2 minted,
used_by_count PRESERVED, contents re-captured, price changed), and proves a
source-gone refresh is refused loudly with the template left intact.

## Acceptance criteria

- [x] Refresh mints a new version: capture is v1; after a refresh the version is
  2 (version+1), and the contents/price reflect the re-captured live source.
- [x] used_by_count is preserved across the refresh (an instantiation bumps it
  to 1; the refresh leaves it at 1 — copies never link).
- [x] A refresh whose source no longer exists 409s ("no longer exists"; stays
  usable as-is), leaving the template's version + used_by_count unchanged.

## Related

T2/T3 templates · T12.4 (capture/instantiate/refresh) · ADR-021 (frozen copies).

## Outcome

T12.5 is the enforceable guarantee for refresh-as-new-version. The mechanics
shipped in T12.4 (RefreshTemplate → UpdateTemplate version+1; used_by_count
bumped on instantiate via BumpTemplateUsage and untouched by refresh); this task
pins them with an end-to-end invariant test that was missing: capture→v1,
instantiate→used_by_count=1, source-change→refresh→v2 with used_by_count still 1
and the re-captured contents/price reflecting the change, and a source-deleted
refresh refused (409, template intact). The version is a monotonic counter
(Design-Spec §258 "v4"), not a retained history — matching the schema and the
frames; no version-history table is implied.
