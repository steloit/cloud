## Goal

Prebuilt dashboards are GENERATED VIEWS, not files (Design-Spec §244): always
current, read-only, and "Customize" forks a copy into My dashboards. Plus the
§2c dashboard endpoints: fork, duplicate, delete-widget.

## Read first

- docs/product/00-sources/Steloit-Console-Design-Spec.md §244 — prebuilt = views
  generated from topology; "Customize" forks a copy (template copy-semantics);
  shared dashboards are live-for-everyone and audited.
- docs/product/claudedocs/spec-change-proposals.md §2c — the dashboard endpoint
  additions (fork/duplicate/delete-widget/share grants).
- T12.6 (services/api/internal/provisioning/dashboards_http.go) — the CRUD +
  two-axis gate this builds on.

## Approach

- SPEC CHANGE FIRST (openapi.yaml): added `POST /dashboards/{dash}/fork`,
  `POST /dashboards/{dash}/duplicate`, `DELETE /dashboards/{dash}/widgets/{wdg}`
  — sub-path form (the Go 1.22 stdlib mux rejects `{dash}:fork`; matches the
  /deployments/{dep}/rollback precedent).
- fork/duplicate share one `copyToPersonal` engine: a READABLE source (both
  axes) is copied into a NEW personal dashboard owned by the caller, widgets +
  layout duplicated, source never mutated.
- Prebuilt dashboards are immutable in `requireDashboardEditor` — every edit/
  delete/add-widget 409s with the "fork to customize" remediation.
- deleteWidget is editor-gated, fences the widget to its dashboard, audits on
  shared dashboards (F7).

## Acceptance criteria

- [x] Prebuilt is read-only: edit/delete/add-widget on a prebuilt 409 with
  the fork remediation; fork yields a personal editable copy carrying the
  widgets; the prebuilt source is untouched.
- [x] Duplicate copies a custom dashboard into an independent personal copy;
  deleteWidget removes a widget (editor-gated, cross-dashboard delete 404s).

## Out of scope / findings

- **Prebuilt GENERATION from topology** ("always current as services come and
  go") is data-plane — needs the service topology + metrics; this task delivers
  the read-only/forkable object model, generation lands with the observe/data
  plane. Prebuilt rows are seeded (tested via a seeded row).
- **Share grants** (§2c "share grants"): DEFERRED — §2c gives no shape and there
  is no restricted-share member model in the contract (restricted is owner-only,
  recorded in T12.6). Designing the grant model is a product decision (agent-guide
  §4: a policy no owner defines → propose, don't improvise). Recorded for founder.
- The §2c endpoints were `:fork`/`:duplicate` (colon); implemented as sub-paths
  for router compatibility — a notation deviation, same surface.

## Outcome

Prebuilt dashboards land as read-only generated-view objects with the
fork-to-customize path (Design-Spec §244), plus the §2c fork/duplicate/
delete-widget endpoints. fork and duplicate share one copy-to-personal engine
(readable source → personal editable copy, widgets+layout duplicated, source
immutable); prebuilt dashboards 409 every mutation with the fork remediation.
The spec change was made FIRST in openapi.yaml (sub-path form for stdlib-mux
compatibility, matching the rollback precedent) then generated across Go/SDK/
console clients. Deferred (recorded): prebuilt topology GENERATION is data-plane;
SHARE GRANTS need a founder decision on the restricted-share member model (no
contract shape exists — improvising would violate agent-guide §4).


**Review round (approved reviewer + qa via read-only general-purpose, no Kernel
— per ADR-0008):** both independently found the MAJOR — fork/duplicate are
writes but skipped the read_only-token guard that Create/Update/Delete enforce,
so a read_only token could mint dashboards via /fork. Fixed: copyToPersonal
refuses limited-scope tokens before writing. Also fixed the copy-name >200-char
regression (capped like the create path). Tests added for every flagged gap:
read_only-token fork 403, member-fork-of-personal 404-before-copy (no row
created), member-fork-of-org owned by the member, born-filter travels
(project-scoped fork stays project-scoped), deleteWidget-on-prebuilt 409
(widget survives), and the F7 audit on a shared-dashboard widget delete.
Recorded minor: copyToPersonal is non-transactional (partial-copy on mid-loop
failure; low blast radius, owner-deletable) — ledgered for a single-tx follow-up.
