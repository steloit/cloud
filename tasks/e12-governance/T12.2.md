## Goal

Policy enforcement wiring + tighten-only property tests: the policy layer
narrows the matrix ceiling, never widens it, and a denial names the policy.

## Why

The two-layer RBAC (ADR-0006/036) is a matrix ceiling tightened by policies.
Enforcement must be provably tighten-only — a policy that could *widen* access
would be a privilege-escalation primitive.

## Read first

- services/api/internal/identity/rbac/rbac.go — `Evaluator.Check`: the two-layer
  chokepoint (matrix N is final; matrix Y consults policies, which may deny).
- services/api/internal/identity/policy/policy.go — `Engine.Evaluate`:
  closest-wins per key, intersection across kinds, fail-closed.
- docs/product/11-permissions/ — the matrix (no env column by design — env
  restrictions are ALWAYS policies, never role rows).
- **Don't read:** the frame gallery end-to-end.

## Approach

This capability was delivered incrementally: **T2.4** built the `PolicyLayer`
seam + `Engine.Evaluate` (closest-wins, tighten-only, fail-closed); **T12.1**
added the authoring guard (refuse `enforce` on an unimplemented kind) and wired
the engine into the `Authorizer` every handler uses. T12.2 is the verification
gate that the enforcement is provably correct.

## Edge cases

- Matrix N + any policy set → still denied (no widening). — property test.
- Unreadable policy source, or an `enforce` policy of an unknown kind → deny
  fail-closed. — `TestFailClosed`.
- A `warn`-posture policy → inert for authZ (never denies). — `TestFailClosed`.
- Project-level row overrides the org-level row of the same key. — closest-wins.

## Acceptance criteria

- [x] denial problem+json names the policy — `Decision.DeniedBy` carries
  `"policy:<key> <reason>"`, mapped to `problem.PermissionDenied(ad.DeniedBy…)`
  by `responseError`; asserted end-to-end (Authorizer layer) in
  `TestPolicyLayerAgainstDB` (`DeniedBy` contains `policy:ai-assistant`).
- [x] property test: no widening — `TestPropertyNoPolicyWidensN` sweeps every
  matrix-N cell under randomized policy environments and asserts the outcome
  stays denied and named.

## Validation

Both `verify:` commands pass. The property test sweeps all N cells; the
integration test proves enforcement against a real DB (named denial, per-key
tightening that doesn't touch non-ai permissions, closest-wins across projects).

## Common mistakes

- Consulting policies on a matrix-N cell (policies must only ever *narrow* a Y).
- A denial that doesn't name the policy — the E3 grammar requires `DeniedBy`.
- Treating a `warn` policy as enforcing (warn is telemetry-only, never a deny).

## Out of scope

- **Warn-mode violation counting** (G9 "warn counts violations"): the engine
  currently *skips* warn rows without emitting a violation event. Recorded as a
  follow-up finding — it is a telemetry feature, not part of this task's
  tighten-only enforcement AC, and it touches the events spine.
- HTTP round-trip enforcement coverage (a real request → 403 problem+json naming
  the policy): the only enforceable kind is `ai-assistant`, which gates `ai.*`,
  and no `ai.*` HTTP endpoint exists yet — arrives with E13.

## Related

- T2.4 (the PolicyLayer engine), T12.1 (authoring guard + wiring), T12.3
  (ai-assistant policy kind). ADR-0006/036 (governed-resource contract).

## Outcome

Policy enforcement was delivered incrementally by T2.4 (the `PolicyLayer` seam +
`Engine.Evaluate`) and T12.1 (the authoring guard + wiring into the `Authorizer`
every handler routes through). T12.2 confirms it is **provably tighten-only**:

- `Evaluator.Check` (rbac.go) is the single two-layer chokepoint — a matrix `N`
  is final and policies are **never** consulted for it; only a matrix `Y` is then
  offered to `Engine.Evaluate`, which can deny but structurally cannot widen.
- `Engine.Evaluate` resolves **closest-wins per key** (project row beats org
  row), intersects across kinds, and **fails closed** (unreadable source, or an
  `enforce` policy of an unknown kind, denies).
- Denials **name the policy**: `Decision.DeniedBy = "policy:<key> <reason>"`,
  surfaced by `responseError` as `problem.PermissionDenied` — the E3 grammar.

Verified by `TestPropertyNoPolicyWidensN` (every matrix-N cell under randomized
policy sets stays denied + named), `TestClosestWins`, `TestFailClosed`,
`TestAIAssistantKind`, and `TestPolicyLayerAgainstDB` (real-DB: org-wide
`ai-assistant: disabled` narrows `ai.*` for the owner naming `policy:ai-assistant`,
does not touch `org.manage`, and closest-wins holds across two real projects).

No net-new code was required — the AC was met by the incremental delivery above;
this task adds the traceability and the `verify:` gate. **Follow-up filed:**
warn-mode policies are skipped, not counted — the G9 "warn counts violations"
telemetry is unimplemented (recorded in spec-change-proposals.md).
