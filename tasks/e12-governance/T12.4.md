## Goal

Templates are frozen copies (ADR-021): capture a service subset with ZERO secret
material (checked at write, DB-level), excluded-service bindings surfaced as
required_inputs, the instantiation estimate carried from birth, and consume via
createProject/createEstimate `template_id` — deleting the recipe never touches
the meals.

## Why

QA scenario 5 is the safety contract: a template shared org-wide must be
incapable of leaking credentials, and instantiations must be genuinely
independent copies.

## Read first

- docs/product/08-api/openapi.yaml — captureTemplate/list/get/update/delete/
  refresh (§/orgs/{org}/templates, /templates/{tpl}) + Template schema +
  createProject.template_id/required_inputs + createEstimate.template_id.
- ADR-021 (decisions.md): copy-never-link; secrets never captured; credentials

- services/api/internal/provisioning/{services.go,bindings.go} — the rows
  capture reads (shape/product/intent are safe; provider_config/secret_ref are

- docs/product/16-qa/qa.md #5 — the AC.

## Approach

1. Migration `templates` (org FK, name, visibility org|restricted, version,
   source_project/source_env as provenance STRINGS — survive source deletion,
   contents jsonb, required_inputs jsonb, monthly_estimate_cents, used_by_count,
   updated_by) with a **DB-level secret guard**: CHECK rejecting `sec_`,
   `secret_ref`, `ciphertext` substrings in contents::text — defense-in-depth
   behind the structural whitelist.
2. Capture builds contents from a WHITELIST only (service name/product/intent/
   shape/scaling; internal bindings by NAME ref + scope): secret material is
   structurally unrepresentable, then the DB check enforces it at write.
   Bindings whose target is outside the captured set (or external providers)
   become `required_inputs[]` — surfaced, never silently dropped.
3. Estimate at birth: PriceAll over captured shapes → monthly_estimate_cents;
   re-priced on update(contents)/refresh (version++).
4. Refresh re-runs capture from the stored source names; a vanished source is a
   409 problem with remediation.
5. Consume: createEstimate.template_id prices the frozen contents;
   createProject.template_id instantiates — new project + env, one internal
   estimate create+accept per service (estimate-before-provision holds at the
   API layer; the budget cap enforces automatically inside CreateService),
   internal bindings rewired to the NEW service ids, required_inputs wired to
   caller-supplied target ids (missing ones → 422 listing every gap).
   used_by_count++ (informational — copies never link).
6. RBAC: manage ops under `template.manage`; list/get/consume under
   `template.consume`; `restricted` visibility readable only by managers.

## Acceptance criteria

- [x] QA scenario 5: capture from an env WITH secrets/bindings → contents
  contain zero secret material (DB-level check proves it); excluded binding →
  required_input; deleting a used template leaves instantiations untouched.
- [x] Estimate at save (birth), in list, and at consume — same integer cents.
- [x] Instantiation is a copy: subsequent template edit/delete changes nothing
  in the instantiated project.

## Common mistakes

- Copying `provider_config`/`secret_ref` into contents "for convenience" — the
  whitelist is the contract; anything not on it stays behind.
- Making instantiations reference the template row (a link) — used_by_count is
  a counter, never a FK with behavior.
- Skipping the estimate at instantiation because "the template carries one" —
  estimate-before-provision is enforced at the API layer per service create.

## Outcome

Templates are frozen copies end-to-end (ADR-021). `templates` table with the
**DB-level secret guard** (CHECK rejecting `sec_`/`secret_ref`/`ciphertext` in
contents — proven live in the test by a blocked UPDATE); capture builds contents
from a WHITELIST (name/product/intent/shape/scaling + internal bindings by NAME)
so secret material is structurally unrepresentable. Excluded-service bindings →
`required_inputs[]`, surfaced never dropped. Birth estimate via PriceAll,
identical integer cents at save / list / consume (asserted). Full CRUD +
refresh-from-source (vanished source → 409 with remediation; version++ on every
change). RBAC: manage ops `template.manage`, reads `template.consume`,
`restricted` visibility readable by managers only.

**Consume:** `createEstimate.template_id` prices the frozen contents;
`createProject.template_id` instantiates — new project/env, one internal
estimate create+accept per service through the STANDARD CreateService gate
(estimate-before-provision + the T11.6 cap enforce automatically), internal
bindings re-wired to the new ids, and **required inputs re-minted as sealed
secrets in the new env** (ADR-021 "credentials re-mint per consumer" — a
mid-implementation design correction: wiring them as cross-env service bindings
is platform-gated, and the credential reading is the honest one). Missing
inputs → 422 naming every gap. `used_by_count` is informational only.

Verified against real Postgres: capture from an env with a live secret + an
excluded binding → zero secret material (response + stored + the CHECK fires on
injection), 1 required_input, birth==list==consume cents, missing-input 422,
instantiation creates 2 copy services + the re-minted secret, then template
edit + delete leave the instantiated project untouched. Endpoint-permission
coverage gained template.manage/template.consume.
